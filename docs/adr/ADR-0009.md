# ADR-0009: Vector4 default construction uses homogeneous point coordinates

![Rejected][badge-rejected]

Rejected in favor of [ADR-0037](./ADR-0037.md).

## Context

`Vector4` is used by the engine's mathematics API for four-component values and for
homogeneous-coordinate values. In homogeneous coordinates, `w = 1` conventionally represents a
point, while `w = 0` represents a direction.

The API already uses `w = 1` when constructing a `Vector4` from a `Vector2` or `Vector3`, and its
point-oriented direction helpers (`up`, `down`, `left`, `right`, `forward`, and `backward`) also
use `w = 1`. The default constructor therefore needs a defined convention that is consistent with
these constructors and useful for the engine's expected homogeneous-coordinate use cases.

This decision must also acknowledge that `w` is included in `Vector4` arithmetic, dot products,
length calculations, and normalization. Choosing a default for `w` consequently affects observable
mathematical behavior, not only initialization.

## Decision

This decision is rejected. `Vector4` is not specialized as a point-oriented
homogeneous-coordinate type. The default construction convention and the
broader `Vector4` design are defined by [ADR-0037](./ADR-0037.md).

The original proposal is retained below as historical context.

The default constructor of `gp::math::Vector4<T>` initializes the vector to `(0, 0, 0, 1)`.
Constructors that create a `Vector4` from a `Vector2` or `Vector3` also default their missing `w`
component to `1`.

Callers creating a direction, a basis axis, or a generic four-dimensional vector must provide `w`
explicitly, normally as `0`. Existing constructors and constants with explicit component semantics
retain their current behavior:

- `Vector4::zero()` remains `(0, 0, 0, 0)`.
- `Vector4::unitX()`, `unitY()`, and `unitZ()` retain `w = 0`.
- `Vector4::unitW()` and `Vector4::positiveW()` retain `w = 1`.
- The scalar constructor continues to initialize all four components to the scalar value.

## Alternatives Considered

Briefly document other approaches that were evaluated and why they were ultimately rejected.

### Option A: W component set to 0 by default

Make the default constructor produce `(0, 0, 0, 0)` or otherwise treat a default-created value as
a direction.

**Why rejected:** This would be less consistent with the existing `Vector2`/`Vector3` conversion
constructors and the point-oriented construction helpers. It would also require callers to
explicitly set `w = 1` for common point construction.

### Option B: Enum depending which mode the dev want to use the W component

Require callers to select the intended interpretation through an enum or a similar mode when
constructing a `Vector4`.

**Why rejected:** This adds construction verbosity and API complexity without eliminating the need
for callers to understand the point-versus-direction distinction. It would also make existing
conversion constructors more cumbersome to use.

### Option C: Require an explicit W component for every construction

Remove the default for `w` from the default, `Vector2`, and `Vector3` constructors so that every
call site must provide the component explicitly.

**Why rejected:** This would make common point construction more verbose and would remove a useful
consistent default from the existing conversion constructors. It also increases boilerplate without
providing a stronger type-level distinction between points and directions.

## Consequences

### Positive

- The original proposal and its rationale remain available for historical reference.

### Negative

- Making `Vector4` point-oriented by default conflicts with its use as a general-purpose
  four-dimensional value.
- Including homogeneous semantics in every operation makes the meaning of `dot`, length,
  normalization, and component-wise arithmetic ambiguous.
- Callers need an explicit distinction between generic 4D values and point/direction values.
