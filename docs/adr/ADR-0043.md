# ADR-0043: Zero-Allocation `.bss` Known-Folder Discovery and Stack `PathBuffer` Normalization in `gp::platform::Paths`

> Establishes `gp::platform::Paths` in `gp::core` as a unified, zero-heap-allocation OS directory
> discovery and lexical path normalization subsystem backed by translation-unit `.bss` caches and
> stack-allocated `gp::PathBuffer` (`gp::FixedString<1024>`), abstracting Windows Known Folders
> (`SHGetKnownFolderPath`), Linux XDG Base Directories (`$XDG_DATA_HOME`, `$XDG_CONFIG_HOME`,
> `$HOME`), and macOS Application Support / bundle paths alongside `constexpr`-capable path
> slicing, relative directory collapsing, and path resolution.

![Accepted][badge-accepted]

## Context

Every layer of a production game engine—from low-level crash dump writers (`gp::launch`), dynamic
module loaders (`gp::platform::SharedLibrary`), and configuration parsers to high-level asset
managers—must query standard operating system directories and manipulate filesystem paths. In
`gp-engine`, this requirement intersects three strict architectural constraints:

1. **Pre-Heap Bootstrapping Paradox ([ADR-0040](./ADR-0040.md) & [ADR-0041](./ADR-0041.md)):**
   Crash handlers, memory telemetry logs, and dynamic library loaders execute before custom memory
   allocators (`gp::memory::Malloc`) are initialized. If path normalization (`combine`, `resolve`,
   `collapseRelativeDirectories`) or OS directory discovery (`executableDir()`, `appDataDir()`,
   `documentsDir()`) allocates heap strings (as Unreal Engine's `FPaths` does via `FString`), the
   engine triggers premature heap allocations or allocator recursion during startup and crash
   handling.
2. **OS Directory Discovery Divergence:**
   * **Windows (Win32 / Shell32):** Standard directories must be queried in UTF-16 via
     `SHGetKnownFolderPath` (`FOLDERID_RoamingAppData`, `FOLDERID_LocalAppData`,
     `FOLDERID_Documents`, `FOLDERID_Profile`), freeing the returned `PWSTR` with `CoTaskMemFree`,
     while the executable location is queried via `GetModuleFileNameW(nullptr, ...)` and temporary
     directories via `GetTempPathW` + `GetLongPathNameW`.
   * **Linux (POSIX / XDG Base Directory Specification):** User data, configuration, cache, and
     documents directories must respect `$XDG_DATA_HOME` (fallback `$HOME/.local/share`),
     `$XDG_CONFIG_HOME` (fallback `$HOME/.config`), `$XDG_CACHE_HOME` (fallback `$HOME/.cache`),
     and `$XDG_DOCUMENTS_DIR` (fallback `$HOME/Documents`), with `$HOME` falling back to
     `getpwuid_r(geteuid(), ...)` when environment variables are stripped in hardened or headless
     containers. The executable path is resolved via `readlink("/proc/self/exe", ...)`.
   * **macOS (Darwin / Mach):** The executable path is queried via `_NSGetExecutablePath`, while
     user data and configuration default to `$HOME/Library/Application Support` and
     `$HOME/Library/Preferences` unless explicitly overridden by `$XDG_DATA_HOME` /
     `$XDG_CONFIG_HOME` for CLI developer workflows.
3. **Lexical Path Edge Cases:** Cross-platform path manipulation must deterministically handle mixed
   separators (`/` and `\`), duplicate slashes (`a//b///c`), Windows volume specifiers (`C:/`),
   UNC network shares (`//Server/Share`), dot-prefixed hidden directories (`.git`, `.config`),
   relative traversal collapsing (`a/b/../c` $\rightarrow$ `a/c`), uncollapsible leading parent
   segments (`../../a/b`), relative-to-base path computation (`makePathRelativeTo`), and OS
   filename validation (rejecting illegal characters and Windows reserved device names `CON`,
   `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`).

## Decision

We introduce `gp::platform::Paths` in `gp::core` following the engine's static platform inheritance
hierarchy (`generic::Paths` $\rightarrow$ `unix::Paths` $\rightarrow$ `linux::Paths` /
`apple::Paths` $\rightarrow$ `macos::Paths`, and `windows::Paths`), combining Unreal Engine 5's
`FPathViews`/`FPaths` lexical algorithms with id Tech's zero-allocation fixed-capacity string
discipline.

### 2. Memory Layout & OS Directory Resolution Matrix

All OS directory queries populate translation-unit-local `.bss` `char[kMaxPathLength]` caches on
first access (or explicit `initialize()` / test override) and return non-dangling `gp::StringView`
slices terminated with a canonical forward slash (`/`):

<!-- markdownlint-disable MD013 -->
| Method | Windows (`WindowsPaths`) | Linux (`LinuxPaths` / `UnixPaths`) | macOS (`MacOSPaths` / `ApplePaths`) | CLI Override |
| :--- | :--- | :--- | :--- | :--- |
| **`executablePath()`** | `GetModuleFileNameW(nullptr, ...)` | `readlink("/proc/self/exe", ...)` | `_NSGetExecutablePath(...)` | `argv[0]` fallback |
| **`executableDir()`** | Parent dir of `executablePath()` | Parent dir of `executablePath()` | Parent dir of `executablePath()` | `-basedir=<path>` |
| **`workingDir()`** | `GetCurrentDirectoryW(...)` | `getcwd(...)` | `getcwd(...)` | — |
| **`launchDir()`** | Cached `workingDir()` at boot | Cached `workingDir()` at boot | Cached `workingDir()` at boot | — |
| **`homeDir()`** | `SHGetKnownFolderPath(FOLDERID_Profile)` | `$HOME` $\rightarrow$ `getpwuid_r` | `$HOME` $\rightarrow$ `getpwuid_r` | — |
| **`appDataDir()`** | `SHGetKnownFolderPath(FOLDERID_RoamingAppData)` | `$XDG_DATA_HOME` $\rightarrow$ `$HOME/.local/share/` | `$XDG_DATA_HOME` $\rightarrow$ `$HOME/Library/Application Support/` | `-appdata=<path>` |
| **`localAppDataDir()`** | `SHGetKnownFolderPath(FOLDERID_LocalAppData)` | `$XDG_CACHE_HOME` $\rightarrow$ `$HOME/.cache/` | `$XDG_CACHE_HOME` $\rightarrow$ `$HOME/Library/Caches/` | — |

| **`documentsDir()`** | `SHGetKnownFolderPath(FOLDERID_Documents)` | `$XDG_DOCUMENTS_DIR` $\rightarrow$ `$HOME/Documents/` | `$XDG_DOCUMENTS_DIR` $\rightarrow$ `$HOME/Documents/` | `-userdir=<path>` |

### 3. Canonical Normalization & Lexical Contract

1. **Canonical Engine Separator (`'/'`):** Inside the engine, all paths use `'/'`
   (`kPreferredSeparator`). Backslashes (`'\\'`) are normalized to `'/'` by `normalizeFilename()`
   and `normalizeDirectoryName()`. Conversion to the host OS separator (`'\\'` on Windows, `'/'`
   on POSIX) is performed exclusively at raw OS API boundaries via `makePlatformFilename()`.
2. **Zero-Copy `StringView` Inspection (`constexpr`):** Read-only decomposition methods
   (`getCleanFilename`, `getBaseFilename`, `getBaseFilenameWithPath`, `getPath`, `getPathLeaf`,
   `getExtension`, `split`, `splitVolumeSpecifier`, `splitFirstComponent`, `isRelative`,
   `isAbsolute`, `isDrive`, `isPathLeaf`, `hasRedundantTerminatingSeparator`, `equals`, `less`,
   `isParentPathOf`, `isUnderDirectory`, `tryMakeChildPathRelativeTo`) operate purely on
   `gp::StringView` without copying characters.
3. **In-Place & Stack `PathBuffer` Transformations (`constexpr`):** Mutating and constructive
   operations (`normalizeFilename`, `normalizeDirectoryName`, `removeDuplicateSlashes`,
   `collapseRelativeDirectories`, `makePlatformFilename`, `combine`, `changeExtension`,
   `setExtension`, `resolve` / `convertRelativePathToFull`, `makePathRelativeTo`,
   `makeValidFileName`) operate on `gp::PathBuffer` (`gp::FixedString<1024>`) on the stack with
   zero heap allocations.
4. **Drive & UNC Root Preservation:** Normalization upper-cases ASCII Windows drive letters
   (`c:\foo` $\rightarrow$ `C:/foo`), preserves root trailing slashes on volume specifiers (`C:/`)
   and POSIX/UNC roots (`/` and `//Server`), and prevents `collapseRelativeDirectories` from
   consuming volume prefixes or collapsing across leading `..` segments.

## Alternatives Considered

### Option A: Dual `FPaths` (Heap `String`) + `FPathViews` Split (Unreal Engine 5 Style)

Maintain two parallel classes: `PathViews` for non-allocating `StringView` operations and `Paths`
returning dynamically allocated `gp::String` instances by value.

**Why rejected:** Allocating heap memory on every `combine()`, `resolve()`, or
`collapseRelativeDirectories()` call violates `gp-engine`'s pre-heap bootstrapping guarantee
([ADR-0040](./ADR-0040.md)) and duplicates API surface across two classes. Using `gp::PathBuffer`
(`FixedString<1024>`) provides value-semantic ergonomics (`const PathBuffer full = Paths::combine(a, b);`)
while remaining 100% stack-resident and `constexpr`-compatible.

### Option B: Embedded Virtual Mount URI Table inside `gp::platform::Paths`

Embed virtual prefix routing (`engine://`, `game://`, `user://`) directly inside
`gp::platform::Paths`.

**Why rejected:** Conflates Layer 0 physical OS path normalization with Layer 1 Virtual File System
(VFS) archive/pak mounting. Low-level consumers (`SharedLibrary`, `CommandLine`, native OS file
dialogs) require raw physical OS paths. Virtual URI mounting is instead cleanly layered on top of
`gp::platform::Paths` in a dedicated VFS subsystem (see [ADR-0044](./ADR-0044.md)).

### Option C: C++17 `std::filesystem::path`

Wrap or expose `<filesystem>` (`std::filesystem::path`) for path normalization and resolution.

**Why rejected:** `std::filesystem::path` performs hidden heap allocations, relies on C++
exceptions and locale facets, stores `wchar_t` on Windows (requiring repeated UTF-16 $\leftrightarrow$
UTF-8 heap conversions), and is strictly forbidden by `gp-engine`'s zero-STL-allocation and
`-fno-exceptions` laws.

## Consequences

### Positive

* **Zero Heap Allocations Across All Operations.** Both OS directory queries (`.bss` cached
  `StringView`) and path manipulations (`PathBuffer` on stack) allocate `0 bytes` on the heap,
  making `gp::platform::Paths` safe during early startup, inside real-time threads, and inside
  crash handlers.
* **`constexpr` Compile-Time Evaluation.** All pure lexical path inspections and `PathBuffer`
  normalizations are `constexpr`, allowing unit tests and static path validations to execute at
  compile time via `static_assert`.
* **Cross-Platform Known-Folder Parity.** Properly abstracts `SHGetKnownFolderPath` on Windows,
  XDG Base Directory environment variables (`$XDG_DATA_HOME`, `$XDG_CONFIG_HOME`,
  `$XDG_CACHE_HOME`) with `$HOME` / `getpwuid_r` fallbacks on Linux, and Apple `Library`
  conventions on macOS.
* **Clean Foundation for Future VFS ([ADR-0044](./ADR-0044.md)).** Exposes normalized,
  trailing-slash-terminated physical root directories ready to be mounted into the engine's future
  Virtual File System.

### Negative

* **Fixed Maximum Path Length (`1024` UTF-8 bytes).** Paths exceeding `kMaxPathLength` (`1024`
  bytes, ~1 KiB per `PathBuffer` on the stack) are clamped, though this is $4\times$ the legacy
  Win32 `MAX_PATH` (`260`) and matches POSIX `PATH_MAX` conventions in AAA engines.
* **Static `.bss` Cache Footprint (~10 KiB).** Caching ten canonical OS directory paths in `.bss`
  reserves ~10 KiB of static memory in `gp::core`.
