# ADR-0049: Dual-Tier Platform Execution Contexts and Scratch-Bound Cooperative Fibers

> OS kernel thread context switches incur 1–10 microsecond scheduler transitions, TLB flushes, and
> kernel lock contention when worker threads block on job dependencies, while C++20 stackless
> coroutines infect entire engine call trees with "colored" return types that cannot yield from
> deep C++ helper routines. `gp-engine` introduces a dual-tier cooperative execution architecture
> in `gp::core`: a low-level **`gp::platform::FiberContext`** abstracting Windows CET/TEB-safe Win32
> Fibers (`CreateFiberEx` / `SwitchToFiber`) and POSIX zero-syscall `x86_64`/`ARM64` ABI
> register-frame switches with `PROT_NONE` hardware guard pages, paired with a high-level
> **`gp::thread::Fiber`** that owns an elastic [`PagedLinearAllocator`](./ADR-0048.md), supports
> two-tier stack sizing (`64 KiB` standard / `512 KiB` large), re-arms completed tasks without
> stack reallocation, and automatically swaps [`FiberScratchArena`](./ADR-0048.md) bindings across
> cooperative yields and cross-core work-stealing migrations.

![Proposed][badge-proposed]

## Context

In an $M:N$ work-stealing job system (such as those in **Naughty Dog's engine**, **EA Frostbite**,
**Guerrilla's Decima**, and **CD Projekt RED's REDengine 4**), $N$ hardware worker threads ($1$ per
logical CPU core) execute thousands of interdependent frame jobs. When a running job spawns child
jobs and waits for their completion (`waitForCounter`), the execution primitive must suspend the
waiting calculation and immediately execute another ready job on the same CPU core without stalling
the hardware thread:

### 1. The Cost of OS Kernel Thread Blocking and Oversubscription

If a worker thread blocks on an OS synchronization primitive (`WaitForSingleObject`, `futex`,
`pthread_cond_wait`) when awaiting a sub-job counter:

- **Kernel Transition & Scheduler Latency:** Entering and exiting the OS kernel scheduler costs
  $1\text{–}10\ \mu\text{s}$ ($3,000\text{–}30,000$ CPU cycles) and pollutes instruction and data caches.
- **Core Starvation or Thread Oversubscription:** If $N$ worker threads are fixed to $N$ hardware
  cores, a blocked worker thread leaves a physical CPU core completely idle (or deadlocks if all
  $N$ workers block on child jobs still sitting in the queue). Spawning extra OS threads to
  compensate causes preemptive timeslicing, cache thrashing, and lock-holder preemption across
  the frame.

### 2. The "Function Coloring" Defect of Stackless Coroutines

C++20 stackless coroutines (`co_await` / `std::coroutine_handle`) suspend only the innermost
coroutine frame. If `JobRoot()` calls `SceneGraph::updateHierarchy()`, which calls
`Octree::cullNode()`, which needs to dispatch parallel child jobs and wait for their completion,
**every intermediate function in the call chain must be rewritten as a coroutine returning a task
handle**. In a production engine where deep C++ call trees, third-party physics callbacks, and
virtual interfaces must be able to yield transparently, execution contexts must be **stackful**
(owning an independent call stack and CPU register state).

### 3. Platform ABI Realities: Windows 11 CET Shadow Stacks & TEB vs. POSIX `ucontext_t`

Implementing user-mode stackful context switching across desktop and console operating systems
exposes severe low-level ABI hazards if handled naively:

- **Windows TEB (`NT_TIB`) and Intel CET Hardware Shadow Stacks:** On 64-bit Windows, the Thread
  Environment Block (`gs:[0x30]`) tracks the active stack's boundaries (`StackBase` at `0x08`,
  `StackLimit` at `0x10`, and `DeallocationStack` at `0x1478`) alongside Structured Exception
  Handling (SEH) unwind chains and Fiber Local Storage (FLS). When a function allocates
  $> 4\text{ KiB}$ on the stack, MSVC emits `__chkstk`, which probes against the TEB's `StackLimit`.
  Furthermore, on modern CPUs with **Windows 11 Hardware-Enforced Stack Protection
  (Intel CET / AMD Shadow Stacks)** enabled, the processor maintains a protected hardware Shadow
  Stack Pointer (`SSP`). A hand-rolled assembly `RET` to a manually swapped `RSP` mismatches `SSP`
  and immediately terminates the process with `FAST_FAIL_CONTROL_INVALID_RETURN_ADDRESS`
  (`0xC0000409`). Conversely, Win32's user-mode `SwitchToFiber` API (coupled with
  `CreateFiberEx(..., FIBER_FLAG_FLOAT_SWITCH)`) updates all `NT_TIB` stack pointers, preserves
  `XMM6–XMM15` and `MXCSR`, integrates natively with Visual Studio's Parallel Stacks debugger, and
  is blessed by `ntdll.dll` to swap the hardware CET shadow stack in user space without a kernel
  scheduler transition.
- **POSIX `ucontext_t` Deprecation and Syscall Penalty:** On Linux and macOS, POSIX
  `<ucontext.h>` (`makecontext` / `swapcontext`) was deprecated in POSIX.1-2004 and removed in
  POSIX.1-2008. Worse, `swapcontext()` issues a `sigprocmask` / `rt_sigprocmask`
  **kernel system call** on every single context switch (~$300\text{–}600\text{ ns}$),
  making it $50\times$ slower than a pure user-space register swap (~$5\text{–}8\text{ ns}$).
  Unlike MSVC x64, Clang and GCC on Linux and macOS support inline assembly, allowing a
  20-instruction System V `x86_64` or ARM64 `AAPCS64` register-frame switch backed by `mmap` stacks
  and `mprotect(..., PROT_NONE)` hardware guard pages.

### 4. Coupling Between Context Switching and [ADR-0048](./ADR-0048.md) Fiber Scratchpads

In [ADR-0048](./ADR-0048.md), `gp-engine` introduced [`FiberScratchArena`](./ADR-0048.md) and
[`PagedLinearAllocator`](./ADR-0048.md) so scratch allocations travel with a fiber across yields
and cross-thread work-stealing migrations. If callers must manually remember to call
`FiberScratchArena::bindFiberArena()` before and after every low-level context switch, a single
forgotten call silently breaks scratchpad isolation or fails to advance the `ThreadScratchAllocator`
switch epoch.

## Decision

We introduce a dual-tier cooperative fiber architecture in `gp::core`, separating the
**platform ABI execution context** (`gp::platform::FiberContext`) from the **engine-level
cooperative fiber primitive** (`gp::thread::Fiber`):

### 1. Tier 1: Platform Execution Context (`gp::platform::FiberContext`)

`gp::platform::FiberContext` encapsulates the OS/CPU-specific stack allocation and register-state transfer:

- **Stateless Function Pointer Contract ([ADR-0022](./ADR-0022.md)):**
  ```cpp
  using FiberContextEntryFunction = void (*)(void* userData);
  ```
- **Thread-to-Fiber Anchoring (`convertCurrentThread` / `restoreCurrentThread`):**
  Before an OS hardware thread ([`gp::platform::Thread`](./ADR-0021.md)) can switch into a child
  fiber and later return to its original OS stack, it converts its active execution stream into a
  root **Thread Anchor Context** via `FiberContext::convertCurrentThread()` (or the RAII
  `ScopedThreadFiberContext` guard).
- **Windows Implementation (`gp::platform::windows::FiberContext`):**
  - Invokes `ConvertThreadToFiberEx(nullptr, FIBER_FLAG_FLOAT_SWITCH)` for thread anchors
    (detecting pre-existing fiber conversion via `IsThreadAFiber()` and `GetCurrentFiber()`).
  - Invokes `CreateFiberEx(commitSize, reserveSize, FIBER_FLAG_FLOAT_SWITCH, trampoline, this)`
    for child contexts, guaranteeing full Win64 `XMM6–XMM15` floating-point preservation, `NT_TIB`
    stack-limit synchronization, Windows 11 CET Hardware Shadow Stack compatibility, and native
    Visual Studio debugger inspection.
  - Invokes `SwitchToFiber(target.m_nativeHandle)` in user mode.
- **Unix / Linux / macOS Implementation (`gp::platform::unix::FiberContext`):**
  - Allocates virtual stack regions via `mmap(nullptr, totalBytes, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0)`
    rounded to the OS page size (`sysconf(_SC_PAGESIZE)`), placing an inaccessible hardware guard
    page at the stack floor via `mprotect(basePtr, pageSize, PROT_NONE)` so stack overflows trigger
    an immediate, deterministic hardware fault (`SIGSEGV`) rather than silent heap corruption.
  - Performs context switches in ~15–20 CPU instructions with **zero kernel syscalls** via inline
    assembly (`gp_jump_fcontext` / `gp_make_fcontext`) adhering strictly to:
    - **System V AMD64 ABI (`x86_64`):** Preserves `RBX`, `RBP`, `R12–R15`, `RSP`, `RIP`, `MXCSR`,
      and x87 FPU control word (`FNSTCW`/`FLDCW`).
    - **ARM64 AAPCS64 ABI (`aarch64`):** Preserves `x19–x29` (`fp`), `x30` (`lr`), `sp`, lower 64
      bits of SIMD registers `d8–d15` (`v8–v15`), `FPCR`, and `FPSR`.

### 2. Tier 2: Engine Cooperative Fiber (`gp::thread::Fiber`)

`gp::thread::Fiber` builds the engine-facing cooperative execution primitive on top of
`gp::platform::FiberContext` and [`gp::memory::PagedLinearAllocator`](./ADR-0048.md):

```text
gp::thread::Fiber
┌─────────────────────────────────────────────────────────────────────────┐
│ m_context       : gp::platform::FiberContext (OS/ABI Stack + Registers) │
│ m_scratchArena  : gp::memory::PagedLinearAllocator (0 B idle footprint) │
│ m_entry / m_data: FiberEntryFunction + void* (Re-armable task payload)  │
│ m_id / m_state  : FiberId (UInt32) + FiberState + FiberStackTier        │
└─────────────────────────────────────────────────────────────────────────┘
```

1. **Two-Tier Stack Sizing Policy (`FiberStackTier`):**
   Following Naughty Dog's production fiber pool architecture (GDC 2015), `FiberStackTier` codifies
   two standard stack tiers alongside custom overrides:
   - `FiberStackTier::Standard64KiB` (`64 KiB`): Default for $>80\%$ of gameplay, animation, and
     culling jobs.
   - `FiberStackTier::Large512KiB` (`512 KiB`): Provisioned for deep recursive call trees (physics
     solvers, BVH construction, asset decompression, or OS/driver calls).
2. **Persistent Re-Armable Execution Loop (`bindTask`):**
   An OS stack allocation or `CreateFiberEx` call must never occur during frame execution. When a
   `gp::thread::Fiber`'s entry function returns, the internal fiber trampoline transitions `m_state`
   to `FiberState::Completed`, optionally resets `m_scratchArena` (`resetScratchOnTaskReturn`), and
   yields automatically back to the designated return/scheduler fiber (`m_returnFiber`). The
   scheduler can then call `fiber.bindTask(newEntry, newUserData)` to transition the fiber back
   to `FiberState::Ready` and immediately re-enter the next task inside the persistent trampoline
   loop **without recreating or reallocating the underlying `FiberContext`**.
3. **Mandatory [`FiberScratchArena`](./ADR-0048.md) Handoff on `switchTo(Fiber& target)`:**
   Every call to `currentFiber.switchTo(targetFiber)` performs the following sequence:
   - Validates that `&currentFiber != &targetFiber` and both fibers are valid.
   - Updates `tl_currentFiber = &targetFiber`.
   - Binds `targetFiber`'s `PagedLinearAllocator` (`&targetFiber.m_scratchArena`, or `nullptr` if
     `targetFiber` is a raw thread-anchor fiber) via
     [`FiberScratchArena::bindFiberArena()`](./ADR-0048.md), which simultaneously increments the
     current OS worker thread's fiber-switch epoch counter (`tl_fiberSwitchEpoch`).
   - Executes `m_context.switchTo(targetFiber.m_context)`.
   - Immediately upon resumption (even if `currentFiber` was stolen and resumed on a
     **different OS worker thread**), re-establishes `tl_currentFiber = this` and binds
     `&this->m_scratchArena` on the resuming OS worker thread via `FiberScratchArena::bindFiberArena()`.

### Architectural Invariants

1. **Zero Heap or Stack Allocations During `switchTo()` and `bindTask()`:** Context switching
   between fibers and re-arming a completed fiber with a new `FiberEntryFunction` must execute
   zero heap or virtual memory allocations.
2. **Automatic `FiberScratchArena` Synchronization:** `Fiber::switchTo()` must unconditionally
   synchronize `FiberScratchArena::bindFiberArena()` both prior to jumping to the target fiber
   and upon resuming on the current or migrated worker thread, guaranteeing that
   `ScopedFiberScratchMark` ([ADR-0048](./ADR-0048.md)) remains valid across arbitrary
   thread migrations and that `ScopedScratchMark` (`ThreadScratchAllocator`) catches illegal
   yields via the thread switch epoch.
3. **Strict Platform Header Isolation ([ADR-0021](./ADR-0021.md)):** `<windows.h>`, `<sys/mman.h>`,
   and architecture-specific assembly blocks must never appear in public headers;
   `WindowsFiberContext.hpp` and `UnixFiberContext.hpp` expose only fixed-width engine types and
   opaque `void*` handles.
4. **Prohibition of Returning From an Unanchored Fiber:** Every `gp::thread::Fiber` executing a
   task must either be explicitly provided a `returnFiber` target (such as the worker thread's
   anchor fiber) or yield back to the scheduler before termination; falling off the end of a fiber
   without a return target triggers an immediate `GP_ASSERT`.
5. **`GP_FORCENOINLINE` Isolation on All `thread_local` Accessors:** Optimizing compilers
   (`clang-cl` / MSVC `/O2` and GCC `-O3`) assume a function never changes its underlying OS
   hardware thread mid-execution and will hoist Thread-Local Storage base address lookups
   (`gs:[0x58]`) into callee-saved registers (`RSI`, `RDI`, `R12–R15`) across function calls. If a
   fiber yields on Worker Thread A and resumes on Worker Thread B, an inlined TLS lookup after the
   yield dereferences Worker Thread A's stale or unmapped TLS block. All internal `thread_local`
   accessors in `Fiber`, `FiberContext`, `FiberScratchArena`, and `ThreadScratchArena` must be
   marked `GP_FORCENOINLINE` so the CPU resolves the active core's TLS segment register fresh
   after every context switch.

## Alternatives Considered

### Option A: Pure Custom Assembly (`fcontext_t`) Across All Platforms Including Windows

Use custom `.asm` files (`ml64.exe` on Windows) to manually swap `RSP` and `NT_TIB` fields on
Windows rather than calling `CreateFiberEx` and `SwitchToFiber`.

**Why rejected:** On modern Windows 11 systems with Hardware-Enforced Stack Protection
(Intel CET / AMD Shadow Stacks), executing a manual `RET` after modifying `RSP` in user-authored
assembly mismatches the CPU's protected Shadow Stack Pointer (`SSP`) and crashes immediately with
`0xC0000409` (`FAST_FAIL_CONTROL_INVALID_RETURN_ADDRESS`). Furthermore, MSVC x64 forbids inline
`__asm`, which would force `gpbt` to maintain separate MASM (`ml64.exe`) and ARMASM (`armasm64.exe`)
toolchains and manually replicate undocumented Windows `TEB` / `FLS` / `SEH` fields that
`SwitchToFiber` handles natively in user mode.

### Option B: POSIX `<ucontext.h>` (`getcontext` / `makecontext` / `swapcontext`) on Linux and macOS

Use the legacy C library `ucontext_t` functions on Unix platforms instead of an ABI register-frame switch.

**Why rejected:** `ucontext_t` was removed from the POSIX.1-2008 standard and is marked deprecated
on macOS. Crucially, `swapcontext()` saves and restores the thread's signal mask via the
`sigprocmask` kernel system call on every context switch, inflating switch latency from ~6
nanoseconds to >300 nanoseconds and defeating the purpose of user-mode fibers.

### Option C: C++20 Stackless Coroutines (`co_await` / `std::coroutine_handle`)

Represent jobs as C++20 stackless coroutines instead of stackful fibers.

**Why rejected:** Stackless coroutines cannot suspend from inside nested standard C++ function
calls ("function coloring"). Any engine subsystem (culling, animation, physics, VFS) that awaits
child jobs deep inside a call hierarchy would require rewriting every intermediate signature into a
coroutine template, and requires `<coroutine>` STL support forbidden by [ADR-0021](./ADR-0021.md).

## Consequences

### Positive

- **Enables sub-25-nanosecond user-mode cooperative yielding across deep call stacks.** Any C++
  function at any call depth can suspend its fiber context and switch to another ready fiber
  without entering the OS kernel scheduler.
- **Guarantees 100% Windows 11 CET Shadow Stack, SEH, and Visual Studio debugger compatibility.**
  Using Win32 `CreateFiberEx` (`FIBER_FLAG_FLOAT_SWITCH`) and `SwitchToFiber` on Windows preserves
  hardware shadow stacks, Win64 `XMM6–XMM15` registers, and Visual Studio Parallel Stacks
  inspection without `.asm` build rules.
- **Delivers zero-syscall ~6 ns context switches with hardware guard pages on Linux and macOS.**
  The `x86_64` and `ARM64` register-frame switch in `UnixFiberContext` avoids `swapcontext`
  syscalls and traps stack overflows immediately via `PROT_NONE` guard pages.
- **Mechanically enforces [ADR-0048](./ADR-0048.md) `FiberScratchArena` migration safety.**
  Because `gp::thread::Fiber::switchTo()` binds the incoming fiber's `PagedLinearAllocator`
  automatically, `FiberScratchAllocator` and `ScopedFiberScratchMark` work seamlessly across
  cross-thread fiber migrations while `ScopedScratchMark` deterministically catches illegal yields.
- **Eliminates runtime fiber stack allocations via persistent task re-arming (`bindTask`).**
  Pooled fibers reuse their underlying stack and `FiberContext` across thousands of tasks over the
  lifetime of the engine.

### Negative

- **Virtual address space reservation per pooled fiber.** Each `gp::thread::Fiber` reserves its
  configured stack size (`64 KiB` standard or `512 KiB` large) in virtual memory
  (`128 \times 64\text{ KiB} + 32 \times 512\text{ KiB} = 24\text{ MiB}` for a 160-fiber pool),
  requiring developers to choose the appropriate `FiberStackTier` for deep recursive workloads.
- **OS Thread-Local Storage (`thread_local`) hazards across yields.** Compiler `thread_local`
  variables remain bound to the underlying hardware worker thread (`gp::platform::Thread`), not
  the migrating `gp::thread::Fiber`. Code that yields across fibers must use
  `FiberScratchAllocator` / `gp::thread::Fiber::getCurrentFiber()` rather than caching
  `thread_local` state across a yield point.
