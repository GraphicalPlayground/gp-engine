# ADR-0051: Bounded Lock-Free Chase-Lev Work-Stealing Deques and Vyukov Sequence MPMC Job Queues

> Centralized job queues bottleneck across 16–64 hardware threads due to MESI cache-line bouncing
> and FIFO cache thrashing, while dynamic Chase-Lev deques violate deterministic frame budgets by
> allocating and garbage-collecting ring buffers on the hot path. `gp-engine` introduces a hybrid,
> zero-allocation Layer 2 queue architecture in `gp::core`: a per-worker bounded lock-free
> Single-Producer Multi-Consumer (SPMC) **`gp::thread::WorkStealingDeque<T>`** (Chase-Lev with
> Lê et al. C11 memory ordering), a bounded Multi-Producer Multi-Consumer (MPMC)
> **`gp::thread::MPMCRingQueue<T>`** (Vyukov per-slot sequence-stamp ring), and 32-byte POD
> **`gp::thread::JobDecl`** and **`gp::thread::JobQueueItem`** descriptors.

![Proposed][badge-proposed]

## Context

With elastic fiber scratchpads ([ADR-0048](./ADR-0048.md)), dual-tier cooperative fibers
([ADR-0049](./ADR-0049.md)), and stack-resident wait-nodes on 64-bit packed `JobCounter` /
`JobFence` primitives ([ADR-0050](./ADR-0050.md)) in place, `gp-engine`'s $M:N$ fiber job
scheduler requires a lock-free queuing layer to distribute tasks and woken fibers across $N$
hardware worker threads. Designing this layer exposes four hardware and concurrency constraints:

### 1. SPSC Limitations and Central MPMC Contention

In [ADR-0025](./ADR-0025.md), `gp-engine` introduced `gp::SPSCRingBuffer<T>` with 3-zone 64-byte
cache-line isolation and shadow index caching. However, `SPSCRingBuffer<T>` is strictly constrained
to a Single-Producer Single-Consumer (SPSC) topology. Conversely, relying solely on global
Multi-Producer Multi-Consumer (MPMC) ring queues (as in Naughty Dog's 6-core PS4 engine) creates
two severe scalability bottlenecks on modern 16–64 thread desktop and console CPUs:

- **Cross-Core MESI Cache-Line Ping-Ponging:** When $N$ worker threads simultaneously spawn and pop
  fine-grained child jobs during a `parallelFor` burst, every operation executes a competing
  `LOCK CMPXCHG` on the shared global queue head and tail cache lines.
- **FIFO Destruction of L1/L2 Data Locality:** A global FIFO queue places newly spawned child jobs
  at the back of the line behind unrelated work. By the time a child job executes, the parent job's
  working set has been evicted from the L1/L2 cache, or a remote CPU core pulls the child job into
  a cold cache while the spawning core executes unrelated tasks.

### 2. The LIFO/FIFO Duality of Work Stealing

To maximize cache locality and minimize cross-core interconnect traffic, a per-worker job queue
must behave as a double-ended queue (**deque**) with asymmetric ordering:

- **Owner Worker Thread (LIFO Bottom Push/Pop):** The owning worker thread pushes newly spawned
  child jobs to the **bottom** and pops from the **bottom** in Last-In, First-Out (LIFO) order.
  The most recently spawned child job operates on data still hot in the owner's L1/L2 cache and
  traverses recursive divide-and-conquer task trees depth-first ($O(\log N)$ active stack depth).
- **Thief Worker Threads (FIFO Top Steal):** Idle worker threads steal from the **top** of a busy
  victim's deque in First-In, First-Out (FIFO) order. In a recursive task split, the oldest item at
  the top represents the coarsest-grained subtree of work, maximizing work acquired per steal.

### 3. Weak Memory Models and the Chase-Lev Last-Element Race

In the classic **Chase-Lev** work-stealing deque, the owner thread mutates `m_bottom` without atomic
Read-Modify-Write (RMW) instructions when multiple items exist (`top < bottom`), while thieves
compete via compare-and-swap (CAS) on `m_top`. When exactly one item remains (`top == bottom`), the
owner (popping from `bottom`) and a thief (stealing from `top`) race for the same slot:

- Without a full `MemoryOrder::SeqCst` StoreLoad barrier between the owner's `m_bottom = b` store
  and `m_top` load (and between a thief's `m_top` load and `m_bottom` load), both x86-TSO store
  buffers and ARMv8 weakly ordered pipelines can reorder the loads ahead of the stores, allowing
  both the owner and the thief to observe the queue as non-empty and execute the same job twice.
- Furthermore, academic Chase-Lev implementations dynamically allocate a new `CircularArray` when
  `bottom - top >= capacity`, requiring Hazard Pointers or Epoch-Based Reclamation (EBR) so thieves
  reading a stale array pointer do not fault, violating `gp-engine`'s zero-allocation frame budget.

### 4. Multi-Producer Injection and Cross-Core Fiber Wake Routing

Because a Chase-Lev deque's `bottom` cursor is strictly owned by a single worker thread, two
critical scheduling flows cannot push directly into a worker's `WorkStealingDeque`:

1. **External OS Thread Job Submission:** Non-worker threads (Game/Main Thread, Audio Thread, I/O
   Thread) and priority-band dispatchers (`High`, `Normal`, `Low`) must enqueue jobs concurrently.
2. **Cross-Core Suspended Fiber Wakeups ([ADR-0050](./ADR-0050.md)):** When Worker $A$ decrements a
   `JobCounter` to `0`, its registered `JobWakeFunction` wakes a suspended `gp::thread::Fiber*` that
   must be pushed into a ready queue accessible by any worker thread without lock contention.

## Decision

We introduce a hybrid, zero-allocation lock-free job queue subsystem in
`source/runtime/core/public/threading/queues/` consisting of **`WorkStealingDeque<T>`**,
**`MPMCRingQueue<T>`**, **`JobDecl`**, and **`JobQueueItem`**:

```text
source/runtime/core/
  public/
    threading/
      queues/
        JobQueueForward.hpp       <-- Forward declarations for queues & PODs
        JobQueueEnums.hpp         <-- JobQueueResult, JobPriority, ItemKind
        JobQueueTypes.hpp         <-- JobEntryFunction & default capacities
        JobQueueDesc.hpp          <-- 32B JobDecl & JobQueueItem descriptors
        WorkStealingDeque.hpp     <-- Bounded SPMC Chase-Lev deque
        MPMCRingQueue.hpp         <-- Bounded MPMC Vyukov sequence ring queue
  tests/
    threading/
      queues/
        JobQueue.tests.cpp        <-- Unit & SMP stress tests for job queues
```

### 1. 32-Byte POD Job Declaration and Queue Item (`JobDecl` & `JobQueueItem`)

Following [ADR-0020](./ADR-0020.md) and [ADR-0022](./ADR-0022.md), all queued work items are
trivially copyable, standard-layout POD structs occupying exactly **32 bytes** (two items per
64-byte hardware cache line):

```text
JobDecl (32 Bytes, alignas(16))
+-----------------------------------------------------------------------+
| entry     : JobEntryFunction (8B)  Stateless void (*)(void*) callback |
| userData  : void*            (8B)  Caller-managed task context        |
| counter   : JobCounter*      (8B)  Optional completion counter        |
| priority  : JobPriority      (1B)  High, Normal, or Low               |
| stackTier : FiberStackTier   (1B)  Standard64KiB or Large512KiB       |
| flags     : UInt16           (2B)  Reserved scheduling flags          |
| reserved  : UInt32           (4B)  Explicit zero padding              |
+-----------------------------------------------------------------------+
```

`JobQueueItem` wraps either a fresh `JobDecl` (`JobQueueItemKind::JobEntry`) or a woken
[`gp::thread::Fiber*`](./ADR-0049.md) (`JobQueueItemKind::ResumedFiber`, unblocked by
[`JobCounter`](./ADR-0050.md) or [`JobFence`](./ADR-0050.md)) inside the same 32-byte footprint so
schedulers can either segregate or unify new jobs and resumed fibers in the same queue templates.

### 2. Bounded Lock-Free SPMC Chase-Lev Deque (`gp::thread::WorkStealingDeque<T>`)

`WorkStealingDeque<T>` implements a bounded, fixed-capacity Single-Producer Multi-Consumer (SPMC)
work-stealing deque over a power-of-two circular buffer (`m_buffer`, `m_mask = m_capacity - 1`),
enforcing [ADR-0025](./ADR-0025.md) 3-zone 64-byte cache-line isolation:

```text
+-----------------------------------------------------------------------+
| Cache Line 0 (64B) - Read-Only Zone (MESI: Shared [S])                |
| m_buffer (8B) | m_capacity (8B) | m_mask (8B) | m_allocator (8B) ...  |
+-----------------------------------------------------------------------+
| Cache Line 1 (64B) - Owner Bottom Zone (Written ONLY by Owner)        |
| m_bottom : Atomic<Int64> (8B) | Padding (56B)                         |
+-----------------------------------------------------------------------+
| Cache Line 2 (64B) - Thief Top Zone (CAS-mutated by Thieves/Last Pop) |
| m_top    : Atomic<Int64> (8B) | Padding (56B)                         |
+-----------------------------------------------------------------------+
```

1. **64-Bit Signed Monotonic Cursors (`gp::Int64`):**
   - `m_bottom` and `m_top` increment monotonically without modulo wrapping, indexing slots via
     `static_cast<gp::USize>(cursor) & m_mask`.
   - Because $2^{63}$ operations require $>29$ years at $10^{10}$ jobs/second, index wrap-around
     ABA is impossible without 128-bit CAS.
2. **Owner LIFO Push (`tryPushBottom` — Zero RMW):**
   - Loads `b = m_bottom.load(Relaxed)` and `t = m_top.load(Acquire)`.
   - If `(b - t) >= static_cast<gp::Int64>(m_capacity)`, returns `JobQueueResult::Full` without
     allocating memory (allowing the scheduler to overflow into `MPMCRingQueue` or run inline).
   - Stores `m_buffer[static_cast<gp::USize>(b) & m_mask] = item` and publishes
     `m_bottom.store(b + 1, Release)`.
3. **Owner LIFO Pop (`tryPopBottom` — Zero CAS When `t < b`):**
   - Decrements `b = m_bottom.load(Relaxed) - 1`, stores `m_bottom.store(b, Relaxed)`, emits
     `atomicThreadFence(MemoryOrder::SeqCst)`, and loads `t = m_top.load(Relaxed)`.
   - **Uncontended Fast Path (`t < b`):** Reads `outItem = m_buffer[b & m_mask]` and returns
     `JobQueueResult::Success` with **zero atomic CAS instructions**.
   - **Last-Item Race (`t == b`):** Competes with potential thieves via
     `m_top.compareExchangeStrong(t, t + 1, SeqCst, Relaxed)`, then restores
     `m_bottom.store(t + 1, Relaxed)` (where `t` is the original top value `b`).
   - **Empty (`t > b`):** Restores `m_bottom.store(b + 1, Relaxed)` and returns
     `JobQueueResult::Empty`.
4. **Thief FIFO Steal (`tryStealTop` & `tryStealTopBatch`):**
   - Loads `t = m_top.load(Acquire)`, emits `atomicThreadFence(MemoryOrder::SeqCst)`, and loads
     `b = m_bottom.load(Acquire)`. If `t >= b`, returns `JobQueueResult::Empty`.
   - Speculatively copies `outItem = m_buffer[static_cast<gp::USize>(t) & m_mask]` (safe because
     `T` is constrained by `gp::thread::JobQueueElement<T>`) and attempts
     `m_top.compareExchangeStrong(t, t + 1, SeqCst, Relaxed)`.
   - Returns `JobQueueResult::Success` on CAS win, or `JobQueueResult::Contended` on CAS loss so
     thief loops can differentiate an empty victim from an active victim under contention.
   - Supports `tryPushBottomRange()` (all-or-nothing batch LIFO push with a single `Release` commit)
     and `tryStealTopBatch()` (stealing up to half of available items in FIFO order).

### 3. Bounded Lock-Free MPMC Sequence Ring Queue (`gp::thread::MPMCRingQueue<T>`)

`MPMCRingQueue<T>` implements **Dmitry Vyukov's** bounded Multi-Producer Multi-Consumer queue over
a power-of-two array of 64-byte cache-line-isolated sequence-stamped slots
(`struct alignas(64) Slot { Atomic<USize> sequence; T payload; }`):

```text
+-----------------------------------------------------------------------+
| Cache Line 0 (64B) - Read-Only Zone: m_slots, m_capacity, m_mask ...  |
+-----------------------------------------------------------------------+
| Cache Line 1 (64B) - Producer Zone : m_enqueuePos (Atomic<USize>)     |
+-----------------------------------------------------------------------+
| Cache Line 2 (64B) - Consumer Zone : m_dequeuePos (Atomic<USize>)     |
+-----------------------------------------------------------------------+
```

- **Initialization:** Each `m_slots[i].sequence` is initialized to its logical index `i`.
- **`tryPush` & `tryPushBatch` (Multi-Producer):** Loads `pos = m_enqueuePos.load(Relaxed)`,
  inspects `seq = slot.sequence.load(Acquire)`, and computes `diff = Int64(seq) - Int64(pos)`:
  - `diff == 0`: Slot is available for this lap. Producer claims `pos` via
    `m_enqueuePos.compareExchangeWeak(pos, pos + 1, Relaxed)`, writes `slot.payload`, and commits
    `slot.sequence.store(pos + 1, Release)`.
  - `diff < 0`: Consumer has not yet freed this slot from the prior lap; returns
    `JobQueueResult::Full`.
  - `diff > 0`: Another producer claimed `pos`; reloads `pos` and retries.
- **`tryPop` & `tryPopBatch` (Multi-Consumer):** Loads `pos = m_dequeuePos.load(Relaxed)`,
  inspects `seq = slot.sequence.load(Acquire)`, and computes `diff = Int64(seq) - Int64(pos + 1)`:
  - `diff == 0`: Item is committed. Consumer claims `pos` via
    `m_dequeuePos.compareExchangeWeak(pos, pos + 1, Relaxed)`, reads `slot.payload`, and advances
    the slot ticket for the next lap via `slot.sequence.store(pos + m_mask + 1, Release)`.
  - `diff < 0`: Queue is empty; returns `JobQueueResult::Empty`.
  - `diff > 0`: Another consumer claimed `pos`; reloads `pos` and retries.

### Queue Topology Comparison Matrix

| Queue Primitive | Topology | Ordering | Owner Cost | Primary Role |
| :--- | :--- | :--- | :--- | :--- |
| **`SPSCRingBuffer<T>`** | 1P / 1C | FIFO | `Relaxed` / `Release` | OS-to-Game events |
| **`WorkStealingDeque<T>`** | 1P / MC | LIFO / FIFO | `Release` / 1 Fence | Worker jobs & steal |
| **`MPMCRingQueue<T>`** | MP / MC | FIFO | 1 CAS + `Release` | Priority & wakes |

### Architectural Invariants

1. **Concept-Constrained Trivially Copyable Payloads (`JobQueueElement<T>`):** Both
   `WorkStealingDeque<T>` and `MPMCRingQueue<T>` require `gp::concepts::IsTriviallyCopyable<T>` and
   `!gp::concepts::IsConst<T>` so speculative thief reads in `tryStealTop()` never invoke
   non-trivial copy constructors or tear non-POD lifetimes.
2. **Strict 3-Zone & Per-Slot 64-Byte Cache-Line Isolation ([ADR-0025](./ADR-0025.md)):**
   Read-only metadata, producer/bottom cursors, and consumer/top cursors each occupy independent
   64-byte cache lines (`sizeof == 192` bytes), and each `MPMCRingQueue<T>::Slot` is `alignas(64)`
   to eliminate adjacent-slot false sharing and cache-line straddling.
3. **Zero Steady-State Heap Allocations:** Pushing, popping, and stealing must never allocate or
   reallocate memory; capacity is fixed to a power of two at initialization (via `Malloc`
   or caller-supplied external storage).
4. **Mandatory `SeqCst` StoreLoad Barrier in `WorkStealingDeque`:** Both `tryPopBottom()` and
   `tryStealTop()` must emit `gp::thread::atomicThreadFence(MemoryOrder::SeqCst)` between their
   initial cursor operation and opposing cursor load to prevent last-item double-execution on
   x86-64 and ARM64.
5. **Explicit Contention Disambiguation:** `WorkStealingDeque::tryStealTop()` must return
   `JobQueueResult::Contended` when a non-empty slot is lost to a competing CAS, distinct from
   `JobQueueResult::Empty`.

## Alternatives Considered

### Option A: Dynamically Resizable Chase-Lev `CircularArray` with Deferred Garbage Collection

Replace `m_buffer` with an atomic pointer to a heap-allocated `CircularArray<T>` that doubles in
capacity when `tryPushBottom()` fills the buffer, retiring old arrays to a garbage list.

**Why rejected:** Violates `gp-engine`'s deterministic frame budget law by triggering heap
allocations on the job-spawning hot path, adds pointer indirection on every queue access, and
requires Epoch-Based Reclamation or frame-end garbage collection so concurrent thieves do not
dereference freed arrays.

### Option B: Central Multi-Priority MPMC Queues Only (Naughty Dog GDC 2015)

Omit per-worker SPMC work-stealing deques and route all job spawns and pops through global MPMC
priority ring queues.

**Why rejected:** Causes severe MESI cache-line contention across 16–64 hardware threads when
workers concurrently execute `LOCK CMPXCHG` on global queue cursors, and enforces FIFO ordering
that evicts L1/L2-hot parent data before spawned child jobs can process it.

### Option C: Intrusive Lock-Free Linked Lists / Treiber Stacks (Unreal Engine 4 Legacy)

Allocate each job as a pooled list node and push/pop via an ABA-tagged atomic head pointer.

**Why rejected:** Requires an atomic CAS and node allocation on every local push and pop, and
suffers L1/L2 cache misses due to pointer chasing across non-contiguous nodes.

## Consequences

### Positive

- **Eliminates atomic RMW instructions on uncontended local worker pushes and pops.** A worker
  thread spawning and consuming its own sub-jobs (`top < bottom`) executes zero `LOCK CMPXCHG` or
  `LOCK XADD` operations on `m_top`.
- **Maximizes both L1/L2 data cache locality and steal granularity.** Local LIFO pops immediately
  process L1-hot child data, while remote FIFO steals extract the oldest, largest subtrees first.
- **Provides lock-free MPMC routing for external threads and [`JobCounter`](./ADR-0050.md) wakes.**
  `MPMCRingQueue<T>` enables arbitrary threads to submit priority jobs or enqueue woken `Fiber*`
  handles without violating the single-producer invariant of `WorkStealingDeque<T>`.
- **Guarantees zero runtime heap allocations and supports external arena buffers.** Both queues
  support `initialize(capacity, malloc)` and `initializeWithExternalBuffer(buffer, capacity)`.

### Negative

- **Bounded per-worker deque capacity requires overflow handling.** Because `WorkStealingDeque<T>`
  does not resize dynamically, pushing more than `capacity()` unconsumed items returns
  `JobQueueResult::Full`, requiring the scheduler to spill into `MPMCRingQueue<T>` or run inline.
- **Per-slot cache-line padding in `MPMCRingQueue<T>`.** Each MPMC ring slot is aligned to 64
  bytes (`alignas(64) Slot` with an 8-byte `Atomic<USize> sequence` and `T payload`), occupying one
  full 64-byte cache line per slot for a 32-byte `JobQueueItem` to prevent false sharing.
