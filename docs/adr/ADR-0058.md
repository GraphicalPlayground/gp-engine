# ADR-0058: Compact Bit-Packed Mutexes, Futex Parking, and Fiber-Safe Recursive Locks

> Introduces `gp::thread::Mutex` (4B), `RecursiveMutex` / `CriticalSection` (16B),
> `SharedMutex` (8B), `OnceFlag` / `GP_CALL_ONCE` (4B), `UniqueLock`, and `SharedLock` in
> `gp::core`, pairing single-instruction inline atomic fast paths with `gp::platform::Futex`
> kernel address parking (`WaitOnAddress`, `futex`, `__ulock_wait`) and dual-domain
> fiber/thread recursive ownership tokens.

![Accepted][badge-accepted]

## Context

[ADR-0021](./ADR-0021.md) rejected `<mutex>` and `<thread>` to avoid hidden heap allocations,
cross-DLL ABI mismatches, and standard header bloat, while [ADR-0049](./ADR-0049.md) and
[ADR-0050](./ADR-0050.md) added cooperative fibers (`gp::thread::Fiber`) and job barriers
(`JobCounter`, `JobFence`). Subsystems across `gp::core`, `gp::hal`, and `gp::rhi` still need
low-level mutual exclusion for short critical sections, reader-writer tables, recursive legacy
callbacks, and one-time static initialization.

Wrapping OS mutex handles (`CRITICAL_SECTION`, `SRWLOCK`, `pthread_mutex_t`, `pthread_rwlock_t`)
or relying on pure user-space spinlocks fails in four ways:

- `CRITICAL_SECTION` takes 40 bytes on x64 Windows, `pthread_mutex_t` takes 40 to 64 bytes on
  Linux, and `pthread_rwlock_t` takes 200 bytes on macOS. Embedding one lock per resource slot,
  allocator bin, or entity chunk wastes L1 cache capacity.
- Opaque OS wrappers require non-`constexpr` runtime initialization (`InitializeCriticalSection`,
  `pthread_mutex_init`) and non-trivial destructors. File-scope locks risk the C++ Static
  Initialization Order Fiasco, and hiding `<windows.h>` behind `.cpp` files forces every
  uncontended `lock()` and `unlock()` through an out-of-line function call.
- Pure user-space Test-and-Test-and-Set (TTAS) spinlocks are 4 bytes and `constexpr`, but if the
  lock holder is preempted by the OS scheduler or stalls during `GP_CALL_ONCE` initialization,
  waiting threads burn CPU cycles and starve sibling threads.
- In an M:N fiber scheduler ([ADR-0049](./ADR-0049.md)), multiple cooperative fibers multiplex
  onto the same OS worker thread (`gp::platform::Thread::currentThreadId()`). An OS-thread-keyed
  `RecursiveMutex` (`CRITICAL_SECTION` or `pthread_mutex_t`) treats two different fibers on the
  same worker thread as the same owner, breaking mutual exclusion if a fiber yields or re-enters.

`gp::core` needs compact (`4` to `16` byte), `constexpr`-constructible, trivially destructible
synchronization primitives that execute a single inline atomic instruction when uncontended,
park in the OS kernel by memory address when contended on OS threads, and track fiber-aware
ownership for recursive locks.

## Decision

We introduce the `gp::platform::Futex` address-wait abstraction under
`source/runtime/core/public/platforms/` and the `gp::thread` mutual exclusion suite under
`source/runtime/core/public/threading/sync/`.

### Bit-packed state layouts and ownership protocol

```text
1. gp::thread::Mutex (4 Bytes, alignas(4))
+----------------------------------------------------+-------------------+---------------+
| Bits [31..2]                                       | Bit [1]           | Bit [0]       |
| Reserved (0)                                       | kMayHaveWaiters   | kLockedBit    |
+----------------------------------------------------+-------------------+---------------+
  Fast lock():   fetchOr(kLockedBit, Acquire) & kLockedBit == 0 (or CAS 0 -> 1)
  Fast unlock(): exchange(0, Release) == kLockedBit (no wake needed if bit 1 is 0)

2. gp::thread::RecursiveMutex / CriticalSection (16 Bytes, alignas(8))
+------------------------------------+--------------------+------------------------------+
| m_ownerToken : Atomic<UInt64> (8B) | m_State (4B)       | m_recursionDepth : UInt32(4B)|
| Bit 63=1: FiberId | Bit 63=0: Tid  | Futex lock word    | Re-entrant acquisition count |
+------------------------------------+--------------------+------------------------------+

3. gp::thread::SharedMutex (8 Bytes, alignas(4))
+----------------------------------------------------------------------------------------+
| Word 0: m_state : Atomic<UInt32> (4B, Writer futex wait address)                       |
|   Bit [31]: kWriterLockedBit   | Bit [30]: kWriterWaitingBit                           |
|   Bit [29]: kReaderWaitingBit  | Bits [28..0]: Active shared reader count (up to 536M) |
+----------------------------------------------------------------------------------------+
| Word 1: m_readerWakeEpoch : Atomic<UInt32> (4B, Reader broadcast futex wait address)   |
+----------------------------------------------------------------------------------------+

4. gp::thread::OnceFlag (4 Bytes, alignas(4))
+----------------------------------------------------------------------------------------+
| m_state : Atomic<UInt32> (0 = NotStarted, 1 = Running, 2 = RunningWaiting, 3 = Done)   |
+----------------------------------------------------------------------------------------+
```

### Primitive comparison matrix

| Primitive | Size / Align | State Storage | Contended Wait Mechanism |
| :--- | :--- | :--- | :--- |
| **`Mutex`** | `4 B` / `4 B` | `Atomic<UInt32>` | 32x `_mm_pause`, then `Futex::wait` |
| **`CacheAlignedMutex`** | `64 B` / `64 B` | `Mutex` + 60B pad | Prevents MESI false sharing |
| **`RecursiveMutex`** | `16 B` / `8 B` | Owner + `UInt32`x2 | Dual Fiber/Thread + `Futex::wait` |
| **`SharedMutex`** | `8 B` / `4 B` | `Atomic<UInt32>`x2 | Writer-preferring + epoch `wakeAll` |
| **`OnceFlag`** | `4 B` / `4 B` | `Atomic<UInt32>` | `Futex::wait` + `Futex::wakeAll` |
| **`UniqueLock<M>`** | `16 B` / `8 B` | `M*` + `bool` | Compile-time RAII exclusive guard |
| **`SharedLock<M>`** | `16 B` / `8 B` | `M*` + `bool` | Compile-time RAII shared guard |

### Architectural invariants

1. `Mutex`, `RecursiveMutex`, `SharedMutex`, and `OnceFlag` are `constexpr` default-constructible,
   trivially destructible (`~T() = default`), non-copyable, and non-movable, and perform zero
   heap allocations across their entire lifecycle.
2. Uncontended `lock()`, `tryLock()`, `unlock()`, `lockShared()`, `tryLockShared()`,
   `unlockShared()`, and completed `OnceFlag::isCompleted()` checks execute inline in public
   headers using `gp::thread::Atomic` intrinsics without calling into `.cpp` translation units
   or including `<windows.h>` / `<pthread.h>`.
3. Contended acquisitions spin in user space for `kMaxSpinIterations = 32` iterations via
   `gp::platform::Thread::spinWait()`. If the lock remains held and the caller is a raw OS thread
   (or `ThreadAnchor` fiber), it sets the waiter bit and sleeps in the kernel via
   `gp::platform::Futex::waitOnAddress()`. If the caller is executing inside a cooperative child
   `gp::thread::Fiber` (`Fiber::isExecutingInChildFiber()`), the slow path stays in user space
   (`Thread::spinWait()` / `Thread::yieldExecution()`) so a brief lock contention inside a fiber
   never puts the underlying `JobSystem` worker thread into an unscheduled kernel sleep.
4. `RecursiveMutex` (aliased as `gp::thread::CriticalSection` and `gp::CriticalSection`) computes
   a 64-bit execution owner token via `RecursiveMutex::currentExecutionOwnerToken()`: when
   `Fiber::isExecutingInChildFiber()` is true, the token is `(1ULL << 63) | currentFiberId`;
   otherwise it is `gp::platform::Thread::currentThreadId()`. Two distinct fibers running on the
   same OS worker thread never share a recursive lock owner token.
5. `SharedMutex` enforces writer preference via `kSharedMutexWriterWaitingBit` (`bit 30`): once a
   writer begins waiting, new `lockShared()` and `tryLockShared()` calls stall behind the pending
   writer so continuous reader traffic cannot starve writers. When the last reader unlocks while
   `kSharedMutexWriterWaitingBit` is set, it wakes one waiting writer on `&m_state`; when a writer
   unlocks with waiting readers and no waiting writer, it increments `m_readerWakeEpoch` and calls
   `Futex::wakeAll(&m_readerWakeEpoch)`. `SharedMutex` also supports single-CAS atomic reader-to-
   writer upgrades (`tryUnlockSharedAndLock()`) and writer-to-reader downgrades
   (`unlockAndLockShared()`).
6. `UniqueLock<MutexType>` (aliased as `ScopedLock<MutexType>`) and `SharedLock<SharedMutexType>`
   are constrained by `gp::concepts::IsBasicLockable`, `IsLockable`, and `IsSharedLockable`,
   support `DeferLock`, `TryToLock`, `AdoptLock`, `tryUpgradeToUnique()`, and deadlock-free
   multi-lock acquisition (`lockMultiple`, `tryLockMultiple`), and carry Clang `-Wthread-safety`
   capability annotations (`GP_THREAD_CAPABILITY`, `GP_SCOPED_THREAD_CAPABILITY`).
7. When `GP_DO_CHECK` is enabled, acquiring `Mutex`, `RecursiveMutex`, or `SharedMutex` increments
   the active fiber/thread non-yielding lock counter (`Fiber::adjustActiveNonYieldingLockCount`),
   and `Fiber::switchTo()` asserts that an outgoing child fiber holds zero non-yielding locks.
8. `OnceFlag` provides both `callOnce()` (`GP_CALL_ONCE`) and fallible `tryCallOnce()`, which
   resets `OnceFlag` to `OnceState::NotStarted` and wakes parked callers if the predicate returns
   `false`.

## Alternatives Considered

### Option A: Opaque OS primitives (`CRITICAL_SECTION`, `SRWLOCK`, `pthread_mutex_t`)

Wrap native OS synchronization structs inside opaque byte arrays (`alignas(8) UInt8[40..200]`) and
route all calls through `.cpp` wrappers.

**Why rejected:** `CRITICAL_SECTION` (40B) and `pthread_rwlock_t` (56B on Linux, 200B on macOS)
are 5x to 25x larger than bit-packed atomic words, require non-`constexpr` initialization and
destruction calls, force every uncontended lock/unlock through an out-of-line function call, and
key recursive ownership to the OS `ThreadId`, which breaks when two cooperative fibers run on the
same worker thread.

### Option B: Pure user-space TTAS spinlocks without kernel address parking

Implement all mutexes and `OnceFlag` purely as user-space atomic spin-yield loops without
`WaitOnAddress` or `futex`.

**Why rejected:** While a pure spinlock works for sub-microsecond critical sections, holding a
lock across an OS thread preemption or a long one-time initialization inside `GP_CALL_ONCE` forces
contending threads to burn 100% CPU in `spinWait()` / `yieldExecution()`, wasting power and
starving lower-priority threads.

### Option C: Intrusive `JobWaitNode` fiber-yielding mutexes

Build `Mutex` and `SharedMutex` on top of [ADR-0050](./ADR-0050.md)'s `JobWaitNode` list so fibers
yield back to the `JobSystem` scheduler on every contended lock.

**Why rejected:** Yielding a fiber inside a low-level mutex can migrate the fiber to a different
OS worker thread mid-critical-section, invalidating surrounding thread-local state and creating
hidden lock convoys across the fiber pool. Following Naughty Dog and REDengine conventions,
asynchronous job dependencies use `JobCounter` and `JobFence` ([ADR-0050](./ADR-0050.md)), while
`Mutex` and `SharedMutex` protect short non-yielding critical sections.

## Consequences

### Positive

- **Minimal cache footprint.** `Mutex` (`4B`), `OnceFlag` (`4B`), `SharedMutex` (`8B`), and
  `RecursiveMutex` (`16B`) pack up to 16 mutexes into a single 64-byte CPU cache line, and
  `CacheAlignedMutex` (`64B`) isolates hot global locks from false sharing.
- **Zero-cost static initialization and inline fast paths.** `constexpr` constructors and trivial
  destructors eliminate static initialization order bugs across DLLs, while uncontended locks
  compile to a single inline atomic instruction.
- **Zero-allocation kernel parking under contention.** `gp::platform::Futex` sleeps contending OS
  threads directly on the 4-byte lock address via `WaitOnAddress`, `futex`, or `__ulock_wait`
  without allocating kernel event handles.
- **Fiber-safe recursive ownership.** Keying `RecursiveMutex` to a dual-domain `FiberId`/`ThreadId`
  token prevents false recursive re-entry between fibers on the same worker thread.

### Negative

- **Non-recursive `Mutex` and `SharedMutex` cannot re-enter.** Calling `Mutex::lock()` or
  `SharedMutex::lockShared()` recursively on the same execution context deadlocks (particularly on
  `SharedMutex` when a writer arrives between recursive reader acquisitions); re-entrant callers
  must use `RecursiveMutex` (`CriticalSection`).
- **Brief user-space spin on fiber contention.** When a child fiber contends on a held `Mutex`,
  it spins/yields in user space rather than parking the worker OS thread in the kernel, so fibers
  must keep critical sections short and never yield while holding a mutex.
