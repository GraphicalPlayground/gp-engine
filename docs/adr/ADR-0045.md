# ADR-0045: Hybrid 24-Byte SSO String Container, Engine-Native `CharTraits`, and Zero-Allocation UTF Codec

> Establishes `gp::container::BasicString<CharT, Allocator>` (`gp::String`, `gp::WString`, `gp::U8String`,
> `gp::U16String`, `gp::U32String`, `gp::InlineString<N>`, `gp::ScratchString`) as a 24-byte owning string
> container combining in-situ Small String Optimization (`22` `char` capacity with zero heap allocations)
> and first-class `gp::concepts::IsAllocator` arena integration ([ADR-0042](./ADR-0042.md)), backed by an
> STL-free `constexpr` `gp::container::CharTraits<CharT>` and a zero-allocation `gp::unicode` UTF-8/16/32
> transcoding and codepoint iteration subsystem.

![Proposed][badge-proposed]

## Context

Strings in a AAA game engine span four distinct operational domains, each with radically different
memory lifetime, mutability, and lookup performance constraints:

1. **Non-Owning Lexical Inspection (`gp::StringView` — [ADR-0040](./ADR-0040.md)):** Zero-copy,
   `16-byte` `{ const CharT* data, USize size }` slices passed across function boundaries.
2. **Pre-Heap / Bounded Stack Buffers (`gp::FixedString<N>` / `gp::PathBuffer` — [ADR-0043](./ADR-0043.md)):**
   Compile-time bounded `CharT[N + 1]` buffers used in crash handlers, OS directory discovery, and
   lexical path normalization before dynamic allocators initialize.
3. **Dynamic Mutable Text Manipulation (`gp::String` — This ADR):** Runtime text assembly, log and
   UI formatting, asset path/URI construction, console command parsing, configuration serialization,
   and OS UTF-8 $\leftrightarrow$ UTF-16 boundary transcoding.
4. **Interned $O(1)$ Comparison Identifiers (`gp::Name` — [ADR-0046](./ADR-0046.md)):** Immutable, globally
   deduplicated identifiers (bones, sockets, shader parameters, gameplay tags) where equality
   reduces to a single 64-bit integer comparison.

Implementing Pillar 3 (`gp::String` and its foundational character/Unicode layer) in `gp-engine`
must resolve five concrete architectural problems:

### 1. Small-String Heap Churn vs. Arena Lifetime Integration

Empirical profiling across AAA engines (Frostbite/EASTL, Anvil, id Tech) demonstrates that over 85%
of transient runtime strings (shader uniform names, UI labels, short asset sub-paths, debug marker
names) are 22 characters or fewer. A naive pointer-based string (`{ CharT* data, USize size, USize capacity }`)
invokes the heap allocator and incurs an L1 cache miss on every short string construction.
Conversely, standard library `std::basic_string` implementations embed opaque, compiler-dependent
Small String Optimization (SSO) layouts that break ABI across DLL module boundaries ([ADR-0021](./ADR-0021.md))
and cannot bind to `gp-engine`'s sized lifetime-scoped arenas (`LinearAllocator`, `StackAllocator`,
`InlineAllocator`, `ThreadScratchAllocator`, `TaggedAllocator`, `PolymorphicAllocator` — [ADR-0042](./ADR-0042.md)).

### 2. Residual `<string>` (`std::char_traits`) Coupling and Locale Bottlenecks

Prior to this ADR, `StringView.hpp` included `<string>` solely to alias `std::char_traits<CharT>`.
Standard `std::char_traits` provides only case-sensitive comparisons, lacks character classification
or case-folding primitives, and in C++23/C++26 deprecates non-standard character specializations.
Worse, C runtime character utilities (`<cctype>` `tolower`, `toupper`, `isspace`, `strcasecmp`)
consult the global C locale (`LC_CTYPE`) behind an internal OS lock, causing both multi-threaded
contention and catastrophic Turkish-locale bugs (where ASCII `'I'` lowercases to dotless `'ı'`
instead of `'i'`, breaking shader and asset identifier lookups).

### 3. Cross-Platform UTF-8 / UTF-16 / UTF-32 Boundary Impedance

`gp-engine` standardizes on UTF-8 (`char`) for all internal engine strings ([ADR-0040](./ADR-0040.md),
[ADR-0043](./ADR-0043.md)). However:
- **Byte Length $\neq$ Codepoint Count:** In UTF-8, a single Unicode scalar value occupies 1 to 4
  bytes. Naive byte-level truncation or indexing mid-sequence corrupts multi-byte UTF-8 characters.
- **OS API Encoding Divergence:** Win32 kernel and shell APIs require UTF-16 (`wchar_t` = 2 bytes
  with surrogate pairs for `U+10000`..`U+10FFFF`), whereas Linux and macOS POSIX APIs use UTF-8
  `char` and 4-byte UTF-32 `wchar_t`.
- **Untrusted Input Safety:** Network chat packets, user save files, and mod manifests can contain
  malformed UTF-8 (overlong encodings, lone continuation bytes, unpaired UTF-16 surrogates, or code
  points $> \text{U+10FFFF}$). With C++ exceptions disabled (`-fno-exceptions`), the engine must
  deterministically sanitize invalid sequences using the Unicode Standard Replacement Character
  (`U+FFFD`) without crashing or reading out of bounds.

### 4. Self-Aliasing Mutation Hazards

When a caller mutates a string using a `StringView` or pointer that aliases the string's own buffer
(e.g., `str.append(str.view().substr(2, 5))` or `str.insert(0, str.cString())`), reallocating the
buffer or shifting characters in-place before reading the source view destroys the source characters,
causing silent memory corruption or use-after-free bugs.

### 5. Missing AAA Gameplay and Tooling String Ergonomics

Standard C++ strings lack the high-frequency operations required daily in gameplay, rendering, and
tooling code: case-insensitive searching (`SearchCase::IgnoreCase`), zero-allocation substring
slicing (`left`, `right`, `mid`, `leftChop`, `rightChop`, `trimView`), in-place substring
replacement (`replaceInPlace`), wildcard glob matching (`matchesWildcard` with `*` and `?`),
zero-allocation token splitting (`splitView`), `<charconv>` exception-free numeric parsing
(`tryParseInt32`, `tryParseFloat32`), and uninitialized buffer resizing (`resizeUninitialized`) for
zero-double-write I/O.

## Decision

We introduce a modular string, character-traits, and Unicode architecture in
`source/runtime/core/public/containers/strings/` and update `StringView.hpp` and `FixedString.hpp`
to share the same STL-free `CharTraits<CharT>` and `SearchCase` foundation.

### 1. The AAA Four-Pillar String Taxonomy in `gp-engine`

| Engine Type | Size (64-Bit) | Ownership & Mutability | Backing Storage | Primary Engine Role |
| :--- | :--- | :--- | :--- | :--- |
| **`gp::StringView`** | `16 B` | Non-owning, read-only | External buffer slice | Function parameters, token slices, zero-copy parsing |
| **`gp::FixedString<N>`** | `N + 1 + sizeof(SizeType)` | Owning, mutable (bounded) | Inline stack/struct array | `PathBuffer` (`1024B`), pre-heap startup, TLV packets |
| **`gp::String`** | `24 B` (`DefaultAllocator`) | Owning, mutable (dynamic) | `22-char` SSO or `IsAllocator` | Dynamic text assembly, formatting, I/O, UTF transcoding |
| **`gp::InlineString<N>`** | `24 B + sizeof(InlineAllocator<N>)` | Owning, mutable (dynamic) | `N-byte` SBO $\rightarrow$ Heap fallback | Stack string builder exceeding 22 chars without heap allocs |
| **`gp::ScratchString`** | `24 B` | Owning, mutable (frame/job) | `22-char` SSO or `ThreadScratchAllocator` | Zero-contention temporary strings on worker/job threads |
| **`gp::Name`** *(Future ADR)* | `8 B` | Interned handle, immutable | Global sharded `NamePool` | $O(1)$ identifier comparison (bones, tags, shader params) |

### 2. 24-Byte Tagged-Union SSO and Arena Allocator Layout (`BasicString`)

`gp::container::BasicString<CharT, Allocator>` occupies exactly **24 bytes** on 64-bit platforms
when instantiated with any stateless allocator (`HeapAllocator`, `AlignedHeapAllocator`,
`ThreadScratchAllocator`) via `GP_NO_UNIQUE_ADDRESS`:

```text
+-----------------------------------------------------------------------+
| Heap Mode (isLong() == true: LSB of capacityFlag is 1)                |
+-----------------------+-----------------------+-----------------------+
| CharT* m_data (8B)    | USize m_size (8B)     | USize m_capFlag (8B)  |
|                       | (in CharT units)      | (cap << 1) | 1ULL     |
+-----------------------+-----------------------+-----------------------+

+-----------------------------------------------------------------------+
| SSO Mode (isLong() == false: LSB of ssoTag is 0)                      |
+---------------------------------------------------------------+-------+
| CharT m_buffer[kSsoCapacity + 1] (up to 23 bytes)             | Tag   |
| (for char: 22 chars + '\0'; at size == 22, Tag == 0 == '\0')  | (1B)  |
+---------------------------------------------------------------+-------+
```

- **Capacity Capacities by `CharT`:**
  - `char` / `char8_t` (`sizeof == 1`): `kSsoCapacity = 22` code units (+1 null terminator).
  - `char16_t` / `wchar_t` (Windows, `sizeof == 2`): `kSsoCapacity = 10` code units (+1 null terminator).
  - `char32_t` / `wchar_t` (POSIX, `sizeof == 4`): `kSsoCapacity = 4` code units (+1 null terminator).
- **Zero-Branch Invariant on Empty Construction:** Default construction zero-initializes the 24-byte
  union (`m_sso.buffer[0] = 0`, `ssoSize = 0`, `isLong = false`), performing **zero allocator calls**
  while guaranteeing `cString()` and `data()` return a valid null-terminated pointer (`&m_sso.buffer[0]`).
- **Bitwise Relocatability (`IsRelocatable`):** Because `BasicString` never stores a pointer to its
  own internal `m_sso.buffer` (instead computing `isLong() ? m_heap.data : m_sso.buffer` inside
  `data()`), moving or relocating a `BasicString` inside `gp::Vector<gp::String>` via
  `gp::memory::relocateConstructItems` (`memcpy`/`memmove`) is 100% valid for stateless allocators.
- **Sized Arena Allocator Contract ([ADR-0042](./ADR-0042.md)):** When transitioning from SSO to
  dynamic storage or resizing a dynamic buffer, `BasicString` computes growth via
  `gp::memory::calculateSlackGrow` and passes exact byte counts `(oldCapacity + 1) * sizeof(CharT)`
  and `(newCapacity + 1) * sizeof(CharT)` to `m_allocator.reallocate()` and `m_allocator.deallocate()`,
  unlocking $O(1)$ in-place top-of-bumper resizing in `LinearAllocator` and `ThreadScratchAllocator`.

### 3. Engine-Native `CharTraits<CharT>` and Locale-Free Case Folding

`gp::container::CharTraits<CharT>` in `containers/strings/CharTraits.hpp` replaces
`std::char_traits<CharT>` across all string and view types:

1. **Deterministic ASCII Case Folding:** `toLower(ch)` and `toUpper(ch)` fold ASCII `'A'`..`'Z'`
   and `'a'`..`'z'` using branchless arithmetic without touching `<cctype>` or OS locales.
2. **Dual-Mode `SearchCase` Comparisons:** `compare`, `equals`, `find`, `rfind`, `startsWith`, and
   `endsWith` support both `SearchCase::CaseSensitive` (using compiler intrinsics `__builtin_memcmp` /
   `__builtin_strlen` where applicable) and `SearchCase::IgnoreCase` in `constexpr` contexts.
3. **64-Bit FNV-1a `constexpr` Hashing:** `CharTraits<CharT>::hash(data, count)` and
   `CharTraits<CharT>::hashIgnoreCase(data, count)` compute 64-bit FNV-1a hashes (`offset_basis = 14695981039346656037ULL`,
   `prime = 1099511628211ULL`), providing deterministic compile-time and runtime hashing for both
   `gp::Map`/`gp::Set` and the future `gp::Name` subsystem.

### 4. Zero-Allocation `constexpr` UTF Codec (`gp::unicode`)

`containers/strings/Unicode.hpp` provides a pure `constexpr`, zero-allocation Unicode transcoding
and inspection suite:

- **Single-Step Codepoint Primitives:** `decodeUtf8(ptr, end, outCodepoint)` and
  `decodeUtf16(ptr, end, outCodepoint)` advance the input cursor and decode one Unicode scalar value
  (`char32_t`). Any ill-formed byte sequence (overlong encoding, unexpected continuation byte,
  truncated multi-byte sequence, unpaired surrogate `0xD800`..`0xDFFF`, or value `> 0x10FFFF`)
  consumes the maximal subpart and outputs `kReplacementChar` (`U'\uFFFD'`).
- **Zero-Allocation Codepoint Range (`Utf8CodepointView`):** Both `String` and `StringView` expose
  `.codepoints()`, returning a lightweight `Utf8CodepointView` whose `const_iterator` yields decoded
  `char32_t` code points in range-based `for` loops with zero memory allocations.
- **Cross-Encoding Conversion:** `unicode::convert(srcView, dstString)` and static factories
  (`String::fromUtf16`, `String::fromUtf32`, `String::fromWide`, `str.toUtf16()`, `str.toUtf32()`,
  `str.toWide()`) pre-calculate exact target code-unit lengths (`utf8ToUtf16Length`,
  `utf16ToUtf8Length`), reserve once, and transcode in a single pass.

### 5. Architectural Invariants

1. **Null-Termination Guarantee:** `BasicString::cString()` and `BasicString::data()` always return
   a non-null pointer `p` such that `p[size()] == CharT{0}`, even for default-constructed or
   moved-from strings.
2. **Zero `<string>` Dependency in Core Headers:** Neither `StringView.hpp`, `FixedString.hpp`, nor
   `String.hpp` may use `std::basic_string` or `std::char_traits`.
3. **Self-Aliasing Safety:** Every mutating method (`assign`, `append`, `prepend`, `insert`,
   `replaceInPlace`) must handle source ranges that alias `[data(), data() + size()]` without
   corrupting memory or reading freed pointers.
4. **Locale Independence:** All case transformations, comparisons, and numeric conversions
   (`<charconv>`) must be 100% independent of the global C/C++ locale.

## Alternatives Considered

### Option A: Pure Pointer + Size + Capacity Without Internal SSO (Unreal Engine `FString` Model)

Store `{ CharT* m_data; USize m_size; USize m_capacity; }` and rely exclusively on
`InlineAllocator<N>` when stack storage is desired.

**Why rejected:** Forces every default `gp::String` instance to allocate on the heap even for
4-character identifiers, causing unnecessary allocator traffic and cache misses when `gp::String` is
used inside data structures, descriptors, or parser ASTs.

### Option B: Intrusive Reference-Counted Copy-on-Write (CoW) String (Decima / CryEngine Model)

Store a single `CharT*` pointing past a heap-allocated `{ Atomic<Int32> refCount, UInt32 size, UInt32 capacity, UInt32 hash }`
header, sharing buffers across copies until mutated.

**Why rejected:** Atomic `refCount` increments/decrements across worker threads induce severe MESI
cache-line ping-ponging ([ADR-0025](./ADR-0025.md)), Copy-on-Write triggers hidden heap allocations
during non-const element access, and shared reference-counted lifetimes are fundamentally
incompatible with scoped frame/scratch arenas ([ADR-0042](./ADR-0042.md)). Fast $O(1)$ immutable
identifier sharing is better served by a dedicated `gp::Name` type.

### Option C: UTF-16 (`wchar_t` / `char16_t`) as Canonical Engine String (Unreal Engine `TCHAR` Model)

Define `gp::String` as UTF-16 by default.

**Why rejected:** Doubles memory footprint and cache bandwidth for ASCII-heavy engine strings (paths,
shader code, JSON/INI/YAML config files, network protocols) and conflicts with [ADR-0040](./ADR-0040.md)
and [ADR-0043](./ADR-0043.md), which standardize on UTF-8 ("UTF-8 Everywhere"). Providing UTF-8
`gp::String` alongside `gp::U16String` and `gp::WString` with zero-pass-overhead transcoding gives
optimal cache density while keeping Win32 interop ergonomic.

## Consequences

### Positive

- **Eliminates heap allocations for short strings ($\le 22$ bytes).** The 24-byte SSO layout stores
  up to 22 UTF-8 bytes directly inside the `gp::String` instance with zero allocator overhead and
  optimal L1 cache locality.
- **Full compatibility with `gp-engine` lifetime-scoped arenas.** Long strings and `InlineString<N>`
  / `ScratchString` aliases route all allocations through the sized `IsAllocator` contract
  ([ADR-0042](./ADR-0042.md)), enabling $O(1)$ in-place top-of-bumper expansion in `LinearAllocator`.
- **Purges `<string>` (`std::char_traits`) and locale locks.** `CharTraits<CharT>` provides
  deterministic, `constexpr`, locale-free character classification, case-insensitive matching, and
  64-bit FNV-1a hashing ready for `gp::Name`.
- **Safe, exception-free Unicode transcoding.** `gp::unicode` decodes, validates, iterates, and
  transcodes UTF-8, UTF-16, UTF-32, and `wchar_t` with deterministic `U+FFFD` replacement on
  malformed input.
- **Production-grade AAA utility ergonomics.** Built-in `SearchCase`, zero-copy slicing, wildcard
  matching, zero-allocation token splitting, `resizeUninitialized`, and `<charconv>` numeric parsing
  eliminate boilerplate across gameplay and tooling modules.

### Negative

- **1-branch/CMOV indirection on `data()` and `size()`.** Selecting between SSO and Heap layouts
  requires checking the 1-bit long flag, adding a single bitwise test and conditional move compared
  to a raw pointer load.
- **Implementation complexity for self-aliasing and SSO transitions.** Mutating operations must
  carefully sequence buffer reallocation and character shifts when source views alias the active SSO
  or heap buffer.
