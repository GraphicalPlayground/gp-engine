# ADR-0056: Contiguous and Byte-Strided Sequence Views (`gp::VectorView` and `gp::StridedView`)

> Establishes `gp::container::VectorView<T>` (`16 B`) and `gp::container::StridedView<T>` (`24 B`)
> as STL-free, `constexpr`, non-owning sequence views standardized on `gp::USize` and signed
> `gp::ISize` byte strides, decoupling engine APIs from concrete container allocators and bridging
> Array-of-Structures (AoS) and Structure-of-Arrays (SoA) data streams without heap allocations.

![Proposed][badge-proposed]

## Context

With [ADR-0042](./ADR-0042.md) and [ADR-0055](./ADR-0055.md), `gp-engine` provides multiple owning
contiguous sequence types tailored to distinct memory lifetimes: `gp::Array<T, N>`,
`gp::Vector<T>`, `gp::InlineVector<T, N>`, `gp::FixedVector<T, N>`, `gp::ScratchVector<T>`,
`gp::PolymorphicVector<T>`, and `gp::AlignedVector<T, A>`.

Passing and inspecting these sequences across module and subsystem boundaries exposes four concrete
architectural problems:

### 1. Allocator Type Proliferation at API Boundaries

In C++, `gp::Vector<Vertex, HeapAllocator>`, `gp::InlineVector<Vertex, 64>`, and
`gp::ScratchVector<Vertex>` are distinct types. If a renderer or physics function accepts
`const gp::Vector<Vertex>&`, callers holding an `InlineVector`, a `ScratchVector`, a fixed
`gp::Array<Vertex, 8>`, or a stack C array cannot pass their data without either templating the
function on every container type or copying elements into a temporary heap-allocated `gp::Vector`.

### 2. The AoS-to-SoA Extraction Penalty in Rendering, Animation, and Physics

Engine subsystems frequently store interleaved records in Array-of-Structures (AoS) layout for
authoring or cache-coherent single-object updates, such as:

```cpp
struct SkinnedVertex
{
    gp::math::Vector3f position;
    gp::math::Vector3f normal;
    gp::math::Vector4f tangent;
    gp::math::Vector2f uv;
};
```

However, downstream algorithms (such as an AABB bounds calculator, a SIMD frustum culler, or a
debug line batcher) often consume only `position` across all $N$ elements. If the consumer only
accepts a contiguous `VectorView<const Vector3f>`, the caller is forced to allocate a temporary
buffer and copy `position` out of every `SkinnedVertex` before calling the function.

### 3. Legacy `Int32` vs. `gp::USize` Index Fragmentation

Earlier forward declarations in `ContainerForward.hpp` parameterized `VectorView<T, InSizeType>`
and `StridedView<T, InSizeType>` with a default `Int32` size type, while `gp::Array`, `gp::String`,
`gp::StringView`, and `gp::Vector` use 64-bit `gp::USize`. Mixing signed 32-bit view sizes with
64-bit container sizes forces narrowing conversions and splits the API into redundant `VectorView`
and `VectorView64` variants.

### 4. Unsafe Pointer + Count Pair Boilerplate

Passing raw `(const T* data, USize count)` parameter pairs loses bounds checking on sub-range
slicing, cannot be passed directly to range-based `for` loops or `<algorithm>`, and requires manual
`reinterpret_cast` boilerplate when inspecting raw byte representations for serialization or RHI
buffer uploads.

## Decision

We introduce `gp::container::VectorView<T>` in
`source/runtime/core/public/containers/views/VectorView.hpp` and `gp::container::StridedView<T>` in
`source/runtime/core/public/containers/views/StridedView.hpp`, standardized on `gp::USize` counts
and `gp::ISize` byte strides.

```text
source/runtime/core/
  public/
    containers/
      ContainerForward.hpp          <-- Forward declarations for VectorView, ConstVectorView,
                                        StridedView, and ConstStridedView (unified on USize)
      views/
        VectorView.hpp              <-- 16-byte contiguous non-owning view (mutable & const T)
        StridedView.hpp             <-- 24-byte byte-strided non-owning view + makeStridedView
  tests/
    containers/
      views/
        VectorView.tests.cpp        <-- Unit tests for VectorView construction, slicing, search,
                                        const conversion, and byte reinterpretation
        StridedView.tests.cpp       <-- Unit tests for StridedView AoS member projection, zero
                                        stride, negative reverse stride, and random-access iterators
```

### 1. `gp::VectorView<T>` and `gp::ConstVectorView<T>` (16-Byte Contiguous Slice)

`gp::container::VectorView<T>` (`gp::VectorView<T>`) is a 16-byte, trivially copyable value type
(`{ T* m_data; gp::USize m_size; }`) representing a non-owning view over contiguous elements:

- **Unified Mutability via `T` Qualification:**
  - `gp::VectorView<T>` provides mutable element access (`T&`).
  - `gp::ConstVectorView<T>` (alias for `gp::VectorView<const T>`) provides read-only access
    (`const T&`).
  - `VectorView<T>` converts implicitly to `VectorView<const T>`.
- **Zero-Copy Container Interoperability:** Implicitly constructs from `gp::Vector<U, Allocator>`,
  `gp::Array<U, N, Alignment>`, C-style arrays `U[N]`, `std::initializer_list<U>` (for `const T`),
  and `(T* data, USize count)` or `(T* first, T* last)` pointer ranges whenever `U*` is
  qualification-convertible to `T*`.
- **Slicing & Query Ergonomics:**
  - Slicing: `slice(offset, count)`, `first(count)`, `last(count)`, `dropFirst(count)`, and
    `dropLast(count)`.
  - Searching: `find`, `findIf`, `contains`, `count`, `indexOf`, `lastIndexOf`, `indexIf`,
    `startsWith`, and `endsWith`.
  - Byte Views: `asBytes()` returns `VectorView<const gp::UInt8>` (`sizeInBytes()`);
    `asWritableBytes()` (enabled when `!IsConst<T>`) returns `VectorView<gp::UInt8>`.

### 2. `gp::StridedView<T>` and `gp::ConstStridedView<T>` (24-Byte Byte-Strided Slice)

`gp::container::StridedView<T>` (`gp::StridedView<T>`) is a 24-byte, trivially copyable value type
that generalizes `VectorView<T>` with a signed runtime byte stride:

```text
+-----------------------+-----------------------+-----------------------+
| T* m_data (8B)        | USize m_size (8B)     | ISize m_stride (8B)   |
+-----------------------+-----------------------+-----------------------+
```

Element `i` is resolved in $O(1)$ via byte pointer arithmetic:

$$\text{address}(i) = \text{reinterpret\_cast}<\text{BytePtr}>(m\_data) + i \times m\_stride$$

- **AoS Member Projection (`makeStridedView`):** Given any contiguous or strided sequence of
  `StructType` and a pointer-to-data-member `MemberType StructType::*member`,
  `gp::makeStridedView(source, &StructType::member)` constructs a `StridedView<MemberType>` (or
  `ConstStridedView<MemberType>`) pointing to `&source[0].*member` with
  `strideInBytes = sizeof(StructType)` (or `source.stride()`). Subsystems can iterate over a single
  struct field across thousands of items with zero allocations and zero data copies.
- **Signed Stride Capabilities (`m_strideInBytes`):**
  - **Contiguous (`m_stride == sizeof(T)`):** Implicitly converts from any `VectorView<T>`,
    `Vector<T, Allocator>`, or `Array<T, N>`.
  - **Interleaved (`m_stride > sizeof(T)`):** Steps across AoS records or matrix rows/columns.
  - **Broadcast (`m_stride == 0`):** Repeatedly yields `*m_data` across `m_size` iterations,
    allowing uniform constants to be fed into stream processors without duplicating memory.
  - **Reverse (`m_stride < 0`):** Steps backward through memory in $O(1)$ without reverse-iterator
    wrappers (`reverseStrided()`).

### 3. Comparison of Sequence View Types in `gp-engine`

| View Type | Size | Memory Layout | Stride | Primary Role |
| :--- | :--- | :--- | :--- | :--- |
| `gp::StringView` | `16 B` | `{ const CharT*, USize }` | `sizeof(CharT)` | UTF-8 text slicing |
| `gp::VectorView<T>` | `16 B` | `{ T*, USize }` | `sizeof(T)` | Contiguous array slice |
| `gp::StridedView<T>` | `24 B` | `{ T*, USize, ISize }` | Runtime bytes | AoS field stream slice |

### 4. Architectural Invariants

1. **Trivially Copyable Value Semantics:** Both `VectorView<T>` and `StridedView<T>` are trivially
   copyable (`IsRelocatable == true`) and should be passed by value in registers.
2. **Unified `gp::USize` / `gp::ISize` Types:** `SizeType` is strictly `gp::USize` and
   `DifferenceType` (and byte stride) is strictly `gp::ISize`. The legacy `Int32` size template
   parameter is removed; `VectorView64<T>` and `ConstVectorView64<T>` remain as backwards-compatible
   aliases to `VectorView<T>` and `ConstVectorView<T>`.
3. **Alignment Invariant on `StridedView`:** `m_strideInBytes` must be an integer multiple of
   `alignof(T)` (`(m_strideInBytes % alignof(T)) == 0`), enforced via `GP_ASSERT` on construction so
   every indexed element satisfies hardware alignment requirements.
4. **Const-Qualification Safety:** Converting a view of `const U` to a mutable view `VectorView<T>`
   or `StridedView<T>` is rejected at compile time via C++23 `requires` constraints.
5. **Debug Bounds Verification:** All indexing (`operator[]`, `at`, `front`, `back`) and slicing
   (`slice`, `first`, `last`, `dropFirst`, `dropLast`) operations assert bounds via `GP_ASSERT`.

## Alternatives Considered

### Option A: Standard Library `std::span` and `std::ranges::transform_view`

Use `<span >` for contiguous views and `std::views::transform` for AoS member projection.

**Why rejected:** Rejected per [ADR-0021](./ADR-0021.md). `std::span` lacks engine slicing/search
utilities (`indexOf`, `lastIndexOf`, `dropFirst`, `slice`) and cannot represent runtime byte
strides. Meanwhile, `std::ranges::transform_view` embeds a callable functor in its type signature,
preventing non-templated `.cpp` functions from accepting a concrete `StridedView<const Vector3f>`
across module boundaries.

### Option B: Element-Count Stride (`m_strideInElements * sizeof(T)`) Instead of Byte Stride

Store the stride as a multiple of `sizeof(T)` instead of raw bytes.

**Why rejected:** An AoS struct such as `struct Entity { UInt32 id; Vector3f pos; UInt8 flags; };`
has `sizeof(Entity) == 20`, which is not an integer multiple of `sizeof(Vector3f) == 12`. Storing
stride in bytes (`m_strideInBytes = 20`, which is a multiple of `alignof(Vector3f) == 4`) allows
`StridedView<Vector3f>` to step across `Entity::pos` accurately, whereas element-count striding
cannot represent it.

### Option C: Retaining Legacy `InSizeType = Int32` Template Parameter on Views

Keep `template <typename InT, typename InSizeType = Int32>` on `VectorView` and `StridedView`.

**Why rejected:** Splits every view consumer into incompatible 32-bit and 64-bit overloads and
forces explicit casts when interoperating with `gp::Vector::size()` (`gp::USize`) and
`gp::Array::size()` (`gp::USize`).

## Consequences

### Positive

- **Decouples function signatures from container allocators.** A single function accepting
  `gp::ConstVectorView<T>` seamlessly accepts `gp::Vector`, `gp::InlineVector`, `gp::FixedVector`,
  `gp::ScratchVector`, `gp::Array`, and C arrays with zero heap allocations.
- **Eliminates AoS-to-SoA temporary buffer copies.** `gp::makeStridedView(vertices, &Vertex::pos)`
  lets bounds, physics, and rendering algorithms read or mutate a single struct field in place.
- **Supports zero-stride broadcasting and negative-stride reversal.** `StridedView` can repeat a
  single element across $N$ iterations (`stride == 0`) or traverse a buffer backward (`stride < 0`)
  using the exact same 24-byte type.
- **Consistent 64-bit `gp::USize` indexing across all containers.** Removes signed/unsigned 32-bit
  conversion friction across the entire `gp::core` container library.

### Negative

- **Non-owning lifetime responsibility.** Like `gp::StringView`, `VectorView` and `StridedView` do
  not extend the lifetime of the underlying container; storing a view after the backing `Vector`
  reallocates or is destroyed results in a dangling pointer.
- **Reduced hardware prefetcher efficiency on wide strides.** Iterating a `StridedView` with a
  large byte stride touches fewer useful bytes per 64-byte cache line than a packed contiguous
  `VectorView`.
