# ADR-0050: Intrusive Stack Wait-Nodes, 64-Bit Packed Job Counters, and Post-Switch Stack Latches

> Global fixed-capacity fiber wait tables incur $O(M)$ cross-core cache-line invalidations on every
> job completion, while naive check-then-park counters suffer from lost wakeups or dual-core stack
> clobbering when a waker resumes a fiber before the yielding core finishes saving its registers.
> `gp-engine` introduces zero-allocation, stack-resident **`gp::thread::JobWaitNode`** entries, a
> 64-bit bit-packed **`gp::thread::JobCounter`** (`CacheAlignedJobCounter`), a binary
> **`gp::thread::JobFence`**, and a hardware-enforced **`Fiber::m_isStackActive`** post-switch
> release latch in `gp::core`.

![Proposed][badge-proposed]

## Context

With elastic fiber scratch arenas ([ADR-0048](./ADR-0048.md)) and stackful cooperative fibers
([ADR-0049](./ADR-0049.md)) in place, `gp-engine`'s $M:N$ work-stealing job system requires
synchronization primitives that allow a running job fiber (or an external OS thread) to spawn child
jobs and suspend execution until those dependencies complete (`counter.wait(targetCount)` or
`fence.wait()`). Designing cooperative fiber synchronization across symmetric multiprocessing (SMP)
cores exposes three critical architectural hazards:

### 1. The Check-Then-Park ("Lost Wakeup") Race Condition

Suppose Fiber $F_A$ on Worker Core $0$ awaits a `JobCounter` whose current value is `1`, while the
final child job finishes simultaneously on Worker Core $1$:

1. Core $0$ loads `counter == 1` (not yet `0`) and prepares to link $F_A$ into the counter's wait
   list.
2. Before Core $0$ links $F_A$, Core $1$ executes `counter.decrement()` (`1 -> 0`), inspects the
   wait list, sees it empty, and returns.
3. Core $0$ finishes linking $F_A$ into the already-completed counter and switches to the worker
   scheduler anchor. Because no further decrements will ever occur, **$F_A$ is permanently
   orphaned, deadlocking the engine**.

### 2. The Premature Resumption ("Dual-Core Stack Clobber") Race Condition

To prevent a lost wakeup, Fiber $F_A$ on Core $0$ must publish its wait-node into the counter's
wait list *before* calling `Fiber::switchTo()` to yield its CPU registers and `64 KiB` stack:

1. Core $0$ links $F_A$'s wait-node into the counter and begins returning toward
   `Fiber::switchTo(schedulerAnchor)`.
2. Five nanoseconds later—while Core $0$ is still executing instructions on $F_A$'s stack frame or
   mid-way through saving `RBX`/`RBP`/`XMM6–XMM15` inside `m_context.switchTo()`—Core $1$
   decrements the counter to `0`, pops $F_A$'s wait-node, and immediately calls `switchTo(F_A)`.
3. **Core $0$ and Core $1$ now execute simultaneously on the exact same `64 KiB` stack**,
   overwriting each other's return addresses and register frames and crashing the process (or
   triggering a Windows 11 CET `0xC0000409` shadow-stack violation).

### 3. Global Wait-Table Contention vs. Per-Event Heap Allocations

Existing industry designs trade off between two extremes:

- **Global Fixed Wait Array (Naughty Dog GDC 2015):** Storing a single global array of $160$
  waiting fiber slots scanned by worker threads on job boundaries avoids pointers inside `Counter`,
  but forces $N$ CPU cores to repeatedly scan and contend on shared global cache lines
  ([ADR-0025](./ADR-0025.md)) and delays fiber wakeups until the next scheduler poll.
- **Heap-Allocated Continuation Nodes (Unreal Engine `FGraphEvent`):** Allocating a reference-
  counted event node per dependency edge avoids fixed tables, but introduces allocator traffic and
  shatters imperative C++ control flow into continuation callbacks.

## Decision

We introduce a zero-allocation, intrusive synchronization subsystem in
`source/runtime/core/public/threading/sync/` consisting of **`JobWaitNode`**, **`JobFiberParker`**
(`ScopedJobFiberParker`), **`JobCounter`** (`CacheAlignedJobCounter`), and **`JobFence`**, paired
with a post-switch stack-occupancy handshake (`m_isStackActive`) inside
[`gp::thread::Fiber`](./ADR-0049.md):

```text
source/runtime/core/
  public/
    threading/
      fibers/
        Fiber.hpp                 <-- Adds m_isStackActive post-switch stack latch
      sync/
        JobSyncForward.hpp        <-- Forward declarations for JobCounter, JobFence, etc.
        JobSyncEnums.hpp          <-- JobSyncResult, JobWaitMode, JobWaitNodeState
        JobSyncTypes.hpp          <-- JobYieldFunction, JobWakeFunction & bit masks
        JobWaitNode.hpp           <-- Stack-allocated wait node & JobFiberParker hooks
        JobCounter.hpp            <-- 64-bit bit-packed JobCounter & CacheAlignedJobCounter
        JobFence.hpp              <-- Binary completion barrier for phase/frame handoffs
  private/
    threading/
      fibers/
        Fiber.cpp                 <-- Post-switch outgoing stack release & incoming acquire
      sync/
        JobWaitNode.cpp           <-- GP_FORCENOINLINE thread-local parker accessors
        JobCounter.cpp            <-- 64-bit packed state machine & intrusive wake logic
        JobFence.cpp              <-- One-shot / resettable fence wait & signal logic
  tests/
    threading/
      sync/
        JobSync.tests.cpp         <-- Unit & SMP race tests for counters, fences & fibers
```

### 1. Stack-Resident Intrusive Wait Node (`gp::thread::JobWaitNode`)

Because a suspended [`gp::thread::Fiber`](./ADR-0049.md) (or a blocked OS thread) preserves its
active call stack in virtual memory throughout `wait()`, every waiter allocates its `JobWaitNode`
**directly on its own call stack**:

```text
Stack Frame of JobCounter::wait() / JobFence::wait()
+-----------------------------------------------------------------------+
| next           : JobWaitNode* (Intrusive singly-linked list pointer)  |
| waitingFiber   : Fiber* (Suspended child Fiber*, or nullptr for OS)   |
| wakeCallback   : JobWakeFunction (Stateless C callback [ADR-0022])    |
| wakeUserData   : void* (Scheduler queue or parker context pointer)    |
| targetCount    : UInt32 (Threshold <= which this waiter wakes)        |
| state          : Atomic<JobWaitNodeState> (Waiting -> Signaled)       |
+-----------------------------------------------------------------------+
```

- **Zero Heap Allocations & Unbounded Capacity:** Linking stack-allocated `JobWaitNode` instances
  into an intrusive list requires **0 bytes** of heap memory and supports an arbitrary number of
  concurrent fiber and OS-thread waiters on a single counter or fence.
- **Stateless Scheduler Hook (`JobFiberParker` & `ScopedJobFiberParker`):** Following
  [ADR-0022](./ADR-0022.md), worker threads register a thread-local `JobFiberParker` containing two
  stateless C function pointers (`JobYieldFunction` to switch back to the worker's scheduler fiber
  and `JobWakeFunction` to push a woken `Fiber*` into the scheduler's ready queue). When no custom
  parker is registered (e.g., standalone `Fiber` unit tests), `JobCounter` automatically defaults to
  yielding via `Fiber::yieldToReturnFiber()`.

### 2. 64-Bit Bit-Packed Atomic `gp::thread::JobCounter`

`JobCounter` packs its entire synchronization state into a single 64-bit
[`gp::thread::Atomic<gp::UInt64>`](./ADR-0024.md) (`m_state`) alongside an intrusive head pointer
(`JobWaitNode* m_waitListHead`), fitting in exactly **16 bytes** (`sizeof(JobCounter) == 16`):

```text
64-Bit Atomic State Word (m_state)
+---------------+-----------------+-------------------------+----------------------+
| Bit [63]      | Bit [62]        | Bits [61..32]           | Bits [31..0]         |
| kLockBit      | kHasThreshold   | waiterCount (30-bit)    | count (32-bit)       |
| (TTAS latch)  | (target > 0)    | Parked wait-node count  | Active job count     |
+---------------+-----------------+-------------------------+----------------------+
```

1. **Single-Instruction Fast Path on `decrement(delta)`:**
   - Executes `const gp::UInt64 prev = m_state.fetchSub(delta, MemoryOrder::AcqRel);`.
   - Because `count >= delta`, subtracting `delta` from bits `[0..31]` never borrows from bits
     `[32..63]`.
   - When `newCount > 0` and `(prev & (kJobCounterHasThresholdWaiterBit | kJobCounterLockBit)) == 0`
     (or when `newCount == 0` and `(prev >> 32) == 0`), `decrement()` completes in **one hardware
     `LOCK XADD` instruction** without acquiring `kJobCounterLockBit` or touching `m_waitListHead`.
2. **Closing Race 1 (Eliminating Lost Wakeups):**
   - To park on `wait(targetCount)`, a waiter acquires `kWaitListLockBit` (bit 63) via `fetchOr`
     with `MemoryOrder::Acquire`.
   - While holding `kWaitListLockBit`, it reloads `m_state` and inspects the lower 32-bit `count`.
     If `count <= targetCount`, it clears `kWaitListLockBit` and returns immediately without
     yielding.
   - Otherwise, it links its stack `JobWaitNode` into `m_waitListHead`, atomically adds `1` to
     `waiterCount` (bit 32), and clears `kWaitListLockBit` (bit 63).
   - If another core called `fetchSub(delta)` during the nanoseconds while `kWaitListLockBit` was
     held, that core observed `(prev >> 32) != 0` (because bit 63 was `1`), forcing it into
     `notifyWaiters()`, where it waits for `kWaitListLockBit` and wakes the newly linked node.
3. **Cache-Line Isolated Variant (`CacheAlignedJobCounter`):**
   - For high-contention parallel-for roots where all $N$ worker threads decrement the same counter,
     `alignas(64) CacheAlignedJobCounter` pads `JobCounter` to a full 64-byte cache line
     ([ADR-0025](./ADR-0025.md)) to prevent false sharing.

### 3. Post-Switch Stack-Occupancy Handshake (`Fiber::m_isStackActive`)

To eliminate Race 2 (Core $1$ resuming $F_A$ while Core $0$ is still vacating $F_A$'s stack),
[`gp::thread::Fiber`](./ADR-0049.md) enforces a hardware-synchronized stack-occupancy invariant
modeled after the Linux kernel's `finish_task_switch()`:

1. Every child `Fiber` owns `gp::thread::Atomic<gp::UInt8> m_isStackActive`. While $F_A$ executes on
   Core $0$, `m_isStackActive` is `1`.
2. When $F_A$ calls `F_A.switchTo(target)` on Core $0$, Core $0$ records `tl_outgoingFiber = &F_A`
   in a `GP_FORCENOINLINE` thread-local slot **before** invoking `m_context.switchTo()`. Throughout
   `JobCounter::wait()` and `m_context.switchTo()`, `F_A.m_isStackActive` remains `1`.
3. Immediately **after** `m_context.switchTo()` returns on Core $0$ (now executing on `target`'s
   stack, completely off $F_A$'s stack), Core $0$ consumes `tl_outgoingFiber` and executes
   `F_A.m_isStackActive.store(0u, MemoryOrder::Release)`.
4. Before any core switches *into* a child `target` fiber in `Fiber::switchTo(target)`, it claims
   `target.m_isStackActive` via an `Acquire` compare-and-exchange loop (`0u -> 1u`), spinning with
   `gp::platform::Thread::spinWait()` for ~10–20 ns until the outgoing core releases the stack.

### 4. Binary Completion Barrier (`gp::thread::JobFence`)

`gp::thread::JobFence` provides an explicit `8-byte` (`sizeof(JobFence) == 8`) one-shot or
resettable completion barrier for frame-phase transitions (e.g., Game Thread awaiting RHI command
recording completion). It packs `kSignaledBit` and `kLockBit` into the low 2 alignment bits of its
8-byte-aligned `JobWaitNode*` head pointer (`gp::Atomic<gp::UIntPtr>`), supporting lock-free
`isSignaled()` queries, single-CAS `signal()`, `reset()`, and dual-mode fiber/OS-thread `wait()`.

### Synchronization Primitive Comparison Matrix

| Primitive | Layout | State Storage | Primary Role |
| :--- | :--- | :--- | :--- |
| **`JobWaitNode`** | `40 B` / `8 B` | Stack intrusive node | Waiter stack record |
| **`JobCounter`** | `16 B` / `8 B` | `64-bit` state + head | Reference counting |
| **`CacheAlignedJobCounter`** | `64 B` / `64 B` | 64B padded counter | Contended `parallelFor` |
| **`JobFence`** | `8 B` / `8 B` | Tagged `UIntPtr` head | Phase barrier |

### Architectural Invariants

1. **Zero Heap Allocations on `wait()`, `add()`, `decrement()`, and `signal()`:** All wait-list
   nodes must reside on the waiting fiber's or OS thread's call stack.
2. **Single-Instruction Uncontended Decrement:** When `waiterCount == 0` and `kWaitListLockBit == 0`
   in `m_state`, `JobCounter::decrement()` must execute a single atomic `fetchSub` without taking
   locks or reading `m_waitListHead`.
3. **Mandatory Post-Switch Stack Release (`m_isStackActive`):** No CPU core may enter a child
   `gp::thread::Fiber` stack until the outgoing CPU core has completed `m_context.switchTo()` and
   released `m_isStackActive` with `MemoryOrder::Release`.
4. **Dual-Mode Execution Safety:** `JobCounter::wait()` and `JobFence::wait()` must operate safely
   both inside a cooperative child `Fiber` (yielding via the active `JobFiberParker` or
   `returnFiber`) and on a raw OS thread or `ThreadAnchor` (spinning via `Thread::spinWait()` until
   `JobWaitNodeState::Signaled`).
5. **`GP_FORCENOINLINE` Thread-Local Isolation ([ADR-0049](./ADR-0049.md)):** All `thread_local`
   accessors (`tl_activeParker`, `tl_outgoingFiber`) must be marked `GP_FORCENOINLINE` with compiler
   barriers to prevent TLS base-address hoisting across cross-core fiber migrations.

## Alternatives Considered

### Option A: Bare 32-Bit Counter with Global Fixed `WaitingFibers` Table Scan (Naughty Dog)

Maintain a bare 4-byte `Atomic<UInt32>` counter and scan a global 160-entry `WaitingFibers` array on
worker threads to discover completed counters.

**Why rejected:** Scanning a shared global table across 16–32 hardware threads causes severe MESI
cache-line bouncing ([ADR-0025](./ADR-0025.md)), couples `JobCounter` to a monolithic global
scheduler, and adds polling latency before a ready fiber is woken.

### Option B: Heap-Allocated Reference-Counted Task Graph Events (Unreal Engine `FGraphEvent`)

Allocate a reference-counted `FGraphEvent` object per dependency barrier that dispatches
continuation tasks when its prerequisite count reaches zero.

**Why rejected:** Requires dynamic memory/pool allocation per synchronization point and forces
engineers to split sequential algorithms into continuation callbacks, negating the procedural
clarity of stackful fibers ([ADR-0049](./ADR-0049.md)).

### Option C: Inline Work-Helping on the Current Call Stack Without Switching Fibers (`enkiTS`)

When waiting on a counter, pop and execute unrelated jobs from the work-stealing queue directly on
top of the waiting function's call stack.

**Why rejected:** Causes unbounded recursive stack growth on `64 KiB` fiber stacks, violates lexical
`ScopedFiberScratchMark` unwinding ([ADR-0048](./ADR-0048.md)), and introduces severe tail-latency
priority inversion when a fast parent job becomes trapped on the stack beneath a long unrelated job.

## Consequences

### Positive

- **Eliminates heap allocations and fixed waiter limits.** Stack-allocated `JobWaitNode` instances
  allow unlimited fibers and OS threads to wait on any `JobCounter` or `JobFence` with zero dynamic
  memory overhead.
- **Preserves 1-instruction `LOCK XADD` speed on uncontended decrements.** Packing `count`,
  `waiterCount`, and `kWaitListLockBit` into one 64-bit word ensures leaf jobs pay zero wait-list
  overhead when no fiber is parked.
- **Mathematically prevents Lost Wakeups and Dual-Core Stack Clobbering.** The 64-bit bit-packed
  wait-list lock combined with `Fiber::m_isStackActive` closes both SMP race windows across all CPU
  architectures.
- **Supports partial-threshold barriers (`wait(targetCount)`).** Callers can wait until a counter
  drops to any `targetCount` (not just `0`), enabling pipelined streaming and ring-buffer
  throttling.

### Negative

- **16-byte `JobCounter` footprint.** Embedding the 8-byte `m_waitListHead` pointer alongside the
  8-byte packed `m_state` increases `sizeof(JobCounter)` from 4 bytes to 16 bytes (and 8 bytes for
  `JobFence`).
- **Brief spin-wait during concurrent wait-list mutations.** Contention on the 1-bit TTAS latch
  (`kWaitListLockBit`) or `m_isStackActive` handoff spins for ~10–25 nanoseconds while a sibling
  core links a pointer or finishes a 20-instruction register swap.
