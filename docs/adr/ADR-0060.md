# ADR-0060: Layer 0 OS `FileHandle`, Positional I/O, Atomic Writes, and Directory Iteration

> Establishes `gp::platform::FileSystem` and `gp::platform::FileHandle` in `gp::core` as the
> Layer 0 OS file and directory I/O subsystem. It pairs non-polymorphic RAII file descriptors with
> lock-free positional I/O (`pread`/`pwrite` and Win32 `OVERLAPPED`), atomic write-and-rename
> transactions (`writeAtomic`), and stack-buffered directory traversal (`iterateDirectory`) below
> Layer 1 `gp::vfs::VirtualFileSystem` ([ADR-0044](./ADR-0044.md)).

![Accepted][badge-accepted]

## Context

`gp::platform::Paths` ([ADR-0043](./ADR-0043.md)) resolves standard OS directories and normalizes
paths in `gp::PathBuffer` (`gp::FixedString<1024>`) without heap allocations. To support early-boot
subsystems (crash dump writers, log file sinks, dynamic library loaders, config parsers) and Layer 1
`gp::vfs::VirtualFileSystem` ([ADR-0044](./ADR-0044.md)), the engine also needs OS file and
directory I/O primitives (`open`, `read`, `write`, `readAt`, `writeAt`, `exists`, `getStats`,
`createDirectory`, `createDirectoryTree`, `removeFile`, `removeDirectoryTree`, `move`, `copyFile`,
`iterateDirectory`, and bulk or atomic file helpers).

Raw OS file and directory APIs introduce five engineering problems in a game engine:

1. **Multi-Fiber File Pointer Races (`Seek` + `Read` vs. Positional `readAt`):**
   Object-oriented file wrappers like Unreal Engine's `IFileHandle::Seek()` and `Read()` mutate a
   single stateful cursor inside the OS kernel file description. When multiple worker fibers in
   `gp::thread::JobSystem` ([ADR-0052](./ADR-0052.md)) read different chunks from the same open
   archive or binary file, a shared cursor forces every fiber to take a mutex per handle. OS kernels
   already provide stateless positional I/O: POSIX `pread`/`pwrite` and Win32 `ReadFile`/`WriteFile`
   with an explicit `OVERLAPPED` 64-bit offset. Positional I/O lets worker fibers read disjoint
   byte ranges from one `FileHandle` concurrently without locks.
2. **Virtual Dispatch and Heap Allocation at Layer 0:**
   Wrapping every OS descriptor in a heap-allocated `IFileHandle*` behind a chain of `IPlatformFile`
   decorators triggers `malloc`/`free` calls on every open and extra vtable indirections on every
   syscall. Early-boot crash handlers and pre-main logger sinks cannot safely call heap-allocating
   file APIs before custom memory allocators ([ADR-0042](./ADR-0042.md)) initialize.
3. **Heap-Allocating Directory Enumeration (`std::filesystem::directory_iterator`):**
   Standard library directory iterators and naive wrappers allocate `std::vector<std::string>`
   lists on the heap during traversal. Scanning a shader cache or asset directory with 20,000 files
   creates tens of thousands of transient string allocations and fragments the heap.
4. **Save-Game and Config Corruption on Crash (`writeAtomic`):**
   Opening an existing save or config file with `CreateAlways` (`O_TRUNC`) destroys the previous
   contents before the new payload reaches disk. If the process crashes, loses power, or hits a
   disk-full error mid-write, the user loses the file to a zero-byte or half-written state.
5. **Cross-Platform UTF-16 vs. UTF-8 and Epoch Differences:**
   * **Windows (Win32):** Expects UTF-16 `wchar_t` paths in `CreateFileW`, `GetFileAttributesExW`,
     `CreateDirectoryW`, `FindFirstFileExW` (`FindExInfoBasic` + `FIND_FIRST_EX_LARGE_FETCH`),
     `MoveFileExW` (`MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH`), and `CopyFileW`.
     Timestamps arrive as 64-bit `FILETIME` ticks (100-ns intervals since January 1, 1601 UTC).
   * **POSIX (Linux & macOS):** Consumes UTF-8 `char` paths in `open`, `stat`/`fstat`/`lstat`,
     `mkdir`, `opendir`/`readdir`, `unlink`, `rmdir`, `rename`, and `fsync`. Timestamps arrive as
     `struct timespec` seconds and nanoseconds since the Unix Epoch (January 1, 1970 UTC).

## Decision

We introduce `gp::platform::FileSystem` and `gp::platform::FileHandle` in `gp::core` as the Layer 0
OS filesystem abstraction, paired with Layer 1 `gp::vfs::VirtualFileSystem`
([ADR-0044](./ADR-0044.md)) in `gp::core/vfs/`.

### 2. Layer 0 Value-Type `FileHandle` & Lock-Free Positional I/O

`gp::platform::FileHandle` is an 8-byte, move-only, non-polymorphic RAII wrapper around
`NativeFileDescriptor` (`void*` Win32 `HANDLE` initialized to `INVALID_HANDLE_VALUE` on Windows;
`Int32` file descriptor initialized to `-1` on POSIX):

```cpp
namespace gp::platform
{

class GP_CORE_API FileHandle final
{
public:
    [[nodiscard]] FileHandle() noexcept = default;
    [[nodiscard]] explicit FileHandle(const NativeFileDescriptor descriptor) noexcept;
    ~FileHandle() noexcept;

    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;
    [[nodiscard]] FileHandle(FileHandle&& other) noexcept;
    FileHandle& operator=(FileHandle&& other) noexcept;

    [[nodiscard]] bool isValid() const noexcept;
    [[nodiscard]] explicit operator bool() const noexcept;
    [[nodiscard]] NativeFileDescriptor nativeDescriptor() const noexcept;
    [[nodiscard]] NativeFileDescriptor release() noexcept;

    gp::Expected<bool, FileError> close() noexcept;
    [[nodiscard]] gp::Expected<gp::USize, FileError>
        read(void* const outBuffer, const gp::USize bytesToRead) noexcept;
    [[nodiscard]] gp::Expected<gp::USize, FileError>
        write(const void* const buffer, const gp::USize bytesToWrite) noexcept;

    [[nodiscard]] gp::Expected<gp::USize, FileError> readAt(
        const gp::UInt64 offset, void* const outBuffer, const gp::USize bytesToRead
    ) const noexcept;
    [[nodiscard]] gp::Expected<gp::USize, FileError> writeAt(
        const gp::UInt64 offset, const void* const buffer, const gp::USize bytesToWrite
    ) noexcept;

    [[nodiscard]] gp::Expected<gp::UInt64, FileError>
        seek(const gp::Int64 offset, const FileSeekOrigin origin = FileSeekOrigin::Begin) noexcept;
    [[nodiscard]] gp::Expected<gp::UInt64, FileError> tell() const noexcept;
    [[nodiscard]] gp::Expected<gp::UInt64, FileError> size() const noexcept;
    gp::Expected<bool, FileError> flush() noexcept;
    gp::Expected<bool, FileError> truncate(const gp::UInt64 newSize) noexcept;

private:
    NativeFileDescriptor m_descriptor{ kInvalidNativeFileDescriptor };
};

} // namespace gp::platform
```

### 3. Architectural Invariants

1. **Zero Heap Allocations Across Layer 0 Syscalls:**
   * Path conversions at the OS boundary (`UTF-8` `gp::StringView` to null-terminated `PathBuffer`
     on POSIX, or stack `wchar_t[kMaxPathLength + 16]` via `MultiByteToWideChar` on Windows) happen
     on the calling thread's stack.
   * `FileSystem::open()`, `exists()`, `isFile()`, `isDirectory()`, `fileSize()`, `getStats()`,
     `setReadOnly()`, `createDirectory()`, `createDirectoryTree()`, `removeFile()`,
     `removeDirectory()`, `removeDirectoryTree()`, `move()`, `copyFile()`, and `iterateDirectory()`
     allocate 0 bytes on the heap.
2. **Thread-Safe Positional `readAt` / `writeAt` Contract:**
   * On POSIX, `FileHandle::readAt` and `FileHandle::writeAt` call `::pread` and `::pwrite`
     (retrying automatically on `EINTR` or partial transfers), which execute atomically with respect
     to the file offset.
   * On Windows, `FileHandle::readAt` and `FileHandle::writeAt` populate a stack `OVERLAPPED`
     struct (`Offset` and `OffsetHigh`) and pass it to `::ReadFile` / `::WriteFile`, so concurrent
     worker fibers can read from one handle without locking.
3. **Canonical Unix Epoch Nanoseconds in `FileStats` ([ADR-0030](./ADR-0030.md)):**
   * `FileStats` holds `size` (`gp::UInt64`), `creationTime`, `lastWriteTime`, `lastAccessTime`
     (`gp::time::Timestamp`), and `attributes` (`FileAttributeFlags`: `None`, `RegularFile`,
     `Directory`, `ReadOnly`, `Hidden`, `SymbolicLink`).
   * All platforms convert file timestamps to 64-bit unsigned nanoseconds since the Unix Epoch
     (`1970-01-01T00:00:00Z`). Windows converts `FILETIME` via
     `(ticks100ns - 116444736000000000ULL) * 100ULL`; POSIX converts `struct timespec` via
     `tv_sec * 1'000'000'000ULL + tv_nsec`.
4. **Crash-Safe Atomic File Replacement (`writeAtomic`):**
   * `FileSystem::writeAtomic(path, data, size)` never truncates the target file in place. It
     writes the payload to a sibling staging file (`<path>.tmp.<seq>` using a process-wide atomic
     sequence counter and `FileOpenMode::CreateNew`), calls `FileHandle::flush()`
     (`FlushFileBuffers` / `fsync`), closes the handle, and executes an atomic OS rename
     (`MoveFileExW` with `MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH` on Windows; `::rename`
     on POSIX). If any step fails, the staging file is unlinked and the original file stays intact.
5. **Stack Directory Enumeration (`iterateDirectory` & `iterateDirectoryRecursive`):**
   * Directory iteration accepts either a stateless C callback
     `(const DirectoryEntry& entry, void* userData) -> DirectoryVisitControl` or any C++ callable
     `(const DirectoryEntry& entry) -> DirectoryVisitControl` (`Continue`, `SkipSubdirectory`,
     `Stop`).
   * `DirectoryEntry` exposes non-owning `gp::StringView` slices (`path`, `name`) pointing into the
     iterator frame's stack `PathBuffer`, along with `FileStats` populated directly from
     `WIN32_FIND_DATAW` on Windows so no extra `GetFileAttributesExW` syscall is needed per entry.
   * The OS iterator filters out `.` and `..` pseudo-entries automatically.
6. **Container-Templated Bulk Read Helpers (`readAllBytes`, `readAllText`):**
   * `FileSystem::readAllBytes(path, outBuffer)` accepts any 1-byte element container
     (`gp::Vector<gp::Byte, Allocator>`, `gp::String`), and `readAllText(path, outString)` accepts
     any `gp::container::BasicString<char, Allocator>` satisfying `gp::concepts::IsAllocator`
     ([ADR-0042](./ADR-0042.md)). Callers can load files directly into a `LinearAllocator` or
     `FiberScratchAllocator` ([ADR-0048](./ADR-0048.md)) with a single `resizeUninitialized` call.

## Alternatives Considered

### Option A: Unreal Engine Polymorphic `IPlatformFile` / `IFileHandle*` Decorator Stack at Layer 0

Expose all OS file operations through a virtual `IPlatformFile` singleton returning heap-allocated
`IFileHandle*` pointers.

**Why rejected:** Forces a heap allocation on every `openRead`/`openWrite`, adds chained virtual
call overhead to every file query, and blurs the boundary between Layer 0 OS syscalls and Layer 1
VFS URI mount routing ([ADR-0044](./ADR-0044.md)).

### Option B: C Standard Library `FILE*` (`fopen` / `fread` / `fwrite` / `fseek`)

Implement Layer 0 file handles on top of `<cstdio>` `FILE*` streams.

**Why rejected:**
1. `<cstdio>` has no portable positional `pread`/`pwrite` equivalent, making lock-free concurrent
   reads from a shared handle across job-system fibers impossible.
2. `FILE*` allocates an internal heap buffer (`BUFSIZ`, typically 4 to 8 KiB) on `fopen` and takes
   an internal CRT lock (`_lock_file`) on every `fread`/`fwrite`, double-buffering data the engine
   already reads into caller buffers.
3. Standard `fopen` on Windows does not accept UTF-8 paths without non-standard `_wfopen_s`
   extensions and lacks granular `FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE` control.

### Option C: C++17 `<filesystem>` and `<fstream>`

Use `std::filesystem` for directory operations and `std::ifstream`/`std::ofstream` for file I/O.

**Why rejected:** Forbidden by `gp-engine`'s zero-STL-allocation and `-fno-exceptions` rules. Both
`<filesystem>` and `<fstream>` rely on locales, virtual `std::streambuf` dispatch, hidden heap
allocations, and exception-throwing overloads or allocating `std::error_code` path conversions.

## Consequences

### Positive

- **Zero Heap Allocations Across All Layer 0 OS Primitives.** File opening, reading, writing,
  seeking, stat queries, directory creation, atomic file replacement, and directory iteration
  allocate 0 bytes on the heap.
- **Lock-Free Multi-Fiber Positional Streaming (`readAt`).** Multiple worker fibers in
  `gp::thread::JobSystem` can read concurrently from a single open `FileHandle` via `OVERLAPPED` /
  `pread` without mutex contention.
- **Zero-Syscall Metadata During Windows Directory Iteration.** Populating `DirectoryEntry::stats`
  directly from `WIN32_FIND_DATAW` during `FindFirstFileExW` / `FindNextFileW` avoids $N$ extra
  `GetFileAttributesExW` kernel transitions when scanning large directories.
- **Crash-Safe Save & Config Integrity (`writeAtomic`).** User saves and engine configuration
  files are protected against partial-write corruption via flushed temporary staging files and
  atomic OS rename swaps.
- **Clean Foundation for Layer 1 `gp::vfs::VirtualFileSystem` ([ADR-0044](./ADR-0044.md)).**
  `gp::vfs::PhysicalMountBackend` wraps `gp::platform::FileSystem` directly while adding logical
  URI routing, priority overlays, and sandbox escape protection.

### Negative

- **Platform-Specific Implementation Maintenance.** Maintaining direct Win32
  (`WindowsFileSystem.cpp`) and POSIX (`UnixFileSystem.cpp`) syscall backends requires mapping
  `GetLastError()` and `errno` into `gp::platform::FileError`.
- **Recursion Depth Bound on `iterateDirectoryRecursive`.** Stack-allocated recursive directory
  traversal uses ~1.1 KiB of stack space per nesting level (`PathBuffer` per depth), so it is capped
  at `kMaxDirectoryRecursionDepth = 32` (~35 KiB max stack) to remain safe inside 64 KiB standard
  fibers ([ADR-0049](./ADR-0049.md)).
