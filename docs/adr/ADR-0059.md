# ADR-0059: Dual-Mode Non-Nullable SharedRef, SharedPtr, WeakPtr, and In-Place Control Blocks

> Introduces `gp::SharedRef<T, Mode>`, `gp::SharedPtr<T, Mode>`, `gp::WeakPtr<T, Mode>`,
> `gp::SharedFromThis<T, Mode>`, `gp::makeShared`, `gp::allocateShared`, and `gp::makeShareable`
> in `gp::core`, pairing a 16-byte dual-counter reference controller wired to
> `gp::RefCountThreadSafety` with single-allocation in-place construction and engine-allocator
> integration.

![Accepted][badge-accepted]

## Context

[ADR-0045](./ADR-0045.md) introduced `gp::RefCountedPtr<T, Policy>` and
`gp::IntrusiveRefCounted<Derived, ThreadSafety>` for 8-byte intrusive reference counting in the
Rendering Hardware Interface (`gp::rhi`). While intrusive counting fits GPU resources and COM
interfaces, four categories of engine code need non-intrusive shared ownership with an external
control block:

- **Non-owning weak observers (`gp::WeakPtr<T>`):** UI widgets, event listeners, editor selection
  sets, and scene-graph parent links must observe shared objects without extending their lifetime
  or leaving dangling raw pointers when the last strong owner releases the object.
  `IntrusiveRefCounted` deliberately omits weak reference counts to keep RHI resources at 4 bytes
  of counter state and avoid zombie memory blocks of `sizeof(T)` ([ADR-0045](./ADR-0045.md)).
- **Subobject aliasing (`SharedPtr` aliasing constructor):** Asset containers and component bags
  often share ownership of a root allocation while handing subsystem callers a typed `SharedPtr`
  or `SharedRef` pointing directly to an embedded member field or base subobject.
- **Unmodifiable or polymorphic value types:** Third-party structures, POD configuration tables,
  and non-intrusive classes cannot inherit from `IntrusiveRefCounted<T>`.
- **Non-nullable shared ownership contracts (`gp::SharedRef<T>`):** Nullable `SharedPtr<T>`
  parameters force defensive `if (ptr != nullptr)` branches throughout call trees even when an API
  contract guarantees a live heap object.

Standard `<memory>` (`std::shared_ptr`, `std::weak_ptr`, `std::enable_shared_from_this`) is
forbidden by [ADR-0021](./ADR-0021.md) because it allocates through the standard library heap,
always pays atomic read-modify-write overhead even on thread-confined graphs, lacks a non-nullable
`SharedRef` counterpart, and cannot bind directly to `gp::concepts::IsAllocator` arenas and pools
([ADR-0042](./ADR-0042.md)).

## Decision

We implement the non-intrusive shared pointer suite under
`source/runtime/core/public/memory/pointers/`, wired to `gp::RefCountThreadSafety`
(`ThreadSafe` by default, or `SingleThreaded` for thread-confined graphs).

### Physical directory layout

```text
source/runtime/core/

        SharedPtr.tests.cpp             <-- Unit and multithreaded stress tests for SharedRef,
                                            SharedPtr, WeakPtr, SharedFromThis, and allocators
```

### Memory layout and control block architecture

```text
1. Smart Pointer Handle Layout: SharedRef<T, Mode> / SharedPtr<T, Mode> / WeakPtr<T, Mode> (16B)
+----------------------------------------+-----------------------------------------------------+
| m_object : T* (8 Bytes)                | m_controller : ReferenceControllerBase<Mode>* (8B)  |
| Direct pointer to T (or aliased field) | Pointer to strong/weak reference control block      |
+----------------------------------------+-----------------------------------------------------+

2. Control Block Header: ReferenceControllerBase<Mode> (16 Bytes on x64)
+----------------------------------------+--------------------------+--------------------------+
| vptr (8 Bytes)                         | m_sharedRefs : UInt32(4B)| m_weakRefs : UInt32 (4B) |
| destroyObject() + destroyController()  | Initial = 1              | Initial = 1 (+1 for live |
| cold-path teardown dispatch            | (Atomic or plain UInt32) | strong references)       |
+----------------------------------------+--------------------------+--------------------------+

3. In-Place Control Block: IntrusiveReferenceController<T, Mode, Allocator> (makeShared)
+-------------------------------------------------------+--------------------------------------+
| ReferenceControllerBase<Mode> (16 Bytes)              | alignas(T) Byte m_storage[sizeof(T)] |
| + GP_NO_UNIQUE_ADDRESS Allocator m_allocator          | In-place constructed T payload       |
+-------------------------------------------------------+--------------------------------------+

4. External Pointer Control Block: DefaultReferenceController<T, Deleter, Mode, Allocator>
+-------------------------------------------------------+--------------------------------------+
| ReferenceControllerBase<Mode> (16 Bytes)              | m_ptr : T* (8 Bytes)                 |
| + GP_NO_UNIQUE_ADDRESS Deleter + Allocator            | Managed external heap pointer        |
+-------------------------------------------------------+--------------------------------------+
```

### Reference counting and `m_weakRefs` "+1" invariant

`ReferenceControllerBase<Mode>` maintains two 32-bit unsigned counters (`m_sharedRefs` and
`m_weakRefs`), both initialized to `1`:

- The initial `1` in `m_weakRefs` represents the collective existence of all live `m_sharedRefs`
  (matching Unreal Engine's `TReferenceControllerBase` and Boost's `sp_counted_base`).
- Copying or destroying a `SharedPtr` or `SharedRef` only modifies `m_sharedRefs`; `m_weakRefs` is
  untouched while `m_sharedRefs > 0`.
- When `releaseSharedRef()` decrements `m_sharedRefs` from `1` to `0`, it issues an `Acquire`
  fence (in `ThreadSafe` mode), calls `destroyObject()` to run `~T()` (or the custom deleter), and
  then calls `releaseWeakRef()`.
- If no `WeakPtr` handles exist, `releaseWeakRef()` immediately drops `m_weakRefs` from `1` to `0`
  and invokes `destroyController()` to free the control block. If `WeakPtr` handles remain alive,
  the control block stays allocated until the last `WeakPtr` releases its weak count.
- `WeakPtr::pin()` invokes `tryAddSharedRef()`, which executes a compare-and-swap loop in
  `ThreadSafe` mode (or a branch check in `SingleThreaded` mode) that increments `m_sharedRefs`
  only if `m_sharedRefs > 0`.

### Smart pointer family comparison

| Type | Size | Nullability | Control Block | Typical Usage |
| :--- | :--- | :--- | :--- | :--- |
| **`UniquePtr<T, D>`** | `8 B` | Nullable | None (`0 B`) | Exclusive RAII, PImpl |
| **`RefCountedPtr<T>`** | `8 B` | Nullable | Intrusive in `T` | RHI resources, D3D12 COM |
| **`SharedRef<T, Mode>`** | `16 B` | **Non-Null** | External / In-Place | Live shared services |
| **`SharedPtr<T, Mode>`** | `16 B` | Nullable | External / In-Place | Optional shared nodes |
| **`WeakPtr<T, Mode>`** | `16 B` | Nullable | Shared with owner | Caches, weak observers |

### Architectural invariants

1. `sizeof(SharedRef<T, Mode>) == 16`, `sizeof(SharedPtr<T, Mode>) == 16`, and
   `sizeof(WeakPtr<T, Mode>) == 16` on 64-bit targets, and all three types specialize
   `gp::concepts::IsRelocatableTrait` as `true` so `gp::Vector` relocates them with `memmove`.
2. `RefCountThreadSafety::ThreadSafe` uses `gp::thread::Atomic<gp::UInt32>` with
   `MemoryOrder::Relaxed` on increments, `MemoryOrder::Release` + conditional
   `gp::thread::atomicThreadFence(MemoryOrder::Acquire)` on final decrements, and `Acquire` CAS on
   `tryAddSharedRef()`. `RefCountThreadSafety::SingleThreaded` uses plain `gp::UInt32` arithmetic
   with zero atomic instructions.
3. `SharedRef<T, Mode>` has no default constructor, no `nullptr` constructor, and no `reset()`.
   Moving from a `SharedRef<T, Mode>` into a `SharedPtr<T, Mode>` is permitted (consuming the
   source), whereas `SharedRef` copy and move operations between `SharedRef` instances preserve the
   non-null invariant by retaining a reference or swapping handles.
4. `gp::makeShared<T, Mode>(args...)` and `gp::allocateShared<T, Mode>(allocator, args...)`
   allocate `IntrusiveReferenceController<T, Mode, Allocator>` in one contiguous block from
   `gp::memory::HeapAllocator` (or any `gp::concepts::IsAllocator`) and return
   `SharedRef<T, Mode>`, which converts implicitly to `SharedPtr<T, Mode>`.
5. `gp::makeShareable(ptr, deleter, allocator)` wraps a raw pointer and optional custom deleter so
   callers can initialize either a `SharedPtr<T, Mode>` or `SharedRef<T, Mode>` with explicit
   ownership transfer.
6. Whenever a `SharedRef` or `SharedPtr` constructs a new control block for a type `T` that
   publicly and unambiguously derives from `SharedFromThis<Base, Mode>`, it automatically updates
   `m_weakThis` on the `SharedFromThis` base so `asShared()` and `asWeak()` work immediately after
   construction.

## Alternatives Considered

### Option A: Function-pointer control block header without virtual dispatch

Replace the `ReferenceControllerBase` virtual table pointer (`8 bytes`) with two function pointers
(`void (*m_destroyObject)(Controller*)` and `void (*m_destroyController)(Controller*)`, `16 bytes`
total).

**Why rejected:** Storing two function pointers grows every control block header from 16 bytes to
24 bytes on 64-bit platforms, pushing small `makeShared` allocations into the next `mimalloc` size
class. Because `destroyObject()` and `destroyController()` only execute once when the strong or
weak reference count reaches zero, a single `vptr` saves 8 bytes per allocation with zero cost on
copy, move, `pin()`, or dereference.

### Option B: Global handle and generation slot table for weak references

Store strong and weak counts in a global slot array indexed by a 32-bit slot index and 32-bit
generation counter rather than per-allocation control blocks.

**Why rejected:** A centralized slot table introduces cross-thread contention on a global pool,
prevents self-contained arena/pool lifetimes via `allocateShared`, and breaks standard C++
subobject aliasing constructors. Generation-indexed handles belong in the entity/object subsystem
rather than general-purpose smart pointers in `gp::memory`.

### Option C: Omit `SharedRef<T>` and provide only nullable `SharedPtr<T>`

Follow the C++ standard library by providing only nullable `SharedPtr<T>` and `WeakPtr<T>`.

**Why rejected:** In large engine codebases, nullable shared pointers encourage defensive null
checks at every call boundary. Providing `gp::SharedRef<T, Mode>` alongside `gp::SharedPtr<T, Mode>`
(following Unreal Engine's `TSharedRef` / `TSharedPtr` split) lets APIs express non-null shared
ownership in the type signature while interoperating with `SharedPtr` and `WeakPtr`.

## Consequences

### Positive

- **Single-allocation cache locality.** `makeShared` and `allocateShared` place the 16-byte
  control block and `T` in one contiguous allocation, avoiding a second heap call and keeping
  reference counts on the same cache line as the object header.
- **Pay-for-what-you-use thread safety.** Wiring `SharedRef`, `SharedPtr`, `WeakPtr`, and
  `SharedFromThis` to `RefCountThreadSafety` lets single-threaded subsystems avoid atomic read-
  modify-write instructions while keeping `ThreadSafe` as the safe default.
- **Type-enforced non-nullability.** `SharedRef<T, Mode>` guarantees a valid object without runtime
  null checks, and `makeShared` returns `SharedRef<T, Mode>` which converts implicitly to
  `SharedPtr<T, Mode>`.
- **Zero-overhead stateless deleters and allocators.** `DefaultReferenceController` and
  `IntrusiveReferenceController` apply `GP_NO_UNIQUE_ADDRESS` to both the deleter and engine
  allocator, keeping `DefaultDelete<T>` and `HeapAllocator` at zero storage overhead.

### Negative

- **16-byte pointer size.** `SharedRef`, `SharedPtr`, and `WeakPtr` store two 8-byte pointers
  (`16 bytes`), which is twice the size of `RefCountedPtr<T>` (`8 bytes`). Performance-critical RHI
  resources and draw packets must continue to use `RefCountedPtr<T>` ([ADR-0045](./ADR-0045.md)).
- **Control-block memory retention under lingering `WeakPtr` handles.** When an object is created
  via `makeShared` or `allocateShared`, `~T()` runs as soon as `m_sharedRefs` drops to `0`, but the
  combined memory block (`sizeof(Controller) + sizeof(T)`) remains allocated until `m_weakRefs`
  also drops to `0`.
