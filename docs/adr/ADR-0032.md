# ADR-0032: Hierarchical Simulation Clock Domains with Multiplicative Time Dilation

> A single global `DeltaTime` cannot simultaneously support pausing the game world while keeping
> UI animations smooth, triggering a 0.05x hit-stop on characters while keeping camera shake at
> 1.0x, or running network prediction at an independent rate. Inspired by Frostbite and Decima, the
> engine separates hardware timekeeping (`EngineClock`) from hierarchical domain clocks
> (`SimulationClock`). Any `SimulationClock` may attach to a parent clock; pause states propagate
> downward (`isEffectivelyPaused()`) and time dilation scales multiply (`getEffectiveTimeScale()`),
> with zero heap allocations.

![Proposed][badge-proposed]

## Context

Real-time interactive simulations execute multiple concurrent subsystems on every frame:
physics solvers, skeletal animation blend trees, particle systems, user interfaces, audio
mixers, and network prediction buffers. Each subsystem operates under different timing
requirements and temporal constraints.

### The Monolithic Global Delta Time Failure Mode

Historically, game engines tracked frame duration through a single global floating-point
variable (`float g_DeltaTime`). Every engine subsystem consumed this value during its update
tick. This design creates three severe architectural failure modes:

1. **Global Pause Contamination:** When the gameplay world pauses, setting `dt = 0` halts all
   subsystems indiscriminately. User interface menu animations, loading spinners, pause-screen
   blur shaders, and developer free-look cameras freeze. Restoring UI responsiveness under a
   monolithic model requires adding branch checks (`if (!isPaused)`) across thousands of leaf
   systems, or passing separate unscaled deltas down deep call stacks.
2. **Ad-Hoc Scale Fragmentation:** Implementing localized slow-motion (such as "bullet time"
   or combat hit-stop) requires either dilating the entire engine (slowing the UI, HUD, and
   camera navigation) or scattering ad-hoc multipliers across game logic:
   `dt * characterScale * globalSlowMo * weatherScale`. Leaf systems frequently forget one
   of the multipliers, resulting in timing desynchronization between character meshes, attached
   particle emitters, and sound effects.
3. **Mismatched Integration Rates:** Network rollback prediction and fixed-timestep physics
   solvers require discrete, non-dilated intervals to remain deterministic. Monolithic delta
   times tie all subsystems to the display refresh rate, introducing simulation divergence
   whenever the render frame rate fluctuates.

### AAA Architectural Precedent: Frostbite and Decima

Modern AAA production engines decouple physical hardware timekeeping from simulation logic by
organizing clocks into hierarchical domain trees:

- **EA Frostbite Engine:** Frostbite isolates hardware time from logical clock domains. The
  engine defines dedicated clocks for real-time profiling, user interface rendering, main
  simulation, and cutscenes. Child clocks inherit dilation factors and pause states from their
  parents, allowing cutscene tracks or debug cameras to advance independently while the main
  gameplay world remains paused.
- **Guerrilla Games Decima Engine:** Decima employs a hierarchical scheduler where simulation
  nodes derive their time scale from parent contexts. Hit-stop effects apply localized time
  dilation (such as 0.05x for 80 milliseconds) to specific combatant hierarchies. The camera,
  ambient foliage, and UI retain their normal time scales without requiring bespoke branching
  in component update loops.

## Decision

We introduce `gp::time::SimulationClock` and `gp::time::EngineClock` to establish a
zero-allocation hierarchical clock domain architecture. Physical hardware timekeeping is
separated from domain clocks that inherit dilation and pause state from parent nodes.

### Built-in Clock Domains

The engine standardizes six canonical clock domains in `gp::time::ClockDomain`:

- `RealTime`: Unscaled, unpausable real wall-clock time used for profiling, network timeouts,
  and operating system window transitions.
- `UI`: Unpausable interface clock used for menus, HUD animations, and developer debug cameras
  while the gameplay simulation is paused.
- `Gameplay`: Primary gameplay simulation clock that pauses during game pause and scales
  during global slow-motion effects.
- `Physics`: Deterministic fixed-timestep accumulator clock attached as a child of `Gameplay`.
- `Animation`: Skeletal animation and VFX clock attached as a child of `Gameplay`, supporting
  localized hit-stop and character time dilation.
- `Audio`: Audio parameter modulation clock attached as a child of `Gameplay`.

### Hierarchical Domain Topology

The six built-in domains form a static hierarchy owned directly by `EngineClock`:

### Zero Heap Allocation Pointer Hierarchy

Each `SimulationClock` maintains a non-owning parent pointer
(`const SimulationClock* m_parent`). Attaching or detaching clocks is a pointer assignment
(`setParent()`), avoiding dynamic allocations and tree balancing overhead:

```cpp
namespace gp::time {

class SimulationClock final
{
private:
    const SimulationClock* m_parent{ nullptr };
    Duration m_totalElapsed{};
    Duration m_lastDelta{};
    Duration m_accumulator{};
    Duration m_fixedStepDuration{ FrameRate(60u, 1u).toFrameDuration() };
    gp::Float64 m_localTimeScale{ 1.0 };
    gp::UInt64 m_tickCount{ 0ULL };
    gp::UInt32 m_maxSubSteps{ 8u };
    bool m_isPaused{ false };
    bool m_singleStepRequested{ false };

public:
    [[nodiscard]] constexpr gp::Float64 getEffectiveTimeScale() const noexcept
    {
        if (isEffectivelyPaused())
        {
            return 0.0;
        }

        gp::Float64 scale = m_localTimeScale;
        const SimulationClock* curr = m_parent;
        while (curr != nullptr)
        {
            scale *= curr->m_localTimeScale;
            curr = curr->m_parent;
        }
        return scale;
    }

    [[nodiscard]] constexpr bool isEffectivelyPaused() const noexcept
    {
        if (m_singleStepRequested)
        {
            return false;
        }

        const SimulationClock* curr = this;
        while (curr != nullptr)
        {
            if (curr->m_isPaused && !curr->m_singleStepRequested)
            {
                return true;
            }
            curr = curr->m_parent;
        }
        return false;
    }
};

} // namespace gp::time
```

### Multiplicative Downward Propagation

State propagates downward through upward pointer traversal:

- **Effective Pause Propagation:** `isEffectivelyPaused()` inspects the current clock and walks
  up the `m_parent` chain. If any ancestor is paused, the query returns `true`. The clock halts
  time progression without requiring child registration lists or recursive dirty-flag updates.
- **Multiplicative Scale Inheritance:** `getEffectiveTimeScale()` computes the product of local
  scale factors along the ancestor chain. If `Gameplay` runs at 0.5x and a child `Animation`
  clock runs at 0.5x, the effective animation time scale evaluates to 0.25x. If any ancestor is
  paused, the effective scale evaluates to 0.0.

### Deterministic Single-Step Debugging

Debugging complex interactions in physics, combat, and skeletal animations requires stepping
paused simulations frame by frame. When a clock domain is paused, invoking `requestSingleStep()`
arms the clock for a single discrete step. On the next call to `advance()`, the clock advances
by exactly `m_fixedStepDuration`, increments its tick count, clears `m_singleStepRequested`,
and returns to its paused state on the following frame.

### Architectural Invariants

1. **Zero Heap Allocation Hierarchy:** Clock connections use non-owning parent pointers
   (`const SimulationClock* m_parent`). Initializing, attaching, detaching, and traversing
   clock hierarchies requires zero dynamic memory allocations.
2. **Multiplicative Scale Inheritance:** The effective time scale is the product of the local
   multiplier and all ancestor multipliers. A pause state at any node sets the effective time
   scale to zero, halting delta accumulation across all descendant domains.
3. **Strict Isolation of Unpausable Domains:** Root clocks (`RealTime` and `UI`) must never
   have `Gameplay` or simulation clocks as ancestors. UI rendering, debug cameras, and profiling
   queries remain active regardless of gameplay pause or slow-motion states.
4. **Frame-Isolated Discrete Single Stepping:** Invoking `requestSingleStep()` unpauses a clock
   domain for exactly one discrete fixed step interval (`m_fixedStepDuration`), bypassing
   ancestor pause checks for that tick and returning to paused state on completion.

### Comparative Evaluation

| Dimension | Monolithic Global Float `dt` | Ad-Hoc Gameplay Scales | Hierarchical Domain Clocks (`SimulationClock`) |
| :--- | :--- | :--- | :--- |
| **UI Pause Isolation** | Impossible without manual branch checks in every leaf system | Fragile; UI components must remember to read unscaled delta | Guaranteed; `UI` clock is an independent root domain |
| **Localized Slow-Motion** | Impossible; slow-motion alters whole engine speed | Error-prone; systems multiply local scalars manually | Clean; adjust local scale on character/animation clock domain |
| **Hierarchy Inheritance** | None; flat global variable | Manual parameter passing down deep call stacks | Automatic multiplicative propagation up parent pointer chain |
| **Memory Allocation Overhead** | Zero allocations (single global float) | Zero allocations (scattered variables) | Zero allocations (inline array storage and raw pointers) |
| **Single-Step Debug Support** | Complex; requires global simulation state gating | Unsupported; ad-hoc multipliers ignore step requests | Native; `requestSingleStep()` steps one fixed frame and re-pauses |

## Alternatives Considered

### Option A: Single Monolithic Global Delta Time (`g_DeltaTime`)

Store a single global floating-point variable representing the elapsed frame duration and expose
it to all systems.

**Why rejected:** Prevents pausing gameplay while updating UI menus, background video, and
developer debug cameras. Prevents isolated slow-motion or hit-stop without slowing the entire
engine. Setting `dt = 0` freezes UI animations, video playback, and editor navigation.

### Option B: Ad-Hoc Multipliers in Component Update Loops (`Update(dt * myScale)`)

Pass a global delta time to engine systems and require individual components to multiply local
scalars (such as `dt * characterTimeScale * weatherScale`).

**Why rejected:** Manual scale passing is error-prone. Leaf systems must receive and multiply
every active scalar, causing frequent timing desynchronization between character meshes,
attached particle emitters, and sound effects. It provides no centralized mechanism for pause
propagation, requiring manual boolean checks at every callsite.

### Option C: Dynamic Heap-Allocated Clock Graph (`std::vector<SimulationClock*>`)

Represent clock domains as nodes in an arbitrary directed acyclic graph where parent nodes hold
dynamically allocated vectors of child pointers.

**Why rejected:** Allocating clock nodes and child arrays on the heap introduces memory
fragmentation and cache misses from pointer chasing across scattered heap allocations. It
violates the engine's zero-heap-allocation policy for core runtime systems and complicates
lifetime management without providing practical benefits over a shallow, parent-pointer tree.

## Consequences

### Positive

- **Decoupled interface and simulation lifecycles.** Menus, HUD animations, background video,
  and debug cameras continue running at full frame rate while gameplay is paused.
- **Composable localized time dilation.** Hit-stop on individual combatants and global
  slow-motion multiply naturally without polluting component update callsites.
- **Deterministic single-frame debugging.** Physics and gameplay engineers can step paused
  simulations forward by exactly one fixed tick to inspect state transitions.
- **Zero allocation overhead.** Clock nodes use raw parent pointers and flat array storage
  in `EngineClock`, requiring zero dynamic memory and keeping traversal within CPU cache.

### Negative

- **Upward traversal per tick.** Computing effective scale requires walking up the parent
  pointer chain on every clock tick, adding pointer dereferences (bounded to shallow depths
  of 2-3 levels in practice).
- **Manual clock assignment discipline.** Subsystems and entities must query and bind to the
  correct domain clock rather than reading a single global variable.
