# ADR-0054: Zero-Allocation Lock-Free Multi-Sink Logger and Hybrid `GP_LOG` Architecture

> Establishes `gp::log` in `gp::core` as a zero-heap-allocation, multi-sink logging subsystem
> combining `<charconv>` stack formatting, `consteval` format string verification, atomic
> `LogCategory` filtering, dual synchronous/lock-free MPMC ring execution, and a hybrid C++23
> function plus short-circuiting `GP_LOG` macro front-end.

![Accepted][badge-accepted]

## Context

Every layer of `gp-engine`, from early `.bss` boot utilities (`gp::CommandLine`,
`gp::platform::Paths`), memory allocators (`gp::memory::Malloc`), and `JobSystem` worker fibers to
high-level HAL, RHI, and gameplay subsystems, requires structured diagnostic telemetry across
multiple outputs (ANSI console, rolling log files, OS debuggers, Tracy profiler, and in-memory test
or editor ring buffers).

Implementing logging via naive standard library facilities (`std::format`, `std::ostringstream`,
`fprintf`) or unconstrained variadic macros introduces four failure modes in a game engine:

- **Heap Allocation & Allocator Recursion:** Standard formatting facilities (`std::format`,
  `snprintf` locale lookups, `std::string`) allocate dynamic memory. If `gp::memory::Malloc` or
  `PagePool` logs an out-of-memory warning or page-lease trace that triggers a heap allocation,
  the engine deadlocks on allocator locks or overflows the call stack via infinite recursion.
- **Hot-Path Frame Jitter & OS I/O Contention:** Writing directly to OS file descriptors or the
  Windows Console Host (`WriteConsole` / `OutputDebugStringW`) from `JobSystem` worker fibers or
  the Render Thread stalls calling cores on kernel locks for hundreds of microseconds to
  milliseconds. That contention causes priority inversion and missed frame budgets.
- **Eager Argument Evaluation & `.rdata` Binary Bloat:** Pure C++ logging functions
  (`log::debug(cat, "State={}", expensiveToString())`) evaluate all function arguments before
  entering the function body, even when `Debug` verbosity is disabled at runtime or compiled out in
  `Shipping` builds. Unstripped string literals also stay in the shipping executable's `.rdata`
  section, where they expose internal file paths and waste memory.
- **Pre-Initialization & Crash-Time Message Loss:** Purely asynchronous loggers that rely only on
  a background consumer thread drop fatal diagnostic messages if the process crashes (`SIGSEGV` /
  `EXCEPTION_ACCESS_VIOLATION`) before the consumer thread drains its queue, or if logs are emitted
  during early boot before OS threads start.

We need an STL-free, zero-heap-allocation logging architecture in `gp::core` that enforces
compile-time format validation, skips disabled call-site argument evaluation, separates hot-thread
log emission from slow OS I/O, and flushes deterministically during unit tests, early boot, and
fatal crashes.

## Decision

We introduce the `gp::log` subsystem inside `source/runtime/core/` built around four core pillars:
a **Granular Multi-Sink Pipeline (`ILogSink`)**, a **Zero-Allocation `<charconv>` Stack Formatter
(`gp::log::formatTo`)**, a **Dual Synchronous / Lock-Free MPMC Ring Router (`gp::log::Logger`)**,
and a **Hybrid `consteval` C++23 Function + Short-Circuiting `GP_LOG` Macro Front-End**.

### 1. Physical Header & Directory Taxonomy

In strict compliance with the Header Granularity Law ([ADR-0001](./ADR-0001.md)) and co-located test
discipline ([ADR-0006](./ADR-0006.md)), `gp::log` decomposes its public declarations by
architectural role:

```text
source/runtime/core/
  public/
    logging/
      LogForward.hpp           <-- Forward declarations (LogCategory, ILogSink, Logger, etc.)
      LogEnums.hpp             <-- LogLevel, LogExecutionMode, LogSinkFlags
      LogTypes.hpp             <-- LogSourceLocation, LogRecordView, LogEntry, LogFormatString
      LogDesc.hpp              <-- LoggerDesc, ConsoleSinkDesc, FileSinkDesc
      LogCategory.hpp          <-- Cache-friendly LogCategory with compile-time & atomic levels
      LogFormatter.hpp         <-- Zero-allocation <charconv> type-safe formatter into FixedString
      ILogSink.hpp             <-- Pure abstract contract for output targets
      Logger.hpp               <-- Central Logger router & C++23 consteval log::info/warn/error API
      LogMacros.hpp            <-- GP_DECLARE_LOG_CATEGORY & short-circuiting GP_LOG* macros
      sinks/
        ConsoleSink.hpp        <-- ANSI color stdout/stderr terminal sink
        FileSink.hpp           <-- Buffered rolling file sink via gp::platform::Paths
        DebugOutputSink.hpp    <-- OS debugger sink (OutputDebugStringW / POSIX stderr)
        TracySink.hpp          <-- Severity-colored Tracy profiler timeline sink (GP_MESSAGE_C)
        MemoryRingSink.hpp     <-- Fixed-capacity in-memory circular sink for tests & overlays
  private/
    logging/
      Logger.cpp               <-- Router state, MPMC queue consumer thread, CLI parsing, & flush
      sinks/
        ConsoleSink.cpp        <-- Platform console write & ANSI color sequences
        FileSink.cpp           <-- OS file handle management & 8 KiB write buffering
        DebugOutputSink.cpp    <-- Win32 OutputDebugStringW / POSIX debugger routing
        TracySink.cpp          <-- Tracy message forwarding
        MemoryRingSink.cpp     <-- In-memory ring buffer storage and query API
  tests/
    logging/
      LogCategory.tests.cpp    <-- Compile-time ceiling & atomic runtime verbosity filtering tests
      LogFormatter.tests.cpp   <-- Zero-alloc formatting for ints, floats, hex, strings, gp::Name
      Logger.tests.cpp         <-- Sync/Async MPMC routing, multi-sink broadcast, & GP_LOG macros
```

### 2. Data-Oriented Pipeline & Execution Modes

```text
  [ Call Site: GP_LOG(LogRHI, Info, "Swapchain {}x{}", w, h) ]
                               |
    1. Compile-Time Gate:      Stripped to ((void)0) if GP_NO_LOGGING or level < CompileTimeMin
                               |
    2. L1 Atomic Category:     if (!Category.isEnabled(Level)) -> skip argument evaluation!
                               |
    3. consteval Format Check: LogFormatString<Args...> validates "{}" count at compile time
                               |
    4. Stack Formatting:       gp::log::formatTo writes into stack buffer (Zero Heap Alloc)
                               |
                               v
  +---------------------------------------------------------------------------------------+
  |                              gp::log::Logger::submit()                                |
  +---------------------------------------------------------------------------------------+
               |                                                       |
     (Synchronous Mode / Pre-Init / Fatal)                   (AsyncRing Mode)
               |                                                       |
               v                                                       v
  [ Spinlock-Guarded Broadcast ]                     [ Lock-Free MPMCRingQueue<LogEntry> ]
               |                                                       |
               |                                        (Background Consumer Thread)
               +---------------------------+---------------------------+
                                           |
                                           v
            +------------------------------+------------------------------+
            |              |               |               |              |
            v              v               v               v              v
      [ConsoleSink]   [FileSink]   [DebugOutputSink]  [TracySink]  [MemoryRingSink]
```

### 3. Call-Site Front-End Comparison & Hybrid Contract

`gp-engine` provides both a **C++23 `consteval` Function API** and a **Short-Circuiting `GP_LOG`
Macro API** over the exact same `Logger::log()` backend:

| Feature / Property | `gp::log::info(cat, fmt, ...)` | `GP_LOG(cat, Level, fmt, ...)` |
| :--- | :--- | :--- |
| **Source Location** | `std::source_location::current()` | `std::source_location::current()` |
| **`consteval` Validation** | Compile-time `{}` count check | Compile-time `{}` count check |
| **Disabled Argument Eval** | Arguments evaluated before call | **Short-circuited (`0` cost)** |
| **`Shipping` `.rdata`** | Relies on compiler Dead Code Elim | **100% stripped by macro** |

```cpp
// 1. Declare a log category (default runtime level = Info, compile-time minimum = Trace):
GP_DEFINE_LOG_CATEGORY(LogCore, gp::log::LogLevel::Info, gp::log::LogLevel::Trace);

// 2. Primary Macro API (lazy argument evaluation + zero .rdata footprint when stripped):
GP_LOG(LogCore, Info, "Initialized {} worker threads in {} ms", workerCount, elapsedMs);
GP_LOG_WARNING(LogCore, "Frame arena usage reached {}%", usagePercent);
GP_LOG_ERROR(LogCore, "Failed to load module '{}' (code: {:#x})", moduleName, errCode);

// 3. Direct C++23 Function API (backed by consteval LogFormatString<Args...>):
gp::log::info(LogCore, "Boot sequence complete for {}", appName);
```

### 4. Architectural Invariants

1. **Zero Heap Allocations:** Formatting (`LogFormatter.hpp`), queueing (`MPMCRingQueue`), routing
   (`Logger.cpp`), and all five built-in sinks (`ConsoleSink`, `FileSink`, `DebugOutputSink`,
   `TracySink`, `MemoryRingSink`) never invoke `new`, `malloc`, or `gp::memory::Malloc` on the
   logging path. All buffers live on the stack or in fixed-capacity `.bss` storage.
2. **Compile-Time Format String Verification (`consteval`):** `LogFormatString<Args...>` parses the
   format string literal at compile time in its `consteval` constructor. Any mismatch between the
   number of `{}` placeholders and `sizeof...(Args)`, unclosed braces, or invalid format specifiers
   outside `{:[#][0][width][.precision][x|X|b|B|d|f|e]}` fails compilation immediately.
3. **Two-Tier Category Filtering (Compile-Time + Atomic L1 Load):** Every `LogCategory` carries a
   `constexpr LogLevel compileTimeMinLevel` and a runtime `gp::Atomic<LogLevel> m_activeLevel`
   queried with `MemoryOrder::Relaxed`. In `GP_LOG`, if a message's level is disabled, the
   variadic argument expressions are never evaluated.
4. **Pre-Init, Re-Entrancy, and Fatal Synchronous Delivery:** Before `Logger::initialize()` starts
   the background flush thread, or whenever a `LogLevel::Fatal` record is submitted, `Logger`
   drains queued records and dispatches synchronously to all active sinks before calling
   `ILogSink::flush()`. Same-thread re-entrancy tracking on the dispatch spinlock drops recursive
   log calls emitted inside a custom `ILogSink::write()` implementation to prevent self-deadlock.
5. **Command-Line Verbosity Overrides ([ADR-0040](./ADR-0040.md)):** During initialization,
   `Logger` inspects `gp::CommandLine` for `-log-level=< trace|debug|info|warn|error|fatal|off >`
   and `-log-sync` so developers and CI runners can change verbosity and execution mode without
   recompiling.

## Alternatives Considered

### Option A: Pure Synchronous Multi-Sink Dispatch Only (Early Unreal `FOutputDeviceRedirector`)

Format strings on the calling thread and synchronously iterate all registered sinks under a global
mutex on every log call.

**Why rejected:** OS file writes and terminal console locks (particularly Windows `conhost.exe`)
can block the calling thread for hundreds of microseconds to several milliseconds. Synchronous
console or disk I/O on `JobSystem` worker fibers during gameplay causes frame budget overruns and
priority inversion.

### Option B: Deferred Binary Argument Serialization into Per-Thread SPSC Rings (`UnrealTrace`)

Serialize raw binary argument bytes into thread-local SPSC buffers and format strings on a
background thread after merge-sorting timestamps across all threads.

**Why rejected:** Requires a binary argument type-tag state machine, dynamic TLS lifecycle
registration for external OS threads (such as audio or SDL callbacks), and a multi-way timestamp
merge-heap on the consumer thread. If a thread crashes before its TLS ring drains, recovering
unformatted binary packets inside a signal or SEH handler is brittle and makes the subsystem harder
to teach.

### Option C: Pure C++23 Logging Functions Without `GP_LOG` Macros

Provide only `gp::log::info(...)` and `gp::log::debug(...)` template functions using
`std::source_location::current()`, and drop `GP_LOG` macros.

**Why rejected:** C++ evaluation rules require all arguments to a function call to evaluate before
entering the function body. A call such as `gp::log::trace(cat, "Dump: {}", buildDebugSummary())`
runs `buildDebugSummary()` even when `Trace` is disabled at runtime or in `Shipping` builds.
Keeping `GP_LOG` macros alongside C++23 functions preserves lazy argument short-circuiting and full
preprocessor stripping when `GP_NO_LOGGING` is enabled.

## Consequences

### Positive

- **Zero Allocation & Safe Pre-Heap Logging.** Because the formatter and sinks use only stack and
  fixed inline buffers, `gp::memory` allocators, `gp::platform::Paths`, and early boot code can log
  safely without allocator recursion or heap corruption.
- **Compile-Time Format Safety Without STL Bloat.** The custom `consteval` `LogFormatString` and
  `<charconv>` formatter catch format-string bugs at compile time and avoid `<format>` and
  `<iostream>` header bloat.
- **Predictable Hot-Path Latency.** In `AsyncRing` mode, worker threads and fibers enqueue
  formatted records via lock-free atomic operations without waiting on OS disk or console I/O.
- **Direct Unit Testability.** `MemoryRingSink` and `LogExecutionMode::Synchronous` let unit tests
  inspect emitted log records, categories, and source locations in memory with no filesystem side
  effects.

### Negative

- **Fixed Maximum Message Length (`kMaxLogMessageLength = 439`).** To keep `LogEntry` at an exact
  512-byte (`8` cache lines) footprint (`72` bytes of metadata plus `440` bytes of inline message
  buffer) with zero heap allocations, single log messages over `439` UTF-8 bytes truncate with a
  null terminator.
- **Bounded Asynchronous Queue Capacity.** Under heavy log bursts that fill the lock-free ring
  before the background flush thread wakes up, `Logger` either flushes synchronously or increments
  an atomic dropped-record counter according to `LoggerDesc::overflowPolicy`.
