# ADR-0052: M:N Cooperative Fiber Job System, Zero-Allocation RDG Task Graphs, and Context-Aware Parallel-For

> Scheduling hundreds of Render Dependency Graph (RDG) passes purely by parking imperative fibers on
> `JobCounter` barriers exhausts fixed fiber pools and introduces frame-level wave bubbles, while
> stackless continuation graphs destroy sequential C++ control flow and lacks per-worker RHI command
> context indexing. `gp-engine` introduces the Layer 3 **`gp::thread::JobSystem`** in `gp::core`: an
> $M:N$ cooperative fiber work-stealing scheduler combining lazy two-tier fiber pool acquisition
> (`64 KiB` / `512 KiB`), priority MPMC and Chase-Lev SPMC queues, a zero-allocation declarative DAG
> continuation subsystem (**`gp::thread::JobGraphNode`** / **`gp::thread::JobGraph`**) tailored for
> RDG pass compilation, and a worker-index-aware **`parallelFor`** splitter (**`JobContext`**) for
> lock-free per-worker RHI command-list recording.

![Proposed][badge-proposed]

## Context

With elastic fiber scratch arenas ([ADR-0048](./ADR-0048.md)), dual-tier cooperative fibers
([ADR-0049](./ADR-0049.md)), stack-resident `JobWaitNode` counters and fences
([ADR-0050](./ADR-0050.md)), and bounded lock-free Chase-Lev / Vyukov queues
([ADR-0051](./ADR-0051.md)) established in Layers 0–2, `gp-engine` requires its Layer 3 **Job
System** orchestrator (`gp::thread::JobSystem`). Beyond general gameplay, physics, and animation
concurrency, this scheduler must serve as the execution backbone for the engine's **Render
Dependency Graph (RDG / FrameGraph)** ([ADR-0002](./ADR-0002.md)).

Designing an AAA job scheduler that simultaneously excels at imperative gameplay concurrency and
RDG frame compilation exposes four critical architectural tensions:

### 1. The RDG Fiber-Pool Exhaustion Hazard

In a pure Naughty Dog-style fork-join fiber scheduler, dependencies between tasks are expressed
exclusively by spawning a task onto a fiber and calling `prerequisiteCounter.wait(0)` inside the
task body. While ideal for dynamic fork-join trees, a modern RDG frame compiles $150\text{–}400$
render passes (shadow cascades, depth pre-pass, G-buffer,async compute culling, lighting,
post-processing) with static read/write resource barriers. If an RDG dispatches 250 passes upfront
and each pass immediately acquires a `Fiber` only to call `wait()` on its upstream pass counter,
all 128 pooled `64 KiB` fibers become parked on downstream passes before the root passes can even
acquire a fiber to execute—**deadlocking the engine**.

### 2. Lazy Fiber Binding vs. Eager Fiber Allocation

If queuing a job (`dispatch`) immediately pops a `Fiber` from the fiber pool, a burst of 2,048 fine
jobs will exhaust the fiber pool even if none of those jobs ever yield. Conversely, if queues
store lightweight 32-byte `JobQueueItem` structs ([ADR-0051](./ADR-0051.md)) and worker threads bind
a pooled `Fiber` **lazily** at the exact moment a CPU core begins executing the job (returning the
`Fiber` to the pool the instant the function returns), 10,000 queued leaf jobs require **at most
$N$ fibers** (one per hardware worker thread). Pooled fibers beyond $N$ are consumed *only* by jobs
that actively yield mid-execution on a `JobCounter` or `JobFence`.

### 3. Lock-Free Per-Worker RHI Command-List Recording (`JobContext::workerIndex`)

In Vulkan, Direct3D 12, and Metal ([ADR-0002](./ADR-0002.md)), `VkCommandPool` and
`ID3D12CommandAllocator` are strictly **not thread-safe**. When an RDG pass records draw or dispatch
commands in parallel across 16 CPU cores (or fans out a heavy G-buffer pass via `parallelFor`),
workers cannot share a single command allocator without mutex locks. Each worker thread requires a
deterministic, compact index $\text{workerIndex} \in [0, N_{\text{workers}}]$ passed directly into
every task and `parallelFor` batch via a `JobContext` struct so RDG passes can index
`passCommandLists[ctx.workerIndex]` in $O(1)$ time with zero locks and zero false sharing.

### 4. External Thread Starvation and Worker Parking Latency

When the Game Thread or Render Thread waits on a frame completion `JobCounter` or `JobFence`, pure
spin-waiting burns a full hardware core while potentially starving runnable jobs if worker threads
are saturated. Conversely, if idle worker threads immediately enter deep OS kernel sleep when queues
empty, micro-bursts of RDG pass completions incur $2\text{–}15\ \mu\text{s}$ kernel wake latencies on
every stage transition.

## Decision

We introduce the Layer 3 **`gp::thread::JobSystem`** subsystem in
`source/runtime/core/public/threading/jobs/`, unifying $M:N$ cooperative fiber work-stealing,
zero-allocation declarative DAG continuations (`JobGraphNode` / `JobGraph`), and context-aware
`parallelFor` dispatch:

```text
source/runtime/core/
  public/
```

### 1. Per-Worker Scheduling Hierarchy and Lazy Two-Tier Fiber Pool

`JobSystem` provisions $N$ dedicated OS worker threads (`gp::platform::Thread`, where index `0` is
reserved as the calling/main-thread slot `kMainThreadWorkerIndex = 0` when main-thread work-helping
is active, and indices `1 .. N` are dedicated background worker threads) alongside two pre-allocated
[`gp::thread::Fiber`](./ADR-0049.md) pools managed by lock-free `MPMCRingQueue<gp::UInt16>` index
free-lists:

- **Standard Pool (`FiberStackTier::Standard64KiB`):** Default `128` fibers (`64 KiB` stack each)
  for general gameplay, physics, culling, and RDG command-list recording tasks.
- **Large Pool (`FiberStackTier::Large512KiB`):** Default `32` fibers (`512 KiB` stack each) for
  deep-call-stack third-party libraries, RHI driver submission, or shader/PSO compilation.

```text
Per-Worker Scheduling Priority Pipeline (selectNextWorkItem)
+-----------------------------------------------------------------------+
| 1. Woken / Resumed Fibers Queue (MPMCRingQueue<JobQueueItem>)         |
|    -> Highest priority: completes already-started tasks holding       |
|       active Fiber stacks & FiberScratchArena pages first!            |
+-----------------------------------------------------------------------+
| 2. Global High-Priority Queue (MPMCRingQueue<JobQueueItem>[High])     |
|    -> Urgent frame-critical kickoffs, audio & RHI handoffs.           |
+-----------------------------------------------------------------------+
| 3. Local Worker Chase-Lev Deque (WorkStealingDeque::tryPopBottom)     |
|    -> LIFO pop of most-recently spawned child jobs (hot L1/L2 cache). |
+-----------------------------------------------------------------------+
| 4. Global Normal-Priority Queue (MPMCRingQueue<JobQueueItem>[Normal]) |
|    -> External thread submissions & root DAG pass dispatches.         |
+-----------------------------------------------------------------------+
| 5. Victim Steal Loop (WorkStealingDeque::tryStealTop across peers)    |
|    -> FIFO steal of coarsest-grained subtrees from busy workers.      |
+-----------------------------------------------------------------------+
| 6. Global Low-Priority Queue (MPMCRingQueue<JobQueueItem>[Low])       |
|    -> Multi-frame background streaming and precomputation.            |
+-----------------------------------------------------------------------+
```

- **Lazy Fiber Acquisition:** Queues hold 32-byte `JobQueueItem` structs (`JobEntry` or
  `ResumedFiber`). When a worker pops a `JobEntry`, it acquires a free `Fiber` index from the
  matching `FiberStackTier` pool, binds the task via `Fiber::bindTask()`, and switches from its
  worker `ThreadAnchor` fiber into the child fiber.
- **Immediate Recycling vs. Cooperative Parking:** If the task runs to completion without yielding,
  the worker immediately decrements `JobDecl::counter` (if non-null) and pushes the `Fiber` index
  back into the tier free-list. If the task yields inside `JobCounter::wait()` or `JobFence::wait()`,
   the worker's `JobFiberParker` switches back to the worker's `ThreadAnchor` fiber *without* freeing
  the child fiber; when the awaited counter later reaches `0`, `JobWakeFunction` enqueues the child
  `Fiber*` as a `JobQueueItem::fromResumedFiber()` into the resumed-fiber queue, and whichever
  worker finishes it returns the `Fiber` index to the pool.

### 2. Execution Context (`gp::thread::JobContext`) for RDG Per-Worker Indexing

To support lock-free per-worker resources (such as RDG per-worker `IRHICommandList` / command
allocator arrays, telemetry buffers, or deterministic sub-allocators), `JobSystem` maintains a
thread-local execution context (`JobSystem::getCurrentJobContext()`) and provides context-aware task
signatures alongside raw `JobEntryFunction` callbacks:

```cpp
struct JobContext
{
    JobSystem* jobSystem{ nullptr };
    gp::UInt32 workerIndex{ 0u };      // Deterministic slot in [0 .. totalSlotCount - 1]
    FiberId fiberId{ kInvalidFiberId }; // Active cooperative fiber ID
    JobPriority priority{ JobPriority::Normal };
};
```

- Slot `0` represents the external/main thread participating via `waitAndHelp()`, while slots
  `1 .. workerCount` map 1:1 to dedicated worker threads. An RDG pass allocating
  `workerCount + 1` command lists can index `cmdLists[ctx.workerIndex]` from any fiber or
  `parallelFor` batch with **zero synchronization overhead**, even if the fiber migrates across
  worker threads after yielding (because `getCurrentJobContext()` queries the currently executing
  OS worker slot via `GP_FORCENOINLINE` TLS).

### 3. Zero-Allocation Declarative Task Graph (`JobGraphNode` & `JobGraph`) for RDG

To prevent RDG pass trees from consuming pooled fibers while waiting on upstream passes,
`gp::thread::JobGraph` provides a declarative, arena-backed Directed Acyclic Graph (DAG) layer that
lowers directly into `JobSystem` dispatches:

```text
JobGraphNode (64 Bytes, alignas(64) Cache-Line Isolated)
+-----------------------------------------------------------------------+
| decl              : JobDecl (32B)       Pass entry, userData, tier    |
| dependents        : JobGraphNode** (8B) Contiguous successor array    |
| dependentCount    : UInt16 (2B)         Number of successor edges     |
|dependentCapacity : UInt16 (2B)         Allocated successor capacity  |
| nodeIndex         : UInt32 (4B)         Graph-local topological ID    |
| unresolvedPrereqs : Atomic<UInt32> (4B) Remaining upstream passes     |
| initialPrereqs    : UInt32 (4B)         Saved count for graph replay  |
| completionCounter : JobCounter* (8B)    Graph-wide completion counter |
+-----------------------------------------------------------------------+
```

1. **Zero Heap Allocations:** `JobGraph` allocates its `JobGraphNode` array and adjacency lists out
   of any caller-supplied [`gp::concepts::IsAllocator`](./ADR-0042.md) (such as a per-frame
   `LinearAllocator` or `FiberScratchAllocator`) or a caller-provided fixed buffer.
2. **Zero Parked Fibers for Pending Passes:** When `JobGraph::submit(jobSystem, &completionCounter)`
   is invoked, `completionCounter` is incremented by `nodeCount`, and **only root nodes**
   (`unresolvedPrereqs == 0`) are dispatched to `JobSystem`. Non-root passes remain dormant in memory
   consuming **zero fibers and zero queue slots**.
3. **Wait-Free Continuation Cascades:** When a node finishes executing its `JobDecl`, its completion
   wrapper iterates `dependents[0 .. dependentCount - 1]` and executes
   `dep->unresolvedPrereqs.fetchSub(1u, MemoryOrder::AcqRel)`:
   - Every dependent whose prerequisite count transitions `1 -> 0` is immediately pushed onto the
     executing worker's `WorkStealingDeque` (with automatic spill to `MPMCRingQueue`), and the
     **first** ready dependent can be tail-executed or popped immediately in LIFO order to keep
     pass metadata hot in L1 cache.
   - Finally, the finished node decrements `completionCounter` by `1`. When the last leaf pass
     completes, `completionCounter` reaches `0`, waking any awaiting RDG submission fiber or
     `JobFence`.
4. **Reusable / Replayable Graphs:** Storing `initialPrereqs` allows cached static RDG topologies or
   multi-iteration physics sub-step graphs to be re-armed in $O(V)$ time via `JobGraph::reset()`
   without rebuilding edges.

### 4. Adaptive Data-Parallel Range Splitter (`parallelFor`)

`JobSystem::parallelFor()` partitions a contiguous index range $[0, \text{elementCount})$ into
batches and executes a stateless `ParallelForFunction(startIndex, count, userData, const JobContext&)`
across all workers:

- **Fast-Path Single-Batch Bypass:** If `elementCount == 0`, returns immediately; if
  `elementCount <= minBatchSize` (or `workerCount == 0`), executes the range inline on the calling
  thread/fiber with **zero queue pushes and zero counter overhead**.
- **Balanced Grain-Size Calculation (`JobSplitStrategy`):**
  - `JobSplitStrategy::FixedBatchSize`: Splits into $\lceil \text{elementCount} / \text{batchSize} \rceil$
    batches.
  - `JobSplitStrategy::Adaptive`: Divides work into up to $\text{workerCount} \times 4$ batches
    (clamped by `minBatchSize` and `maxBatchCount = 256`) so straggler cores are load-balanced via
    work stealing without flooding queues.
- **Stack-Resident Descriptor Array:** For $\le 64$ batches, batch descriptors and the
  `CacheAlignedJobCounter` reside **100% on the caller's stack** (or `FiberScratchArena` when
  batches exceed the inline stack threshold), upholding the zero-heap-allocation invariant.

### 5. Two-Phase Spin-Then-Park Worker Wake Protocol & `waitAndHelp`

- **Bounded Spin + Bitmask Sleep:** When a worker thread finds all queues empty, it executes a
  configurable spin phase (`spinIterationsBeforeSleep`, calling `Thread::spinWait()`). If no work
  arrives, it sets its bit in an atomic 64-bit `m_sleepingWorkerMask`, re-verifies queue state under
  a `SeqCst` fence to prevent lost wakeups, and parks on its per-worker OS wait primitive.
- **Zero-Syscall Fast Path When Workers Are Awake:** When `dispatch()` or `JobWakeFunction` enqueues
  work, it loads `m_sleepingWorkerMask`. If `m_sleepingWorkerMask == 0ULL` (all workers are actively
  running or in their spin phase), the producer performs **zero OS kernel syscalls**.
- **Deadlock-Free External Thread Work-Helping (`waitAndHelp`):** When the Game Thread or Render
  Thread calls `jobSystem.waitForCounter(counter)`, it converts itself via `ScopedThreadFiber` (if
  not already in a fiber) and helps execute ready jobs until `counter.isAtOrBelow(targetCount)`,
  guaranteeing forward progress even if configured with `workerCount = 1` on constrained CI VMs.

### Architectural Invariants

1. **Zero Steady-State Heap Allocations:** `dispatch()`, `parallelFor()`, `waitForCounter()`,
   `waitForFence()`, and `JobGraph::submit()` must never allocate from the global heap after
   `JobSystem::initialize()`.
2. **Lazy Fiber Binding:** Queued `JobDecl` entries must never hold a `gp::thread::Fiber` while
   waiting in `WorkStealingDeque` or `MPMCRingQueue`; fibers are leased strictly during active
   execution or while suspended on a `JobCounter` / `JobFence`.
3. **Resumed Fibers Prioritized Over Fresh Jobs:** Workers must drain woken `ResumedFiber` items
   before starting new `JobEntry` items to bound maximum concurrent fiber and `PagePool` usage.
4. **Deterministic Worker Slot Indexing (`0 .. getTotalWorkerSlotCount() - 1`):** Every task and
   `parallelFor` invocation must receive a valid `JobContext` whose `workerIndex` uniquely identifies
   the currently executing hardware worker slot (`0` for the external/main thread, `1 .. N` for
   dedicated workers).
5. ** TLS Re-Resolution Across Fiber Migrations ([ADR-0049](./ADR-0049.md)):** All worker-slotTLS
   queries (`getCurrentWorkerIndex()`, `getCurrentJobContext()`) must be marked `GP_FORCENOINLINE`
   with compiler barriers so a fiber that yields on Worker $1$ and resumes on Worker $3$ always
   reads Worker $3$'s `workerIndex`.

## Alternatives Considered

### Option A: Pure Imperative Fork-Join Fiber Pool Without Declarative `JobGraph` (Naughty Dog)

Express all RDG pass dependencies by spawning every pass onto a fiber upfront and calling
`prerequisiteCounter.wait()` at the top of each pass function.

**Why rejected:** Spawning $M_{\text{passes}} > M_{\text{fibers}}$ interdependent passes upfront
parks every fiber in the pool on downstream passes before upstream root passes can acquire a fiber,
causing a deterministic fiber-starvation deadlock in complex RDG frames.

### Option B: Stackless Continuation Task Graph Only (Unreal Engine 5 `LowLevelTasks`)

Omit cooperative fibers and execute all tasks on OS thread stacks using continuation callbacks and
inline stack work-helping on `Wait()`.

**Why rejected:** Destroys imperative C++ control flow for gameplay and physics code, causes
unbounded stack growth and priority inversion during recursive inline `Wait()` helping, and breaks
[`ScopedFiberScratchMark`](./ADR-0048.md) LIFO unwinding invariants.

### Option C: Eager Fiber Binding at `dispatch()` Time

Acquire a `Fiber*` from the pool inside `dispatch()` before pushing to `WorkStealingDeque`.

**Why rejected:** Limits the maximum number of queued jobs to the size of the fiber pool (`128`),
wasting `64 KiB` stacks on unstarted leaf tasks in the queue and forcing `dispatch()` to block or
fail during `parallelFor` fan-out bursts.

## Consequences

### Positive

- **Eliminates RDG fiber-pool exhaustion and topological wave bubbles.** Declarative `JobGraphNode`
  continuations consume zero fibers until all upstream prerequisites complete, allowing RDG frames
  with thousands of passes to execute over a compact 128-fiber pool.
- **Enables lock-free per-worker RHI command recording.** Passing `JobContext::workerIndex` into
  every task and `parallelFor` batch lets RDG passes index directly into per-worker command
  allocators without locks or TLS guesswork.
- **Unifies stackful fiber ergonomics with lock-free work stealing.** Gameplay code can yield
  mid-function on `JobCounter::wait()` while leaf tasks and RDG passes scale across 16–64 cores via
  Chase-Lev work-stealing deques.
- **Guarantees forward progress on single-core and headless CI environments.** `waitAndHelp` allows
  the calling thread to drain queues while waiting on counters or fences.

### Negative

- **Bounded Queue Overflow Requires Inline/Spin Fallback:** If a burst of jobs simultaneously fills
  both the local `WorkStealingDeque` (`1024` slots) and global `MPMCRingQueue` (`4096` slots),
  `dispatch()` must spin-help until a slot frees.
- **Two-Tier Fiber Pool Sizing Configuration:** Deeply recursive tasks that yield simultaneously
  across more than `standardFiberCount` (`128`) active suspension points must wait for an active
  fiber to complete before starting a new root task.
