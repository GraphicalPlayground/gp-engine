# ADR-0044: Layered Virtual File System (VFS) Mount-Point and Logical URI Routing Architecture

> Defines the future I/O Virtual File System (`gp::vfs`) architecture as a priority-layered mount
> table that consumes physical OS directory roots from `gp::platform::Paths` ([ADR-0043](./ADR-0043.md))
> and binds them—alongside read-only compressed archive/pak backends and mod override layers—to
> logical URI schemes (`engine://`, `game://`, `user://`, `appdata://`, `cache://`, `temp://`),
> isolating gameplay, shader, and asset streaming code from physical disk layouts and console
> sandbox partitions.

![Proposed][badge-proposed]

## Context

While `gp::platform::Paths` ([ADR-0043](./ADR-0043.md)) provides zero-allocation discovery of
physical OS directories (`executableDir()`, `appDataDir()`, `documentsDir()`, `tempDir()`) and
lexical path manipulation, higher-level engine subsystems (asset streaming, shader compilation,
save-game serialization, localization, and modding) must **never** hardcode physical OS paths or
concatenated directory trees directly in gameplay or rendering code.

Relying solely on raw physical paths in high-level subsystems creates four production bottlenecks:

1. **Loose-File Development vs. Packaged Shipping Builds:** During editor/development workflows,
   assets (`game://textures/hero_albedo.ktx2`) reside as loose files on the host filesystem. In
   shipping builds (Decima `.core` archives, Glacier `.rpkg`, Unreal `.pak`/`.utoc`, id Tech
   `.resources`), those exact same logical paths reside inside memory-mapped or block-compressed
   archive containers without corresponding loose OS files.
2. **Modding, DLC, and Hotfix Layering:** Supporting patches, DLC packs, and user mods requires
   multiple backing stores (e.g., `BaseGame.pak` at priority `100`, `Patch_1_01.pak` at priority
   `200`, and a user mod directory at priority `300`) to overlay the same `game://` namespace so
   the highest-priority mount transparently wins on read without modifying asset references.
3. **Console Partition & Sandbox Isolation:** Console operating systems enforce strict hardware
   partitioning and read/write access controls:
   * **PlayStation 5 (Prospero):** Read-only package mount `/app0`, DLC mounts `/addcont0`,
     persistent scratch `/download0`, and transient `/temp0`.
   * **Xbox Series X|S (Scarlett):** Read-only package volume `G:\`, persistent local storage
     `T:\`, scratch drive `D:\`, and connected storage blobs for save games.
   * **Nintendo Switch (NX):** Read-only cartridge/package `rom:/`, mounted save data `save:/`,
     and temporary cache `cache:/`.
   * **Desktop Sandboxes (Windows AppContainer / macOS App Sandbox / Steam Deck Flatpak):**
     Strictly forbid writing to `executableDir()`, requiring all writes to route through
     `user://` (`documentsDir()`) or `appdata://` (`appDataDir()`).
4. **Directory Traversal & Sandbox Escape Vulnerabilities:** Allowing untrusted mod manifests or
   network-replicated asset paths to open raw OS paths enables `../../` path traversal outside the
   game's designated directories.

## Decision

When the engine's I/O subsystem is implemented, we will enforce a **Strict Two-Layer Separation**
between **Layer 0 (`gp::platform::Paths` in `gp::core`)** and **Layer 1 (`gp::vfs::VirtualFileSystem`)**:

### 1. Architectural Layering Diagram

```text
  ┌─────────────────────────────────────────────────────────────────────────┐
  │            Gameplay / Renderer / Asset Manager / Config / UI            │
  │     Logical URIs: "engine://shaders/pbr.hlsl", "user://saves/01.sav"    │
  └────────────────────────────────────┬────────────────────────────────────┘
                                       │
                                       ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │                 Layer 1: Virtual File System (gp::vfs)                  │
  │  • Parses scheme ("engine://", "game://", "user://", "appdata://")      │
  │  • Enforces CollapseRelativeDirectories() sandbox jail per mount point  │
  │  • Evaluates priority-ordered IMountBackend stack (Mod > Patch > Base)  │
  │  •Enforces ReadOnly vs. ReadWrite access permissions per scheme         │
  └───────────────┬─────────────────────────────────────────┬───────────────┘
                  │ (Physical Loose Files)                  │ (Packaged Archives)
                  ▼                                         ▼
  ┌──────────────────────────────────────┐  ┌───────────────────────────────┐
  │     Layer 0: gp::platform::Paths     │  │   Archive / Pak Mounts        │
  │  • Paths::executableDir()            │  │  • Memory-mapped / Async I/O  │
  │  • Paths::appDataDir()               │  │    (DirectStorage / io_uring) │
  │  • Paths::documentsDir()             │  │  • 64-bit hash TOC lookup     │
  │  • Paths::tempDir()                  │  └───────────────────────────────┘
  └──────────────────────────────────────┘
```

### 2. Canonical Logical URI Schemes & Bootstrap Mounts

During engine initialization, `VirtualFileSystem::initialize()` queries `gp::platform::Paths` and
registers the default physical mount points:

<!-- markdownlint-disable MD013 -->
| Logical Scheme | Access Policy | Desktop Physical Source (`gp::platform::Paths`) | Console Equivalent (PS5 / Xbox / Switch) | Primary Purpose |
| :--- | :--- | :--- | :--- | :--- |
| **`engine://`** | `ReadOnly` | `Paths::combine(Paths::executableDir(), "engine")` (or `.pak`) | `/app0/engine` / `G:\engine` / `rom:/engine` | Core engine shaders, default fonts, fallback meshes, localization. |
| **`game://`** | `ReadOnly` | `Paths::combine(Paths::executableDir(), "content")` + Mods | `/app0/content` + `/addcont0` / `G:\content` | Project assets, levels, audio banks, DLC, and mod overrides. |
| **`user://`** | `ReadWrite` | `Paths::combine(Paths::documentsDir(), appName)` | Console Save Data API / `save:/` | User-visible save games, screenshots, custom keybinds, replays. |
| **`appdata://`** | `ReadWrite` | `Paths::combine(Paths::appDataDir(), appName)` | Persistent Title Storage | Roaming user profiles, persistent telemetry, editor preferences. |
| **`cache://`** | `ReadWrite` | `Paths::combine(Paths::localAppDataDir(), appName, "cache")` | `/download0` / `T:\cache` / `cache:/` | Compiled PSO/shader caches, DDC, downloaded cloud chunks. |
| **`temp://`** | `ReadWrite` | `Paths::combine(Paths::tempDir(), appName)` | `/temp0` / `D:\` | Transient crash staging, diff files, and per-session scratch files. |
<!-- markdownlint-enable MD013 -->

### 3. Planned C++ Bootstrap & Resolution Contract

```cpp
// During engine bootstrap (consuming Layer 0 gp::platform::Paths):
gp::vfs::VirtualFileSystem::mount(
    "engine://",
    gp::platform::Paths::combine(gp::platform::Paths::executableDir(), "engine"),
    gp::vfs::MountPriority::Base,
    gp::vfs::MountAccess::ReadOnly
);

gp::vfs::VirtualFileSystem::mount(
    "game://",
    gp::platform::Paths::combine(gp::platform::Paths::executableDir(), "content"),
    gp::vfs::MountPriority::Base,
    gp::vfs::MountAccess::ReadOnly
);

// Mounting a high-priority user mod folder over game:// without touching asset references:
gp::vfs::VirtualFileSystem::mount(
    "game://",
    gp::platform::Paths::combine(gp::platform::Paths::documentsDir(), "MyGame/Mods/HDTextures"),
    gp::vfs::MountPriority::ModOverride,
    gp::vfs::MountAccess::ReadOnly
);

gp::vfs::VirtualFileSystem::mount(
    "user://",
    gp::platform::Paths::combine(gp::platform::Paths::documentsDir(), "MyGame"),
    gp::vfs::MountPriority::Base,
    gp::vfs::MountAccess::ReadWrite
);
```

### 4. Architectural Invariants for `gp::vfs`

1. **Strict Sandbox Jail (Zero Escape via `..`):** When resolving a logical URI such as
   `game://textures/../models/hero.mesh`, `VirtualFileSystem` strips the scheme prefix (`game://`)
   and invokes `gp::platform::Paths::collapseRelativeDirectories()` on the relative sub-path
   **before** joining it with the physical mount root. If `collapseRelativeDirectories()` returns
   `false` (indicating leading `..` segments that attempt to escape the mount root), the VFS
   immediately rejects the request with `VfsError::SandboxEscapeViolation`.
2. **Priority-Ordered Read Resolution, Single-Target Write Resolution:** A logical scheme (such as
   `game://`) may bind multiple `IMountBackend` instances sorted by descending `MountPriority`
   (`DeveloperOverride > ModOverride > Patch > DLC > BaseArchive`). Read operations (`openRead`,
   `exists`) query mounts from highest to lowest priority until a hit is found. Write operations
   (`openWrite`, `createDirectory`, `remove`) are forbidden on `ReadOnly` schemes (`engine://`,
   `game://`) and route deterministically to the highest-priority `ReadWrite` mount on writable
   schemes (`user://`, `appdata://`, `cache://`, `temp://`).
3. **Backend Pluralism ([ADR-0007](./ADR-0007.md)):** Mount points abstract the storage medium
   behind `IMountBackend`, allowing loose OS directories (`OsDirectoryMountBackend` backed by
   `gp::platform::Paths`), memory-mapped archives (`PakMountBackend`), and console save-data
   containers to share a single unified URI namespace.
4. **Zero Reverse Coupling into `gp::core`:** `gp::platform::Paths` remains completely unaware of
   URI schemes (`engine://`) and mount tables, ensuring `gp::core` remains lightweight and usable
   before the VFS is mounted.

## Alternatives Considered

### Option A: Hardcode `gp::platform::Paths` Concatenations Directly in Subsystems

Have the renderer, audio engine, and gameplay code call
`Paths::combine(Paths::executableDir(), "content/textures/...")` directly.

**Why rejected:** Fails as soon as assets are packed into single-file archives (`.pak`) for
shipping builds, prevents mod/patch overlaying without rewriting file paths, and breaks on consoles
where DLC and base game assets live on separate OS mount partitions (`/app0` vs. `/addcont0`).

### Option B: Implicit Working-Directory Relative Paths (`chdir` to Content Root)

Change the process working directory (`chdir` / `SetCurrentDirectoryW`) to the game root and open
all files via relative paths (`"textures/hero.ktx2"`).

**Why rejected:** The process current working directory is global mutable OS state vulnerable to
modification by third-party DLLs or native OS file dialogs ([ADR-0038](./ADR-0038.md)), cannot
distinguish read-only shipped content from writable user save directories, and cannot merge
multiple physical directories into a single logical hierarchy.

## Consequences

### Positive

* **Seamless Loose-to-Archive Transition.** Asset references (`game://levels/world01.map`) remain
  100% identical between loose-file editor builds and compressed archive shipping builds.
* **First-Class Modding and Patching.** Hotfixes, DLCs, and community mods can override any file
  in `game://` simply by mounting a higher-priority directory or archive.
* **Console & Desktop Sandbox Compliance.** Enforces compile-time/runtime separation between
  immutable installation mounts (`engine://`, `game://`) and writable user/cache partitions
  (`user://`, `appdata://`, `cache://`, `temp://`).
* **Mechanical Path-Traversal Security.** Collapsing relative directories on the sub-path before
  prepending the mount root makes `../../` directory traversal attacks mathematically impossible.

### Negative

* **Two-Step Resolution Indirection.** Resolving a logical URI into an OS file handle or archive
  slice requires parsing the scheme prefix and scanning the mount priority list (mitigated by
  fixed inline mount arrays and 64-bit path hash TOCs in archive backends).
* **Requires Explicit Bootstrap Mounting.** Subsystems that run prior to `VirtualFileSystem::initialize()`
  (such as `gp::CommandLine` or early crash handlers) must use Layer 0 `gp::platform::Paths`
  directly rather than `user://` or `temp://` URIs.
