# ADR-0048: Elastic Page-Chunked Linear Arenas and Context-Swapped Fiber Scratch Allocators

> OS thread-local scratchpad allocators (`ThreadScratchAllocator`) corrupt memory and trigger silent cross-thread data races when cooperative fibers yield at dependency counters (`waitForCounter`) and migrate across worker threads via work stealing, while pre-allocating fixed worst-case contiguous slabs for every fiber in a large pool ($M \gg N$) wastes tens of megabytes of idle RAM. `gp-engine` introduces a two-tier fiber-safe scratch architecture in `gp::memory`: a lock-free, ABA-safe **`PagePool`** that leases fixed-size memory pages (`64 KiB` default) on demand, an elastic **`PagedLinearAllocator`** that chains pages intrusively with $O(1)$ cross-page `MemoryMark` unwinding and zero idle memory footprint, and a context-swapped **`FiberScratchArena`** / **`FiberScratchAllocator`** / **`ScopedFiberScratchMark`** suite paired with fiber-switch epoch assertions in `ScopedScratchMark` to mechanically catch illegal fiber yields inside thread-local scratch scopes.

![Proposed][badge-proposed]

## Context

In [ADR-0042](./ADR-0042.md), `gp-engine` established a lifetime-scoped allocator library including `LinearAllocator` and `ThreadScratchAllocator` (`ThreadScratchArena` + `ScopedScratchMark`). While a `thread_local LinearAllocator` bound to an OS thread is optimal for traditional thread-per-subsystem architectures or non-yielding leaf tasks, it breaks down fundamentally inside an **$M:N$ Fiber-based Work-Stealing Job System** (such as those in **Naughty Dog's engine**, **EA Frostbite**, **Guerrilla's Decima**, and **id Tech 7**), where $M$ cooperative execution contexts (e.g., $128\text{–}256$ fibers) multiplex dynamically over $N$ hardware worker threads ($1$ per CPU core):

### 1. Same-Thread LIFO Clobbering Across Cooperative Fiber Yields

In a fiber scheduler, when a job executing on **Fiber $F_1$** (running on **Worker Thread $T_0$**) spawns child jobs and awaits their completion via `waitForCounter(counter)`, $F_1$ does not block $T_0$ in the OS kernel. Instead, $T_0$ suspends $F_1$'s register context and stack, and switches immediately to a ready **Fiber $F_2$**:

1. Fiber $F_1$ on Worker $T_0$ enters `ScopedScratchMark` (`mark = 0`) and allocates a `16 KiB` array from $T_0$'s `ThreadScratchArena` (`offset: 0 -> 16384`).
2. Fiber $F_1$ spawns child jobs and yields inside `waitForCounter()`.
3. Worker $T_0$ switches to Fiber $F_2$, which enters its own `ScopedScratchMark` (`mark = 16384`), allocates `8 KiB` from the **same** $T_0$ `ThreadScratchArena` (`offset: 16384 -> 24576`), and yields on a slow I/O or physics counter.
4. Fiber $F_1$'s fast child jobs finish first; $T_0$ resumes $F_1$. When $F_1$ exits its `ScopedScratchMark`, it rewinds $T_0$'s `ThreadScratchArena` cursor back to `0`—**silently wiping out $F_2$'s live `[16384..24576)` allocation while $F_2$ is still suspended**.

### 2. Cross-Thread Fiber Migration via Work Stealing

When suspended Fiber $F_1$'s dependency counter reaches zero, $F_1$ is pushed onto the ready queue and can be stolen and resumed by **Worker Thread $T_1$** on a different physical CPU core while Worker Thread $T_0$ is busy executing Fiber $F_3$:

- **Cross-Core Data Race:** $F_1$ (now running on $T_1$) continues reading and writing the buffer it allocated from $T_0$'s `thread_local` slab at step 1, while $F_3$ (running on $T_0$) simultaneously bumps and overwrites $T_0$'s `thread_local` slab without synchronization.
- **Wrong-Arena Reallocation and Rewind:** If $F_1$ grows a `gp::Vector<T, ThreadScratchAllocator>` or destroys its `ScopedScratchMark` while running on $T_1$, `ThreadScratchArena::get()` resolves to **$T_1$'s** `thread_local` arena rather than $T_0$'s. $F_1$ rewinds $T_1$'s cursor to an unrelated offset from $T_0$ and permanently leaks its allocation on $T_0$.

### 3. The $M \times \text{MaxCapacity}$ Static Memory Explosion

Simply giving each of the $M$ fibers in the fiber pool its own dedicated, fixed-capacity contiguous `LinearAllocator` (e.g., $160 \text{ fibers} \times 512\text{ KiB} = 80\text{ MiB}$) creates an unappealing trade-off:

- **Massive Idle Memory Waste:** At any given CPU cycle, at most $N$ fibers (e.g., $8\text{–}16$ hardware threads) are actively executing on cores, and only a fraction of suspended fibers hold live scratch allocations across a yield point. Pre-allocating worst-case contiguous slabs for all $M$ fibers wastes $85\%\text{–}95\%$ of the reserved memory.
- **Hard Capacity Cliff:** If a single recursive culling or BVH-building job temporarily needs `600 KiB` of scratch space, a fixed `512 KiB` per-fiber slab immediately fails with `nullptr` even when `75 MiB` of sibling fiber slabs sit completely unused.

### 4. Contention in Naive Shared Atomic Bumpers

Replacing per-fiber arenas with a single shared `ConcurrentLinearAllocator` whose cursor is a `gp::Atomic<gp::USize>` avoids idle memory waste, but forces every fine-grained container growth and scratch allocation across all $N$ worker threads to contend via `LOCK CMPXCHG` / `LOCK XADD` on the same 64-byte cache line ([ADR-0025](./ADR-0025.md)). Furthermore, interleaved allocations from concurrent fibers make $O(1)$ in-place top-of-cursor `reallocate()` and lexical `ScopedMemoryMark` unwinding impossible.

## Decision

We introduce an elastic, two-level fiber scratch architecture in `source/runtime/core/public/memory/allocators/` consisting of **`PagePool`**, **`PagedLinearAllocator`**, and the **`FiberScratchArena`** / **`FiberScratchAllocator`** / **`ScopedFiberScratchMark`** / **`ScopedFiberArenaBind`** family, alongside a fiber-switch epoch guard on [`ThreadScratchArena`](./ADR-0042.md).

### 1. Lock-Free, ABA-Safe Fixed-Size `PagePool`

`gp::memory::PagePool` manages a contiguous memory slab partitioned into `m_pageCount` uniform pages of `m_pageSize` bytes (defaulting to `kDefaultPageSizeBytes = 64 KiB`, cache-line aligned to `64` bytes):

- **Zero-Metadata Intrusive Page Free Stack:** Recycled pages store a 32-bit `nextPageIndex` inside their first 4 bytes (`kInvalidPageIndex = 0xFFFFFFFFu`).
- **64-Bit ABA-Tagged Atomic Stack Head (`m_freeStackHead`):** Aligned to `kCacheLineSize` (`64` bytes per [ADR-0025](./ADR-0025.md)), `gp::Atomic<gp::UInt64> m_freeStackHead` packs `{ UInt32 headIndex; UInt32 abaTag }` into a single lock-free 64-bit word ([ADR-0024](./ADR-0024.md)). Every `acquirePage()` and `releasePage()` increments `abaTag`, mathematically eliminating ABA race conditions when multiple worker threads concurrently pop and push pages.
- **Lazy $O(1)$ Bump Carving (`m_carvedPageCount`):** Situated on an independent 64-byte cache line, `gp::Atomic<gp::USize> m_carvedPageCount` tracks uncarved pages. `initialize()` and `reset()` complete in $O(1)$ time without touching or paging in the underlying multi-megabyte virtual slab. `acquirePage()` pops from `m_freeStackHead` first and falls back to `m_carvedPageCount.fetchAdd(1)` only when the recycled stack is empty.
- **$O(1)$ Bulk Chain Reclamation (`releasePageChain`):** When a `PagedLinearAllocator` unwinds multiple pages during `rewind()` or `reset()`, it splices the entire chain of pages back onto `m_freeStackHead` in a single atomic compare-and-swap loop rather than issuing one atomic CAS per page.

### 2. Elastic Intrusive Page-Chained Bump Arena (`PagedLinearAllocator`)

`gp::memory::PagedLinearAllocator` implements `IAllocator`, `gp::concepts::IsAllocator`, and `gp::concepts::IsMarkableAllocator`:

```text
PagePool (Shared Lock-Free Slab: N x 64 KiB Pages)
  │
  ├──► [Page 0 (64 KiB)] ◄── prevPage ── [Page 1 (64 KiB, m_currentPage)]
  │    ┌──────────────┬─────────────────┐ ┌──────────────┬─────────────┬───────────────┐
  │    │ PageHeader   │ Used Payload    │ │ PageHeader   │ Used        │ Free Space    │
  │    │ (32 Bytes)   │                 │ │ (32 Bytes)   │             ▲ m_offset      │
  │    └──────────────┴─────────────────┘ └──────────────┴─────────────┴───────────────┘
```

1. **Zero Idle Footprint:** A newly constructed or `reset()` `PagedLinearAllocator` holds `m_currentPage = nullptr` (**0 bytes** of leased memory).
2. **Non-Atomic Hot-Path Bumping:** Inside `m_currentPage`, `allocate(size, alignment)` aligns `m_currentPage->usedOffset` upward and advances it with **zero atomic operations**.
3. **$O(1)$ In-Place Top-of-Page Reallocation:** If `ptr` is the most recent allocation at the top of `m_currentPage` (`ptr + oldSizeInBytes == pageStart + m_currentPage->usedOffset`) and `newSizeInBytes` fits within `m_currentPage`, `reallocate()` adjusts `usedOffset` in place in $O(1)$ time without copying bytes.
4. **Elastic Page Chaining & Oversized Fallback:**
   - When an allocation exceeds the remaining bytes of `m_currentPage` but fits within a standard pool page (`usableSize <= m_pagePool->getPageSize() - sizeof(PageHeader)`), the arena leases a new page via `m_pagePool->acquirePage()` and links `newPage->prevPage = m_currentPage`.
   - When a single allocation exceeds the usable capacity of a pool page (or when `m_pagePool == nullptr`), the arena allocates an exact-sized block from `m_backingMalloc` (`isOversizedHeapBlock = true`) and links it into the page list so its lifetime remains deterministically governed by `rewind()` and `reset()`.
5. **Cross-Page `MemoryMark` Unwinding (`mark()` and `rewind()`):**
   - `mark()` records `{ .offset = currentOffset, .activeAllocations = ..., .allocatedBytes = ..., .pageCookie = m_currentPage }`.
   - `rewind(savedMark)` walks backward from `m_currentPage` to `savedMark.pageCookie`, returning all newer pool pages to `m_pagePool` via `releasePageChain()` (and freeing any oversized blocks to `m_backingMalloc`), then restores `m_currentPage->usedOffset = savedMark.offset`. If `savedMark.pageCookie == nullptr`, all pages are released and the arena returns to a **0-byte footprint**.

### 3. Context-Swapped Fiber Scratchpad (`FiberScratchArena` & `FiberScratchAllocator`)

`gp::memory::FiberScratchArena` decouples the scratchpad lifetime from the OS hardware thread and binds it to the **active Fiber execution context**:

- **Scheduler Context-Switch Hook (`bindFiberArena` / `ScopedFiberArenaBind`):**
  - Each fiber context in the Job System owns a lightweight `PagedLinearAllocator` header (`sizeof(PagedLinearAllocator) == 72` bytes, holding 0 pages when idle) connected to the shared `FiberScratchArena` `PagePool`.
  - When a worker thread switches execution onto a fiber (either starting a new job or resuming a yielded fiber after `waitForCounter`), the scheduler calls `FiberScratchArena::bindFiberArena(&fiber.scratchArena)` (or holds `ScopedFiberArenaBind` around `switchToFiber`).
  - `bindFiberArena` updates a thread-local pointer `tl_activeFiberArena` and increments a thread-local `tl_fiberSwitchEpoch` counter in two L1-cache writes (zero atomics).
  - If `FiberScratchArena::get()` is invoked on a thread with no bound fiber (e.g., Main/OS initialization thread or unit tests outside the job scheduler), it transparently falls back to a thread-local `PagedLinearAllocator` backed by the shared `PagePool`.
- **Zero-Byte Stateless Container Proxy (`FiberScratchAllocator`):**
  - Satisfies `gp::concepts::IsStatelessAllocator` and `gp::concepts::IsMarkableAllocator`.
  - Containers such as `gp::Vector<Transform, gp::memory::FiberScratchAllocator>` incur **0 bytes** of allocator storage overhead via `[[no_unique_address]]` and remain 100% safe to mutate, grow (`reallocate`), and destroy after the owning fiber yields and migrates to a different CPU worker thread.
- **Migration-Verified RAII Guard (`ScopedFiberScratchMark`):**
  - Captures `PagedLinearAllocator& m_arena = FiberScratchArena::get()` and `MemoryMark m_mark = m_arena.mark()` on construction.
  - Upon scope exit—even if the fiber yielded multiple times and migrated from Worker Thread 0 to Worker Thread 15—`~ScopedFiberScratchMark()` asserts `&m_arena == &FiberScratchArena::get()` (verifying the fiber context was properly restored) and rewinds `m_arena` to `m_mark`.

### 4. Mechanical Fiber-Yield Detection in `ThreadScratchAllocator`

To prevent engineers from accidentally using `ThreadScratchAllocator` / `ScopedScratchMark` across a fiber yield point:

- `ScopedScratchMark` records `m_mark.contextEpoch = FiberScratchArena::getThreadSwitchEpoch()` (and the originating `ThreadScratchArena*` in `m_mark.pageCookie`) upon construction.
- In `~ScopedScratchMark()`, the guard asserts that `ThreadScratchArena::tryGet() == m_mark.pageCookie` and `FiberScratchArena::getThreadSwitchEpoch() == m_mark.contextEpoch`. If a fiber yielded or switched on the worker thread while `ScopedScratchMark` was active on the stack, an immediate `GP_ASSERT` fires with a diagnostic message instructing the caller to use `FiberScratchAllocator` and `ScopedFiberScratchMark`.

### Architectural Invariants

1. **Zero Atomic Operations on Intra-Page Fiber Bumps:** Allocating, reallocating in-place, and rewinding within a fiber's active `64 KiB` page must execute zero atomic instructions. Atomic compare-and-swap operations are restricted strictly to `PagePool` page acquisitions and bulk page-chain releases.
2. **Zero Idle Slab Footprint per Fiber:** An unallocated or fully rewound `PagedLinearAllocator` must hold zero leased pages from `PagePool`, ensuring that pre-allocating hundreds of fiber contexts incurs zero megabytes of idle scratch buffer overhead.
3. **Mandatory Migration Safety for `ScopedFiberScratchMark`:** `ScopedFiberScratchMark` must store a direct reference/pointer to the originating fiber's `PagedLinearAllocator` and assert upon destruction that `FiberScratchArena::get()` still resolves to that exact arena on the resuming worker thread.
4. **Mechanical Enforcement of Non-Yielding `ScopedScratchMark`:** Every `FiberScratchArena::bindFiberArena()` transition on a worker thread must increment that worker thread's switch epoch so any live `ScopedScratchMark` (`ThreadScratchAllocator`) spanning a fiber context switch triggers a deterministic debug assertion.

## Alternatives Considered

### Option A: Fixed-Size Contiguous `LinearAllocator` Pre-Allocated per Fiber

Instantiate a contiguous `256 KiB` or `512 KiB` `LinearAllocator` inside each of the $M$ fibers in the fiber pool and swap a `thread_local LinearAllocator*` pointer on fiber context switches.

**Why rejected:** Scales committed memory by $M \text{ (total fibers)} \times \text{MaxCapacity}$ rather than active concurrency. With $160$ fibers at $512\text{ KiB}$ each, $80\text{ MiB}$ of RAM is permanently tied up even when $90\%$ of fibers are idle or using less than $16\text{ KiB}$, while any single job exceeding $512\text{ KiB}$ still fails with out-of-memory.

### Option B: Pure Naughty Dog `TaggedHeap` Without Per-Fiber LIFO Mark/Rewind

Provide only a global `TaggedHeap` (`2 MiB` or `64 KiB` blocks tagged with a `uint64_t` subsystem/frame ID) where worker threads bump inside a thread-cached block and bulk-free all blocks matching a tag at the end of a phase.

**Why rejected:** While bulk tag reclamation is ideal for cross-job outputs that survive until the end of a frame phase, it cannot reclaim temporary memory inside iterative loops or recursive functions within a single job (`ScopedMemoryMark`). Because multiple fibers on the same worker thread would share a thread-cached tagged page, an individual fiber cannot rewind the page cursor on scope exit without clobbering sibling fibers. `PagePool` + `PagedLinearAllocator` captures the shared page-pooling advantage of `TaggedHeap` while preserving $O(1)$ per-fiber LIFO `ScopedFiberScratchMark` unwinding.

### Option C: Shared Lock-Free Atomic Bump Arena (`ConcurrentLinearAllocator`)

Use a single contiguous frame buffer with a cache-line-aligned `gp::Atomic<gp::USize> m_offset` incremented via `fetchAdd` / CAS by all fibers across all worker threads.

**Why rejected:** High-frequency temporary allocations across $8\text{–}32$ worker threads cause severe MESI cache-line bouncing on `m_offset` ([ADR-0025](./ADR-0025.md)). Furthermore, because allocations from different fibers interleave arbitrarily in the buffer, top-of-cursor in-place `reallocate()` (used when `gp::Vector` grows) and scoped `rewind()` are impossible.

## Consequences

### Positive

- **Guarantees 100% memory safety across fiber yields and work-stealing migrations.** `FiberScratchAllocator` and `ScopedFiberScratchMark` follow the fiber execution context rather than the OS thread, preventing LIFO clobbering and cross-thread races after `waitForCounter()`.
- **Eliminates $M \times \text{Capacity}$ idle memory waste.** Idle fibers hold zero pages; active fibers lease `64 KiB` pages on demand from the lock-free `PagePool` and immediately return them when `ScopedFiberScratchMark` unwinds.
- **Preserves $O(1)$ non-atomic bump speed and in-place container growth.** Within an active page, `PagedLinearAllocator` matches the non-atomic pointer-bump and top-of-cursor in-place `reallocate()` performance of `LinearAllocator`.
- **Mechanically catches `ThreadScratchAllocator` misuse across fiber yields.** The thread-local fiber-switch epoch counter turns a subtle, non-deterministic multithreaded memory corruption bug into an immediate, self-documenting assertion failure.

### Negative

- **Page-tail internal fragmentation on boundary crossings.** When an allocation does not fit in the remaining tail bytes of the current `64 KiB` page, those remaining bytes go unused until the scope rewinds beyond that page.
- **One pointer indirection on `FiberScratchArena::get()`.** Resolving the active fiber arena reads a `thread_local PagedLinearAllocator*` pointer (1 L1 cache load), which is negligible (~1 cycle) compared to heap allocation.
- **Scheduler obligation to invoke `bindFiberArena`.** The Fiber Job Scheduler must bind the incoming fiber's `PagedLinearAllocator` (via `ScopedFiberArenaBind` or `bindFiberArena`) on every fiber context switch.
