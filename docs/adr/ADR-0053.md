# ADR-0053: Job System Lifecycle Integration, Double-Buffered Frame Arenas, and Phased Frame Task Graphs in `gp::Application`

> Amends and extends [ADR-0012](./ADR-0012.md) by integrating `gp::thread::JobSystem`
> ([ADR-0052](./ADR-0052.md)), command-line thread count overrides
> ([ADR-0040](./ADR-0040.md)), double-buffered per-frame `gp::memory::LinearAllocator` arenas
> ([ADR-0042](./ADR-0042.md)), and zero-allocation arena-backed `gp::thread::JobGraph` execution
> phases (`onBuildFrameGraph` and `onBuildRenderGraph`) directly into the `gp::Application` host loop.

![Accepted][badge-accepted]

*Amends and extends [ADR-0012: Centralized Application Layer for Platform Lifecycle and Event Orchestration](./ADR-0012.md).*

## Context

In [ADR-0012](./ADR-0012.md), `gp::Application` was established as the engine's central execution
host, owning the injected `IApplicationBackend`, `IInputSystem`, `IWindow`, `SPSCByteRingBuffer`
event stream, and `EngineClock`. However, that initial specification modeled a strictly
single-threaded frame loop (`onFixedUpdate` -> `onUpdate` -> `onRender`) before the engine's
3-layer cooperative fiber concurrency architecture ([ADR-0048](./ADR-0048.md) through
[ADR-0052](./ADR-0052.md)) existed.

Leaving `gp::thread::JobSystem`, `gp::thread::JobGraph`, and per-frame linear arenas disconnected
from `gp::Application` introduces four architectural failure modes in downstream modules (Editor,
Gameplay, Physics, and the Render Dependency Graph):

- **Ad-Hoc Thread Pool Instantiation & Core Oversubscription:** If `gp::Application` does not own
  the primary `gp::thread::JobSystem` instance, individual subsystems or sandbox applications are
  forced to instantiate their own `JobSystem` pools or query global singletons, causing OS worker
  thread oversubscription, contested core affinity masks, and uncoordinated `FiberScratchArena`
  page pool lifetimes.
- **Startup/Shutdown Ordering Hazards:** Subsystems initialized inside
  `Application::onInitialize()` immediately need `JobSystem::parallelFor()` and
  `JobSystem::dispatch()` for parallel asset parsing, shader warmup, and scene construction.
  Conversely, `Application::onShutdown()` must execute *before* the `JobSystem` is torn down so
  subsystems can flush in-flight asynchronous jobs prior to releasing their memory.
- **Dangling Cross-Frame Transient Allocations:** A single per-frame `LinearAllocator` reset at the
  top of `Application::run()` invalidates transient allocations from Frame $N-1$. Subsystems that
  compare previous and current frame transforms, interpolate state across frames, or hand off
  extracted visibility packets to rendering require a double-buffered pair of frame arenas
  (`m_frameArenas[frameIndex & 1u]` and `m_frameArenas[(frameIndex - 1u) & 1u]`) where Frame
  $N-1$'s arena remains intact throughout Frame $N$.
- **Heap-Allocating or Uncoordinated Frame Task Graphs:** Re-allocating `gp::thread::JobGraph` node
  and edge buffers from the general heap every frame violates deterministic frame budgets.
  Furthermore, without dedicated frame-graph construction hooks (`onBuildFrameGraph` and
  `onBuildRenderGraph`) in the canonical loop, gameplay and RDG subsystems must insert ad-hoc
  blocking barriers inside `onUpdate()` and `onRender()`, creating synchronization bubbles where
  $N-1$ worker cores sit idle.

We require a unified, backward-compatible extension of `gp::Application` that provisions
`gp::thread::JobSystem` with CLI override support, manages double-buffered per-frame
`LinearAllocator` arenas, and drives zero-allocation `JobGraph` phases for both simulation
and rendering.

## Decision

We extend `gp::Application` in `source/runtime/application/` to own and orchestrate the
engine's `gp::thread::JobSystem`, double-buffered per-frame `gp::memory::LinearAllocator`
arenas (`m_frameArenas[2]`), and a per-frame arena-backed `gp::thread::JobGraph` (`m_frameGraph`).

### 1. Physical Header & Directory Taxonomy

In accordance with the Header Granularity Law ([ADR-0001](./ADR-0001.md)), `gp::application`
decomposes its public declarations by architectural role:

```text
source/runtime/application/
  public/
    ApplicationForward.hpp   <-- Forward declarations (Application, ApplicationDesc, ApplicationFrameContext)
    ApplicationTypes.hpp     <-- ApplicationFrameContext POD & default frame arena/graph constants
    ApplicationDesc.hpp      <-- ApplicationDesc (embeds JobSystemDesc, frameArenaBytes, graph capacities)
    Application.hpp          <-- Central Application host class, subsystem getters, and virtual hooks
  private/
    Application.cpp          <-- Lifecycle initialization, CLI overrides, frame arena rotation, & DAG loop
  tests/
    Application.tests.cpp    <-- Headless unit tests (JobSystem, parallelFor, JobGraph, & double arenas)
```

### 2. Multi-Threaded `gp::Application` Host Loop

The canonical loop in `Application::run()` is extended from 9 steps ([ADR-0012](./ADR-0012.md)) to
a 12-phase cooperative pipeline where the Main Thread (`workerIndex == 0`) acts as both the OS
event coordinator and a participating `JobSystem` worker:

```text
+---------------------------------------------------------------------------------------------------+
|                             gp::Application Multi-Threaded Host Loop                              |
+---------------------------------------------------------------------------------------------------+
                                                 |
  1. OS Power-Saving Wait:    If minimized/suspended, waitEventsTimeout(100ms) [Workers parked]
                                                 |
  2. Input Frame Reset:       m_inputSystem->beginFrame() [Clears edge latches & resets deltas]
                                                 |
  3. Producer Phase:          m_backend->pumpEvents(m_eventStream) [OS Thread -> SPSC Ring Buffer]
                                                 |
  4. Consumer Phase:          drainEventStream() [Updates Window/Display/Input shadow state & hooks]
                                                 |
  5. Clock Tick:              timeStats = m_clock.tick() [QPC/TSC, Outlier Smoothing, Accumulator]
                                                 |
  6. Frame Arena Rotation:    activeIdx = timeStats.frameIndex & 1u
                              m_frameArenas[activeIdx].reset() [O(1) rewind; N-1 arena stays intact]
                              rebindFrameGraphToCurrentArena() [Zero-heap JobGraph over active arena]
                                                 |
  7. Fixed Simulation:        for (0 .. stepCount) -> onFixedUpdate(fixedDelta)
                                                 |
  8. Variable Update:         onUpdate(timeStats) [Imperative gameplay & parallelFor dispatches]
                                                 |
  9. Update DAG Phase:        onBuildFrameGraph(m_frameGraph, frameCtx)
                              if (!m_frameGraph.isEmpty()) -> m_frameGraph.executeAndWait(m_jobSystem)
                                                 |
 10. Render & RDG Phase:      if (visible):
                                m_frameGraph.clear()
                                onRender(timeStats)
                                onBuildRenderGraph(m_frameGraph, frameCtx)
                                if (!m_frameGraph.isEmpty()) -> m_frameGraph.executeAndWait(m_jobSystem)
                                                 |
 11. Frame-End Barrier:       onEndFrame(frameCtx) [Post-render bookkeeping while N & N-1 are valid]
                                                 |
 12. Adaptive Frame Pacing:   m_clock.paceFrame(targetFps) [Foreground vs. Background FPS target]
                                                 |
                                           (Repeat Loop)
```

### 3. Extended Subsystem Ownership Hierarchy

```text
gp::Application
  |-- m_desc:                 ApplicationDesc (HAL, Window, Clock, JobSystem, & FrameArena config)
  |-- m_backend:              gp::UniquePtr<hal::IApplicationBackend>
  |-- m_inputSystem:          gp::UniquePtr<hal::input::IInputSystem>
  |-- m_mainWindow:           gp::UniquePtr<hal::IWindow>
  |-- m_eventStream:          gp::SPSCByteRingBuffer
  |-- m_clock:                gp::time::EngineClock
  |-- m_jobSystem:            gp::thread::JobSystem (M:N fiber scheduler & worker thread pool)
  |-- m_frameArenas[2]:       gp::memory::LinearAllocator[2] (Double-buffered Frame N & Frame N-1 arenas)
  |-- m_frameGraph:           gp::thread::JobGraph (Per-frame DAG backed by currentFrameArena)
  |-- m_activeFrameArenaIdx:  gp::UInt32 (0 or 1, rotated each frame via frameIndex & 1u)
  |-- m_lastPumpStats:        hal::EventPumpStats
  `-- m_isRunning:            gp::Atomic<bool>
```

### 4. Command-Line Overrides (`gp::CommandLine`)

During `Application::initializeInternal()`, before `m_jobSystem.initialize()` is invoked,
`Application` inspects `gp::CommandLine` ([ADR-0040](./ADR-0040.md)) so developers and automated
CI pipelines can control concurrency without recompiling:

<!-- markdownlint-disable MD013 -->
| Command-Line Flag | Effect on `Application` Concurrency Configuration |
| :--- | :--- |
| **`-threads=<N>`** or **`-workers=<N>`** | Overrides `m_desc.jobSystem.workerThreadCount` with `clamp(N, 1, kMaxJobSystemWorkers)`. |
| **`-no-jobsystem`** | Overrides `m_desc.enableJobSystem = false` (or ` deals with headless single-threaded diagnostic runs`). |
| **`-core-affinity`** / **`-no-core-affinity`** | Enables or disables `m_desc.jobSystem.enableCoreAffinity`. |
<!-- markdownlint-enable MD013 -->

### 5. Architectural Invariants

1. **Deterministic Initialization & Teardown Bracket:** `m_frameArenas[2]` and `m_jobSystem` are
   initialized in `initializeInternal()` *before* `onInitialize()` is called, and torn down in
   `shutdownInternal()` *after* `onShutdown()` returns. Any derived `Application` can safely
   dispatch jobs, run `parallelFor`, or allocate from `getCurrentFrameArena()` inside
   `onInitialize()`, `onFixedUpdate()`, `onUpdate()`, `onRender()`, and `onShutdown()`.
2. **Double-Buffered Frame Arena Lifetimes (`N` and `N-1`):** `m_frameArenas[activeIdx]` is reset
   in $O(1)$ time immediately after `m_clock.tick()` at the start of each frame. Allocations made
   from `getCurrentFrameArena()` in Frame $N$ remain valid throughout Frame $N$ and throughout the
   entirety of Frame $N+1$ via `getPreviousFrameArena()`.
3. **Zero-Heap Per-Frame `JobGraph` Allocation:** At the start of each frame (after resetting
   `getCurrentFrameArena()`), `Application` carves the `JobGraphNode[]` and `JobGraphNode*[]`
   adjacency buffers for `m_frameGraph` directly out of `getCurrentFrameArena()` via
   `m_frameGraph.initialize(getCurrentFrameArena(), maxFrameGraphNodes, maxFrameGraphDependentsPerNode)`.
   Neither `onBuildFrameGraph()` nor `onBuildRenderGraph()` ever touches the global heap.
4. **Main-Thread Work-Helping (`workerIndex == 0`):** Whenever
   `m_frameGraph.executeAndWait(m_jobSystem)` is invoked during the Update DAG or Render/RDG phase,
   the Main Thread participates as `workerIndex == 0` via cooperative work-helping
   ([ADR-0052](./ADR-0052.md)), ensuring zero wasted CPU cores even on 2-core or 4-core machines.

## Alternatives Considered

### Option A: Imperative Fork-Join Only without Built-In Frame `JobGraph` or Double Arenas

Add `gp::thread::JobSystem` and a single `LinearAllocator` to `gp::Application`, leaving all
`JobGraph` construction to individual subsystems inside `onUpdate()` and `onRender()`.

**Why rejected:** Forces every subsystem to construct and wait on its own isolated `JobGraph`
inside `onUpdate()`, introducing synchronous fork-join bubbles between subsystems and
invalidating cross-frame transient data whenever the single `LinearAllocator` resets.

### Option B: Multi-Frame Pipelined Ring (`Frame N` Sim, `Frame N-1` Extract, `Frame N-2` Render)

Run three consecutive frames concurrently across `JobSystem` fibers using a 3-slot `FramePacket`
ring (modeled after Naughty Dog's *Uncharted 4* fiber pipeline).

**Why rejected:** Adds 1 to 2 frames of mandatory input-to-photon latency and requires every
gameplay and editor subsystem to triple-buffer its state into immutable frame packets even for
simple tools and unit tests. Same-frame phased DAG execution (id Tech 7 style) achieves full
core utilization via intra-stage `JobGraph` and `parallelFor` parallelism without sacrificing
input responsiveness.

### Option C: Pure Declarative DAG Only (Remove `onFixedUpdate`, `onUpdate`, and `onRender`)

Replace all imperative virtual hooks with a single `onBuildFrameGraph(JobGraph&)` method.

**Why rejected:** Dynamic-count fixed-timestep physics sub-stepping (`0 .. maxSubSteps` per frame,
[ADR-0033](./ADR-0033.md)) is naturally sequential across sub-steps and depends on the runtime
accumulator output. Removing `onFixedUpdate()`, `onUpdate()`, and `onRender()` breaks backward
compatibility with [ADR-0012](./ADR-0012.md) and forces simple applications to wrap trivial logic
in static callback trampolines.

## Consequences

### Positive

- **Turnkey Multi-Threading Across All Engine Layers.** Every `gp::Application` subclass
  (`EditorApplication`, game binaries, and headless test hosts) automatically receives an
  initialized `gp::thread::JobSystem` and `FiberScratchArena` pool before `onInitialize()` runs.
- **Zero-Allocation RDG & Simulation Graph Foundation.** Pre-binding `m_frameGraph` to the active
  frame's `LinearAllocator` allows simulation passes and future Render Dependency Graph (RDG)
  passes to compile and execute every frame with zero heap allocations.
- **Safe Cross-Frame Data Handoff (`N-1` Readability).** Double-buffered frame arenas
  (`getCurrentFrameArena()` and `getPreviousFrameArena()`) allow subsystems to read previous-frame
  transient snapshots without heap copies or use-after-free bugs.
- **Effortless Concurrency Debugging via CLI Flags.** Developers can pass `-threads=1` or
  `-no-jobsystem` on the command line to deterministically reproduce race conditions or profile
  thread scaling.

### Negative

- **Dedicated Per-Application Memory Footprint.** `gp::Application` pre-allocates two frame arenas
  (`2 * 4 MiB = 8 MiB` by default, configurable via `ApplicationDesc::frameArenaBytes`) plus the
  `JobSystem` fiber stacks (`~24 MiB` default, configurable via `ApplicationDesc::jobSystem`).
  Headless unit tests can configure smaller capacities via `ApplicationDesc`.
- **Two-Frame Lifetime Ceiling on Frame Arena Pointers.** Pointers allocated from
  `getCurrentFrameArena()` must never be stored in persistent member variables beyond Frame
  $N+1$, as the arena rewinds on Frame $N+2$.
